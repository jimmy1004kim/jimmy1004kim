## 이 문서는

내부 시스템 구축 프로젝트를 **착수부터 운영 인계까지** 표준화된 절차로 진행하는 **워크플로우 가이드**.

T4의 다른 산출물과의 관계:

```
[T4-1~13 산출물] = 각 단계의 결과물
[T4-14 본 문서]  = 전체 프로세스·언제·어떻게·누가
[T4-15 운영 인계] = 마지막 단계 상세
```

### 다른 워크플로우와의 차이

|워크플로우|적용|
|---|---|
|**공통 — 새 프로젝트 시작·종료·자산화**|모든 프로젝트|
|**T4-14 (본 문서)**|**내부 시스템 구축에 특화**|
|**T4-15 운영 인계**|T4-14의 마지막 단계 상세|

### 내부 시스템 구축이 일반 프로젝트와 다른 점

|항목|외부 발주 SI·신규 서비스|**내부 시스템 구축**|
|---|---|---|
|사용자|외부 고객|**내부 직원 (운영팀)**|
|변화 관리|작음|**매우 큼** (직무 변화)|
|외부 연동|적음|**많음** (기존 시스템·외부 API)|
|데이터 마이그레이션|없거나 적음|**많음** (기존 도구·엑셀)|
|운영 인계|외부에서 운영|**사내 시스템 운영자에게 인계**|
|성공 지표|매출·전환율|**업무 효율·정합성·만족도**|
|단계적 출시|옵션|**필수** (Big Bang 위험)|

본 워크플로우는 위 7가지 차이점을 반영.

### 6대 페이즈 (Phase)

|Phase|기간|주요 산출물|게이트|
|---|---|---|---|
|**P0. 발견** (Discovery)|2~4주|AS-IS·페인 분석·기회 식별|GO/NO-GO 1차|
|**P1. 정의** (Definition)|3~6주|TO-BE·요구사항·ROI|**GO/NO-GO 2차 (의사결정)**|
|**P2. 설계** (Design)|4~8주|기능·화면·정책·데이터·권한·자동화·매뉴얼|설계 검토|
|**P3. 구축** (Build)|8~24주|코드·테스트·시범 운영|출시 검토|
|**P4. 출시·안착** (Launch & Stabilize)|4~8주|Phase별 출시·변화 관리·안정화|출시 후 30일·90일|
|**P5. 운영 인계** (Handover)|2~4주|운영 매뉴얼·시스템 운영자 인계·종료|운영 인계 완료|

### 표준 절차의 4대 원칙

|원칙|의미|
|---|---|
|**단계별 GO/NO-GO 게이트**|각 페이즈 끝에서 진행 결정|
|**이해관계자 정렬**|단계마다 의사결정자·운영팀·법무·재무 검토|
|**단계적 출시 (Phase 1·2·3)**|Big Bang 금지·점진 안착|
|**변화 관리 병행**|시스템 구축과 변화 관리 동시 진행|

### 단계적 출시 (Phased Rollout)

내부 시스템에서 Big Bang은 **거의 항상 실패**:

|방식|위험|
|---|---|
|Big Bang (한 번에 다)|운영 중단 위험·반발·복구 어려움|
|**단계적 출시 (Phase 1·2·3)**|**안전·점진 적응·각 단계 검증** ⭐|

**Phase별 구성 원칙**:

- Phase 1: 가치 큰 핵심 기능 + 빠른 성공
- Phase 2: 가치 중간 기능
- Phase 3: 보조 기능·안정화

## 6. 단계적 출시 (Phased Rollout) 원칙

### 6.1 왜 단계적인가

|위험 (Big Bang)|완화 (단계적)|
|---|---|
|모든 운영 중단 위험|Phase별 부분 운영 가능|
|운영팀 부담 폭증|점진 적응|

|변화 관리 실패|작은 성공·신뢰 누적|

### 6.2 Phase 분리 원칙

|원칙|의미|
|---|---|
|**Phase 1 = 가치 큰 핵심**|가장 큰 페인 해결·빠른 성공|
|**Phase 2 = 중간 가치**|자동화 확장·고도화|
|**Phase 3 = 보조·안정화**|모니터링·고도 자동화·정리|
|**각 Phase 자체 가치**|Phase 1만으로도 ROI 일부 회수|
|**Phase 종속성 최소화**|Phase 2 실패해도 Phase 1 운영 가능|

### 6.3 OpsHub 단계적 출시 예

```
Phase 1 (6,500만·3개월): 주문·재고·대시보드 MVP

Phase 2 (3,500만·2개월): 정산·CS 통합
  → Phase 1 안착 확인 후 진입
  → 정산 자동화·CS 누락 0건

Phase 3 (2,000만·1개월): 이상 감지·고도화
  → 안정 운영의 마무리
```
