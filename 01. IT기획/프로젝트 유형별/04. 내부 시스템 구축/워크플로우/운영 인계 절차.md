## 이 문서는

내부 시스템 구축 후 **개발팀·PM에서 시스템 운영자(또는 외부 인수자)에게 운영 책임을 안전하게 이관하는 절차**.

T4의 다른 산출물과의 관계:

```
[T4-12 운영 매뉴얼] = 인계의 핵심 자료
[T4-13 변화 관리]   = 인계 받는 사람의 적응
[T4-14 구축 표준 절차] = 인계는 P5 단계
[T4-15 본 문서]     = 인계 절차의 상세 (Phase 5 deep dive)
```

### 왜 운영 인계 절차가 핵심인가

내부 시스템 구축의 가장 흔한 사후 실패:

- **"구축은 끝났는데 운영 못 함"** — 인계 부실
- **"개발팀이 계속 운영 지원"** — 책임 분리 안 됨·개발 능력 낭비
- **"시스템 운영자 6개월 뒤 퇴사"** — 인계 부담·번아웃
- **"외부 API 변경 시 대응 못 함"** — 노하우 전수 X
- **"장애 시 우왕좌왕"** — 트러블슈팅 미숙
- **"신규 직원이 다시 처음부터 학습"** — 인계 자료 부실

운영 인계가 위 6가지 모두 해결.

### 인계의 3가지 시나리오

|시나리오|특징|적용|
|---|---|---|
|**사내 시스템 운영자 (신규 채용)**|신규 직무·온보딩|⭐ **본 가이드 주력**|
|**사내 다른 팀 (예: 인프라팀)**|기존 팀 + 시스템 추가|단계 일부 생략 가능|
|**외부 인수자 (외주 운영)**|외부 회사에 운영 위탁|계약·NDA·이중 검증 추가|

### 인계의 6대 영역

|영역|의미|인계 자료|
|---|---|---|
|**기술**|아키텍처·코드·인프라|운영 매뉴얼·DB·인프라|
|**운영 절차**|일일·주간·월간 활동|체크리스트·런북|
|**장애 대응**|트러블슈팅·런북|장애 시나리오·연락처|
|**외부 시스템**|9채널·CafeBean 등|어댑터·API 문서·자격 증명|
|**권한·보안**|계정·키·접근|권한 표·KMS·시크릿|
|**이해관계자**|운영팀·CTO·법무|연락처·에스컬레이션|

본 가이드는 6영역 모두 다룸.

### 인계의 4단계 모델

```
1. 관찰 (Observe) — 인수자가 보기만
   ↓
2. 동행 (Pair) — 함께 작업·인수자 보조
   ↓
3. 주도 (Lead) — 인수자 주도·인계자 백업
   ↓
4. 단독 (Solo) — 인수자 단독·인계자 떠남
```

각 단계 1~2주씩. 총 4~8주 인계.

### 인계 성공의 5대 원칙

|원칙|의미|
|---|---|
|**체크리스트 기반**|빠뜨림 방지|
|**시범 운영 (실제 장애 시뮬레이션)**|실력 검증|
|**4단계 점진 인계**|관찰→동행→주도→단독|
|**이중 검증**|인계자 + 인수자 + CTO|
|**운영 인계 후 백업 기간**|인계자 30일 백업·문의 응대|

## 언제 사용

- 내부 시스템 구축 P5 단계 (T4-14 마지막)
- 새 시스템 운영자 입사·온보딩
- 운영 책임 이관 (인프라팀·외주 등)
- 신규 직원이 기존 시스템 인수 시

## 표준 구성

```

```

|---|---|
|모든 운영 활동|**완전 단독**|
|박CTO 1:1 (격주)|진척·이슈|
|운영팀장 협업|권한·이슈·외부 채널|
|**인계자 (김데브)**|**떠남·필요 시 질문 응대만** (월 5건 한도)|

#### 인수자 단독 결정 권한

이 시점부터 인수자가 단독 결정 가능한 영역:

- 일상 운영·일일 체크리스트
- 일반 알람 (Medium·Low) 대응
- 외부 API 변경 어댑터 수정·배포 (소규모)
- 신규 직원 권한 부여 (운영팀장과 공동)
- 일반 트러블슈팅

**여전히 박CTO 협의 필요**:

- Critical 장애 (CEO·CFO·운영팀장 통보 필요)
- 정책 변경 (POL-XXX 수정)
- 권한 정책 변경 (T4-10 수정)
- 데이터 라이프사이클·법령 관련
- 외부 컨설팅·법무 자문
- 분기 권한 검토

#### 산출물

- **단독 운영 3주 보고**
- **인계 완료 확인서** (인수자·인계자·박CTO·운영팀장 서명)

### 6.2 G6 회의

**참석자**: 박CTO·운영팀장·인계자 (김데브)·인수자 (시스템 운영자)·PM **의제**:

1. 영역별 체크리스트 검증 (15분)
2. 시범 시나리오 결과 (15분)
3. 인수자 자기 평가 (10분)
4. 운영팀·박CTO 피드백 (10분)
5. **인계 완료 결정** (5분)

**결과**:

- 🟢 GO: 인계 완료·인계자 떠남·백업 기간 30일 시작
- 🟡 조건부: 일부 영역 추가 학습 (2주 연장)
- 🔴 NO-GO: 인계 실패·재계획 (드물게·예외)
