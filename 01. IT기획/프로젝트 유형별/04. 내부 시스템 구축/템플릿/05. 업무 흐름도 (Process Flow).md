## 이 문서는

내부 시스템에서 **업무가 어떻게 진행되는지를 시각화한 다이어그램 + 단계별 명세**.

T4 산출물 흐름에서의 위치:

```
[T4-1 AS-IS] → [T4-2 TO-BE] → [T4-3 요구사항] → [T4-5 업무 흐름도] → [T4-6 기능 정의]
        ↓             ↓                ↓                ↓                  ↓
   "현재 어떻게"  "앞으로 어떻게"  "무엇을 만들까"  "어떤 순서로"      "어떻게 만들까"
```

다른 산출물과의 비교:

|구분|T4-1 AS-IS 흐름|**T4-5 업무 흐름도 (TO-BE)**|T4-6 기능 정의|T4-11 자동화 로직|
|---|---|---|---|---|
|시점|현재|**미래 (TO-BE)**|미래 (구현)|미래 (구현)|
|단위|현재 업무|**TO-BE 업무 흐름 1건**|기능 1건|자동화 로직 1건|
|강조|페인 포인트|**사람·시스템 역할 분담**|명세·동작|알고리즘·조건|
|청중|BA·운영팀|**PM·개발·운영팀·QA**|개발·QA|개발|

**핵심**: T4-5는 **"시스템이 도입되면 업무가 어떻게 흐를 것인가"**의 시각화. BPMN·Swimlane으로 명확.

### 왜 업무 흐름도가 핵심인가

내부 시스템 구축에서 자주 발생하는 실패:

- **기능은 만들었는데 업무가 이어지지 않음** — 기능 1·2·3은 있지만 "사용자가 1 → 2 → 3 가는 길"이 모호
- **사람·시스템 역할 분담 모호** — "이건 사람이 해야 하나, 시스템이 해야 하나" 회의 반복
- **예외 케이스 누락** — 정상 흐름만 그리고 예외 처리 못 함
- **시스템 간 경계 모호** — OpsHub·CafeBean·샵플링·채널 어디서 무엇

업무 흐름도가 이 4가지를 모두 해결.

### 흐름도의 3가지 유형

|유형|의미|적용|
|---|---|---|
|**BPMN (Business Process Model and Notation)**|표준 비즈니스 프로세스 표기법|복잡한 업무·시스템 간 경계 명확|
|**Swimlane (역할별)**|역할·시스템별 세로 차선|**누가 무엇을 하나** 명확 ⭐|
|**Flowchart (간단)**|박스·화살표|작은 흐름·결정 트리|

본 가이드는 **Swimlane 중심 + BPMN 보조** 권장 (내부 시스템에 적합).

### Swimlane 차선의 4가지 분류

|차선 (Lane)|의미|
|---|---|
|**외부 이벤트·트리거**|외부 시스템·시간 등에서 발생|
|**시스템 (OpsHub)**|OpsHub 자동 처리|
|**외부 시스템**|9개 채널·CafeBean·슬랙 등|
|**사람 (운영팀)**|사람이 직접 하는 작업|

흐름도는 위 4개 차선 사이를 화살표로 연결.

### 핵심 표기법 (BPMN 단순화)

|기호|의미|
|---|---|
|⬭ (원)|**시작·종료** 이벤트|
|▭ (사각형)|**활동** (사람·시스템 작업)|
|⬨ (다이아몬드)|**결정·분기** (조건)|
|→|**흐름 (Sequence)**|
|⇢ (점선)|**메시지·데이터 흐름**|
|⬚ (Swimlane)|**역할·시스템 차선**|

복잡한 BPMN 기호 (보상·신호 등) 는 일반 내부 시스템에서 불필요.

## 언제 만드나

- 기능 정의서 (T4-6) 작성 전

**기준**: "업무가 어떤 순서로 흐르는가"를 정의해야 기능을 정의할 수 있는 시점.

## 4. 예외 케이스·에러 처리

|#|예외 케이스|발생 단계|처리 방법|복구|
|---|---|---|---|---|
|1|**채널 API 일시 장애** (5xx·timeout)|S3·S4|자동 재시도 (S7)|재시도 3회 후 알람|
|2|**채널 API 인증 만료** (401·403)|S4|토큰 갱신 시도 → 재시도|갱신 실패 시 즉시 알람 (높음)|
|3|**재고 음수** (negative)|S3|재고 0으로 클램프 + 경고 알람|운영팀 수동 보정|
|4|**이벤트 중복**|S1|idempotency key로 중복 감지·skip|자동 무시|
|5|**동시 다발 변동 충돌**|S2·S3|SKU별 FIFO 큐로 순서 보장|자동 처리|
|6|**재시도 후 일부 채널 실패**|S8|슬랙 알람 + 운영팀 수동 보정|S11|
|7|**정합성 검증 불일치**|S12|별도 슬랙 알람·자동 재동기화 시도 1회|실패 시 운영팀 수동|
|8|**OpsHub 자체 장애**|전체|RabbitMQ 큐에 이벤트 보존 (TTL 24시간)·복구 후 재처리|자동|
|9|**CafeBean Webhook 누락**|S1|1시간마다 CafeBean 재고 데이터 폴링 비교 (백업)|자동 감지·재동기화|

### 에러 시 알람·롤백

- **자동 재시도 (S7)** 가 1차 방어
- **슬랙 알람 (S9·S10)** 이 2차 방어 — 운영팀 인지
- **OpsHub 대시보드** 에 실패 작업 큐 표시
- **이력 (S14)** 으로 모든 작업 추적 가능
- **롤백**: 재고는 trace 가능 → 시간 역행 가능하나 일반적으로 "보정" 방식으로 처리
