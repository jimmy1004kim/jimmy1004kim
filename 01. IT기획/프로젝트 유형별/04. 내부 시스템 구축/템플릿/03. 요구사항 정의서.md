## 이 문서는

TO-BE 청사진을 **개발 가능한 단위의 요구사항으로 분해·정리한 명세 문서**.

T4 산출물 흐름에서의 위치:

```
[T4-1 AS-IS] → [T4-2 TO-BE] → [T4-3 요구사항] → [T4-6 기능 정의] → 구현
                       ↓               ↓                ↓
                  "무엇을 할까"   "무엇을 만들까"   "어떻게 만들까"
```

T2 (외주·구축) 요구사항 정의서와의 차이:

|구분|T2 (외주 구축) 요구사항|**T4 (내부 시스템) 요구사항**|
|---|---|---|
|청중|발주자 + 외주사 (양 측 계약)|**내부 개발팀 + 운영팀**|
|강조|계약 범위 (Out-of-Scope 명확)|**AS-IS 페인 → TO-BE 해결 매핑**|
|변경|계약 변경 절차|**유연한 변경 가능 (Phase별)**|
|우선순위|발주자 결정|**운영팀·의사결정자 협의**|
|ROI|계약 금액 vs 가치|**개발 비용 vs 운영 효율**|

**핵심**: 내부 요구사항은 **"운영팀이 안 쓰면 무용지물"**. 그래서 운영팀 합의·우선순위 명확화가 핵심.

### 요구사항의 2가지 분류 (FR + NFR)

|분류|의미|예시|
|---|---|---|
|**기능 요구사항 (FR)**|시스템이 무엇을 해야 하나|주문 자동 처리·재고 동기화·이상 알람|
|**비기능 요구사항 (NFR)**|시스템이 어떻게 작동해야 하나|응답 시간·가용성·보안·확장성|

본 가이드는 FR + NFR 둘 다 다룸. **NFR 누락이 내부 시스템 실패의 흔한 원인**.

### NFR의 7대 영역

|영역|핵심 질문|
|---|---|
|**성능**|얼마나 빨라야 하나|
|**가용성**|얼마나 안정적이어야 하나|
|**보안·개인정보**|누가 무엇을 볼 수 있나|
|**확장성**|미래 성장에 대응 가능한가|
|**사용성**|운영팀이 쉽게 쓸 수 있나|
|**운영·유지보수**|모니터링·장애 대응 가능한가|
|**데이터 정합성**|데이터가 정확하고 일관된가|

### 요구사항의 5가지 품질 기준 (SMART for Requirements)

|기준|의미|
|---|---|
|**Specific**|구체적 (모호 X)|
|**Measurable**|측정 가능 (Pass/Fail 명확)|
|**Achievable**|달성 가능|
|**Relevant**|TO-BE 비전과 정합|
|**Testable**|QA 가능 (수용 기준 명확)|

요구사항마다 5가지 자체 점검.

### 우선순위 — MoSCoW 방식

|우선순위|의미|비중|
|---|---|---|
|**Must Have (M)**|필수 — 없으면 시스템 가치 없음|60%|
|**Should Have (S)**|중요 — 가급적 Phase 1에 포함|20%|
|**Could Have (C)**|있으면 좋음 — Phase 2~3 가능|15%|
|**Won't Have (W)**|이번 프로젝트에서 제외|5%|

각 요구사항에 M/S/C/W 부여.

## 작성 팁

- **FR + NFR 둘 다** — NFR 누락이 내부 시스템 실패의 흔한 원인
- **MoSCoW 우선순위** — Must/Should/Could/Won't 명확
- **Phase 배정** — 한 번에 다 ❌, Phase 1·2·3 분산
- **SMART 5가지 점검** — 요구사항마다 자체 평가
- **수용 기준 명확** — Pass/Fail 판단 가능
- **AS-IS 매핑** — 모든 페인 포인트가 연결되었는지 확인
- **외부 인터페이스 명시** — IF-XXX
- **제약사항 명시** — 기술·법무·예산·시간·인력
- **운영팀 검토 필수** — 사용자가 합의 안 하면 무용지물
- **변경 절차 정의** — 변경 잦은 내부 시스템
- **버전 관리** — v0.1·v0.5·v1.0 변경 이력
- **수용 기준 = 인수 시 검수 기준** — QA 케이스로 직결

## 자주 하는 실수

- **FR만, NFR 누락** — 성능·보안·가용성 빠뜨림 → 운영 단계 문제
- **MoSCoW 없음** — 모든 요구사항 동일 우선순위 → 일정 폭주
- **Phase 배정 없음** — 한 번에 다 → Big Bang 실패
- **수용 기준 모호** — "잘 작동한다" → QA 어려움
- **AS-IS 매핑 안 함** — 페인 포인트 일부 누락
- **외부 인터페이스 누락** — IF-XXX 안 그림
- **제약사항 누락** — 기술·법무·예산 무관심
- **운영팀 미참여** — 사용자 합의 X → 안 씀
- **변경 절차 없음** — 무분별한 변경 → 일정·범위 폭주
- **데이터 정합성 NFR 누락** — 운영 시작 후 문제 발견
- **모니터링·매뉴얼 NFR 누락** — 운영팀이 못 씀
- **버전 관리 X** — 누가 무엇을 언제 바꿨는지 모름
