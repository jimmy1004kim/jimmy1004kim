## 이 문서는

내부 시스템의 **비즈니스 규칙·운영 원칙·예외 처리 기준을 문서화한 정책 명세**.

T4 산출물 흐름에서의 위치:

```
[T4-3 요구사항] + [T4-6 기능 정의] → [T4-8 정책 정의서] + [T4-11 자동화 로직] → 구현
                                            ↓                    ↓
                                  "어떤 규칙으로 작동"     "어떻게 계산·실행"
```

### 정책 vs 기능 vs 자동화 로직

|구분|T4-6 기능 정의서|**T4-8 정책 정의서**|T4-11 자동화 로직|
|---|---|---|---|
|단위|기능 1건 (F-XXX)|**정책·규칙 1건 (POL-XXX)**|알고리즘 1건 (AUTO-XXX)|
|강조|무엇을 할까|**어떤 규칙·기준**|어떻게 계산·실행|
|변경|개발 변경 필요|**운영팀·법무·CFO 변경 가능**|개발 변경|
|예시|"주문 자동 처리"|"주문 30분 미응답 시 자동 취소"|"재고 동기화 알고리즘"|
|청중|개발·QA|**운영팀·법무·재무·개발**|개발·QA|

**핵심**: 정책은 **"비즈니스 규칙"**. 기능 안에 내장되어 있지만 **변경 가능성·법무·재무 관점이 별도**.

### 왜 정책 정의서가 필요한가

내부 시스템에서 자주 발생하는 문제:

- **정책이 코드 안에만 있음** — 변경 시 개발 의존
- **정책 변경 추적 불가** — "이 규칙 누가 언제 만들었지?"
- **법무·재무 검토 누락** — 정산·세금·개인정보 규칙이 코드에만
- **예외 처리 모호** — "이 경우엔 어떻게?" 회의 반복

정책 정의서가 위 4가지 모두 해결.

### 내부 시스템 정책의 7대 영역

|영역|의미|예시|
|---|---|---|
|**운영 정책 (Business)**|핵심 비즈니스 규칙|주문 자동 취소·재고 보충·환불 정책|
|**데이터 정책 (Data)**|데이터 보관·삭제·정합성|90일 보관·익명화·백업|
|**보안·개인정보 (Privacy)**|접근·암호화·개인정보 처리|권한·로그·암호화·법령 준수|
|**외부 시스템 (Integration)**|API·Rate Limit·실패 대응|재시도·fallback·외부 의존|
|**알람·SLA**|모니터링·응답 시간|응답 시간·CS SLA·이상 알람|
|**회계·재무**|정산·세금·환불|정산 오차 허용·세금계산서·환불 절차|
|**변경 관리**|정책 변경 절차|누가·어떻게·검토·승인|

본 가이드는 7가지 모두 다룸.

### 정책의 6가지 품질 기준

|기준|의미|
|---|---|
|**명확성 (Clarity)**|모호하지 않음|
|**측정 가능 (Measurable)**|Pass/Fail 명확|
|**일관성 (Consistency)**|다른 정책과 충돌 X|
|**법규 준수 (Compliance)**|법령·계약 위반 X|
|**합리성 (Reasonable)**|운영 가능|
|**변경 가능 (Changeable)**|변경 절차 명확|

각 정책에 6가지 점검.
