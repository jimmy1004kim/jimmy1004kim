## 이 문서는

내부 시스템 구축 전, **현재 (As-Is) 업무가 어떻게 진행되고 있는지 정밀하게 정리한 문서**.

T4 산출물 흐름에서의 위치:

```
[T4-1 AS-IS 업무 분석] → [T4-2 TO-BE 설계] → [T4-3 요구사항] → [T4-6 기능 정의]
        ↓                       ↓                      ↓
   "현재 어떻게"            "앞으로 어떻게"        "무엇을 만들까"
```

T1~T3과의 결정적 차이:

|구분|T1·T2·T3 (외부 사용자 대상)|**T4 (내부 시스템)**|
|---|---|---|
|사용자|외부 고객|**내부 직원 (운영팀·관리자)**|
|출발점|시장·고객 문제|**운영 비효율·반복 작업**|
|가치 측정|매출·전환율·NPS|**작업 시간 감축·휴먼 에러 감소·ROI**|
|분석 대상|사용자 행동 데이터|**현재 업무 프로세스**|
|가장 중요한 산출물|가설·MVP|**AS-IS 업무 분석서** ← 이 문서|

**핵심**: 내부 시스템 구축의 **가장 큰 실패 원인**은 "현재 업무를 잘 모른 채 만든 시스템". AS-IS 분석을 제대로 안 하면 운영팀이 안 쓰는 시스템 나옴.

### AS-IS 분석의 5가지 책임

1. **현재 업무를 빠짐없이 정리** — 자동화할지 말지 결정의 기준
2. **반복·비효율·휴먼 에러 식별** — 자동화 후보 도출
3. **업무량 정량화** — ROI 계산의 기초 (시간·빈도)
4. **이해관계자·역할 파악** — TO-BE 설계 시 누가 영향받나
5. **암묵지 명시화** — 베테랑의 머릿속 작업을 문서로

### AS-IS 분석의 4가지 깊이

|깊이|의미|적용|
|---|---|---|
|**Level 1. 업무 인벤토리**|어떤 업무들이 있나|전체 영역 (필수)|
|**Level 2. 업무 프로세스**|각 업무가 어떻게 진행되나 (단계·시간·도구)|자동화 후보 (필수)|
|**Level 3. 페인 포인트·예외 케이스**|무엇이 어렵나·언제 막히나|자동화 후보 (필수)|
|**Level 4. 데이터·시스템 흐름**|데이터가 어디서 어디로 가나|시스템 설계 시 (필수)|

본 가이드는 4가지 모두 다룸.

### 왜 "관찰"이 핵심인가

내부 시스템 AS-IS 분석은 **인터뷰만으로 부족**:

- 직원은 자신의 업무를 다 설명하지 못함 (암묵지·습관)
- "나는 이렇게 한다"고 말해도 실제는 다름
- 예외 케이스·트러블슈팅은 관찰해야 보임

**필수 방법**:

1. **인터뷰** (1:1, 60~90분) — 큰 흐름 파악
2. **Shadowing (관찰)** — 실제 작업하는 모습 옆에서 관찰 (4시간 이상)
3. **데이터 분석** — 작업 로그·시스템 사용 패턴
4. **워크북 분석** — 실제 사용 중인 엑셀·문서·매뉴얼

## 언제 만드나

- 내부 시스템 구축 프로젝트 착수 직후 (Phase 1 — Discovery)
- 기존 시스템 개선·리뉴얼 전
- 업무 표준화·프로세스 개선 전

**기준**: TO-BE를 그리기 전, **현재를 정확히 알아야 하는** 모든 시점.

## 10. 인사이트·자동화 후보

### Insight 1: 작업 시간의 70%가 "동기화·통합 작업"

샵플링 → 채널·채널 → 엑셀·채널 → CafeBean 등 **데이터를 옮기는 작업**이 70%. 시스템 통합으로 직접 절감 가능.

### Insight 2: 9개 채널 어드민 직접 접근이 비효율 핵심

운영팀이 일 평균 25회 채널 어드민 접속. 통합 화면으로 채널 어드민 접근 빈도 90% 감축 가능.

### Insight 3: 월말 정산이 가장 큰 단일 부담

박정산 단독으로 월 5일 풀가동. 정산 자동화로 5일 → 1일 가능 (베테랑 의존도 ↓).

### Insight 4: 휴먼 에러의 80%가 자동화로 해결 가능

수기 작업 → 자동화 시 에러 대폭 감소. 정합성 이슈도 자동 검증 가능.

### Insight 5: 김운영 베테랑 의존도가 위험

암묵지가 시스템화·매뉴얼화되지 않음. OPSHUB는 김운영의 노하우를 시스템 로직으로 명시화 기회.

## 자주 하는 실수

- **인터뷰만 함** — Shadowing 없음 → 암묵지 누락
- **인터뷰 표본 작음** — 1~2명만 → 편향
- **업무 인벤토리 누락** — 47건 중 일부만
- **휴먼 에러 정량화 X** — 추정 없음 → ROI 계산 어려움
- **데이터 흐름도 누락** — 시스템 설계 시 막힘
- **시스템 연동 현황 X** — TO-BE 설계 시 누락
- **베테랑 노하우 명시화 X** — 시스템화 못 함
- **시즌 변동 무시** — 평소만 봄 → 바쁜 시즌 부족
- **이해관계자 검토 누락** — 운영팀이 안 씀
- **자동화 후보만 분석** — 전체 인벤토리 누락 → 누락 업무 발견
- **사용 중인 도구 수집 안 함** — 엑셀·구글 시트·매크로 누락
- **TO-BE 안 그림** — 분석만 → 활용 X

## 작성 후 체크

- [ ] 분석 범위 (포함·제외) 명확한가
- [ ] 이해관계자 모두 파악되었는가
- [ ] 인터뷰 + Shadowing 둘 다 진행했는가
- [ ] 업무 인벤토리 빠짐없는가 (10~50개)
- [ ] 핵심 업무 프로세스 (Top 5~10) BPMN·플로우 시각화되었는가
- [ ] 페인 포인트·예외 케이스 식별되었는가
- [ ] 데이터 흐름도 있는가
- [ ] 시스템 연동 현황 (자동·반자동·수동) 명시되었는가
- [ ] 휴먼 에러 정량화되었는가
- [ ] 작업 시간 정량화되었는가
- [ ] 자동화 후보 우선순위 도출되었는가
- [ ] 인사이트 (3~5개) 정리되었는가
- [ ] 한계 명시되었는가
- [ ] 이해관계자 검토·합의되었는가
- [ ] TO-BE·요구사항·ROI 분석으로 발전 가능한가
