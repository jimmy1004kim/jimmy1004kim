## 이 문서는

진단 인터뷰의 **사전 준비, 진행 절차, 질문 목록, 사후 정리 방법을 정의하는 실무 도구**.

진단 컨설팅에서 인터뷰는 가장 풍부한 데이터 소스다. 그러나 **즉흥 인터뷰는 즉흥 결과를 낳는다**. 같은 진단을 다른 컨설턴트가 해도 비슷한 결과가 나오려면, 누가·무엇을·어떻게 물을지 사전에 설계되어 있어야 한다.

인터뷰 가이드는 인터뷰어용 **내부 도구**다. 인터뷰 대상자에게는 보여주지 않는다.

## 다른 문서와의 관계

| 문서              | 역할                |
| --------------- | ----------------- |
| 진단 계획서          | 누구를·얼마나 인터뷰할지 합의  |
| 진단 프레임워크        | 무엇을 평가할지 정의       |
| **인터뷰 가이드**     | **실제로 어떻게 인터뷰할지** |
| 인터뷰 결과 (후속 산출물) | 인터뷰 가이드 기반 정리     |
|                 |                   |

프레임워크의 각 평가 항목이 인터뷰 가이드의 질문으로 변환된다.

## 언제 만드나

진단 프레임워크 정의서 완성 직후, 첫 인터뷰 시작 전.

타임라인:

1. 진단 계획서 v1.0
2. 진단 프레임워크 정의서 v1.0
3. **인터뷰 가이드 작성** ← 여기
4. 시범 인터뷰 1~2건 → 가이드 보완
5. 본 인터뷰 진행

## 인터뷰 대상별 차이

대상에 따라 같은 영역이라도 질문이 달라진다.

|대상|핵심 관심사|질문 톤|
|---|---|---|
|경영진|전략·방향성·외부 환경|큰 그림·결정 근거·미래 비전|
|부서장|부서 운영·성과·자원|부서 관점·KPI·자원 배분|
|중간관리자|프로세스·시스템·실무 운영|실제 운영·병목·개선점|
|실무자|일상 업무·도구·불편함|현장 상황·구체적 사례|
|외부 (고객·공급사)|외부에서 본 우리|객관적 평가·기대|

**같은 질문이라도 표현이 달라야** 한다. 경영진에게 "ERP 데이터 정합성"을 물으면 안 풀린다. "보고 받으시는 데이터가 정확한가요?"가 적절.

## 인터뷰 기법 (5가지 핵심)

### 1. 개방형 질문 (Open Question)

- "예/아니오"로 답할 수 없는 질문
- ❌ "데이터 분석을 하시나요?"
- ⭕ "데이터를 보고 결정을 바꾼 사례가 있다면 어떤 게 있나요?"

### 2. 5 Whys

- 표면 답변 너머의 근본 원인 도달
- "왜?"를 5번 반복 (적절히, 무리하지 말 것)

### 3. 침묵 활용 (Silence)

- 답변 후 즉시 다음 질문 ❌
- 3~5초 침묵 → 인터뷰 대상자가 추가 정보 자발적으로 제공

### 4. 구체화 요청 (Probing)

- "구체적인 예를 들어주실 수 있나요?"
- "최근에 그런 일이 있었나요?"
- 추상적 답변에 머무르지 않게

### 5. 페어 프레이밍 (Paraphrasing)

- 답변을 본인 언어로 다시 정리해서 확인
- "그러니까 이런 말씀이신가요?"
- 오해 방지 + 인터뷰 대상자가 추가 보완 기회

## 윤리 원칙 (4가지)

진단 인터뷰는 인터뷰 대상자에게 부담을 줄 수 있다. 다음 원칙 반드시 준수.

1. **익명성 보장** — 누가 무엇을 말했는지 외부 비공개. 인터뷰 시작 전 명시
2. **자발성 존중** — 답하기 곤란한 질문은 패스 가능
3. **녹음은 동의 후** — 사전 동의 없는 녹음 금지
4. **사용 목적 명확화** — 이 인터뷰 결과가 어디에 어떻게 쓰일지 사전 공유

## 5. 인터뷰 진행 원칙

### 5.1 5대 원칙

1. **개방형 질문 우선** — "어떻게", "왜", "예를 들면" 활용
2. **5 Whys** — 표면 답변에 머무르지 말 것 (단, 무리하지 말 것)
3. **침묵 활용** — 답변 후 3~5초 침묵
4. **구체화 요청** — "최근에 그런 일이 있었나요?", "구체적 예가 있다면?"
5. **페어 프레이밍** — "그러니까 이런 말씀이신가요?" 로 확인

### 5.2 금기 사항

- ❌ 유도 질문 ("그게 문제죠?")
- ❌ 평가자 의견 노출 ("저도 그렇게 생각합니다")
- ❌ 다른 인터뷰 결과 노출 ("다른 분도 그렇게 말씀하셨어요")
- ❌ 비밀 보장 어김
- ❌ 시간 초과 (대상자 시간 침해)

### 5.3 어려운 상황 대응

|상황|대응|
|---|---|
|답변이 너무 짧음 ("그냥 그래요")|"그렇게 느끼시는 이유가 있다면?"|
|답변이 너무 김 (주제 이탈)|적절한 시점에 정중하게 "그 부분도 흥미롭네요. 시간 관계상 다음 질문으로..."|
|정치적 답변 ("문제 없습니다")|"이상적으로는 어떤 모습이면 좋을까요?" 로 우회|
|동료 비방|중립적 유지 + "구체적 사례보다 패턴으로 말씀해주실 수 있을까요?"|
|컨설턴트에 대한 적대감|인터뷰 목적 재설명 + 익명성 재확인|

## 6. 기록 방법

### 6.1 기록 원칙

- **2명 진행 권장** — 1명 인터뷰, 1명 기록 (역할 분담)
- **녹음 + 메모 병행** — 녹음은 정확성, 메모는 즉시 정리
- **인용 표시** — 그대로 옮긴 답변은 큰따옴표 + 페이지 표시
- **객관 기록** — 인터뷰어 해석·평가는 별도 섹션에

### 인터뷰 결과 #001

**기본 정보**

|항목|내용|
|---|---|
|익명 코드|EXEC-01|
|일시|2026-07-03 14:00 ~ 15:30|
|장소·방식|본사 임원실, 대면|
|인터뷰어|김컨설턴트(진행), 정OO(기록)|
|인터뷰 시간|실제 92분|

**핵심 인사이트 (5개)**

1. **창업주는 "지금도 잘 돌아간다" 인식** — DX의 시급성에 대한 인식 격차 존재
2. **데이터 신뢰는 낮은 편** — "보고서 숫자가 종종 다르다" 발언
3. **2세 경영자와의 의견 차이를 인지** — "젊은 친구들은 다 디지털 이야기"
4. **고객사 압박은 인지** — "OO자동차에서 매주 데이터 달라고 한다"
5. **투자 의사결정 시 ROI보다 직관 중심** — "감으로 결정하지"

**영역별 응답 요약**

[영역 1. 디지털 전략]

- Q1 (3년 방향): "내실 다지기. 무리한 확장보다 안정"
    - 인용: "디지털은 좋은데, 우리 같은 회사가 갑자기 바꾸기는 어렵지"
- Q2 (디지털 투자): "예산은 있는데, 어디에 쓸지가 어렵다"
- Q3 (장애물): "사람들 마음가짐, 그리고 정작 뭘 사야 할지 모르겠다"

[영역 2. 데이터·분석]

- Q4 (의사결정 데이터): "매출 보고서, 가끔 품질 보고서"
    - 인용: "근데 그 숫자가 가끔 부서마다 달라서 어느 게 맞는지..."
- Q5 (KPI 대시보드): "그런 거 없어. 매월 회의 때 보고 받는 정도"

[영역 5. 조직·인력]

- Q6 (DX 조직): "정보화팀이 있긴 한데 거기는 시스템 유지보수만"
    - 인용: "DX를 누가 끌고 갈 수 있을지 모르겠어"
- Q7 (임직원 인식): "젊은 직원들은 원하지만, 오래된 직원들은 부담스러워 함"

**관찰**

- 디지털 전환의 필요성 자체는 인지하나, "어디서부터 어떻게"에 대한 막막함이 컸음
- "젊은 친구들"이라는 표현 자주 사용 — 세대 격차 인식
- 본인을 디지털과 거리 두는 태도 ("나는 이런 거 잘 모른다")
- 인터뷰 후반부터 점점 솔직해짐 — 초반의 방어적 태도가 누그러짐

**인터뷰어 가설**

- 창업주는 디지털 전환의 필요는 알지만, 본인이 주도할 자신이 없는 상태로 추정
- "내실 다지기"라는 표현은 실질적으로 "지금 그대로"를 의미할 가능성
- 2세 경영자에게 권한을 점진적으로 이양하면서 DX를 추진할 가능성 높음
- → 권고안에서 "세대 협력 거버넌스" 형태가 적절할 것

**추가 확인 필요**

## 작성 팁

- **시범 인터뷰 필수** — 첫 1~2건은 시범. 가이드 미흡한 부분 보완 후 본 인터뷰
- **2명 진행** — 1명 진행 + 1명 기록. 1명이 다 하면 깊이 떨어짐
- **녹음 + 메모 병행** — 녹음만 의존하면 사후 정리 부담. 메모는 즉시
- **대상별 가이드 차별화** — 같은 항목이라도 표현·예시가 달라야
- **즉석 인사이트 별도 표시** — 인터뷰 중 떠오른 가설은 본 답변과 구분
- **익명 코드 일관성** — 처음부터 정해두고 외부 보고에 일관 사용
- **윤리 원칙 사전 명시** — Opening에서 익명성·자발성 약속
- **시간 엄수** — 90분 인터뷰가 120분 되면 대상자 신뢰 하락
- **인터뷰 후 즉시 정리** — 1시간 지나면 기억 절반. 30분 이내 메모 정리
- **종합 분석 미팅 주 1회** — 인터뷰 종료 후 한꺼번에 분석하면 시간 부족

## 자주 하는 실수

- **즉흥 인터뷰** — 가이드 없이 시작 → 인터뷰별 결과 일관성 깨짐
- **유도 질문** — "그게 문제죠?" → 인터뷰어 의견대로 답변 유도. 객관성 훼손
- **너무 많은 질문 욕심** — 60분에 30개 질문 → 깊이 없이 표면만 훑음
- **답변 즉시 다음 질문** — 침묵 활용 안 함 → 추가 정보 손실
- **개방형 질문 부족** — 예/아니오 질문만 → 단답으로 끝남
- **녹음 동의 없이 진행** — 윤리 위반·법적 리스크
- **익명성 약속 어김** — 한 번이라도 어기면 향후 인터뷰 신뢰 전부 잃음
- **인터뷰 후 정리 미루기** — 다음날 정리하면 기억 절반 손실
- **현장 관찰 누락** — 답변뿐 아니라 표정·머뭇거림 등 비언어 정보 중요
- **인터뷰어 1명 진행** — 진행하면서 기록도 하면 깊이 떨어짐

## 작성 후 체크

- [ ] 인터뷰 목적이 명확한가
- [ ] 대상별 가이드가 따로 작성되어 있는가 (경영진·부서장·실무자 등)
- [ ] 진단 프레임워크의 평가 항목이 인터뷰 질문으로 매핑되어 있는가
- [ ] Opening 스크립트에 익명성·자발성·녹음 동의가 포함되어 있는가
- [ ] 질문이 개방형으로 작성되어 있는가
- [ ] 후속 질문(Probing)이 미리 준비되어 있는가
- [ ] 인터뷰 진행 인력이 2명 이상 배정되어 있는가
- [ ] 익명 코드 체계가 정의되어 있는가
- [ ] 시범 인터뷰 1~2건이 계획되어 있는가
- [ ] 사후 정리 절차가 명확한가
- [ ] 인터뷰 결과 양식이 준비되어 있는가
- [ ] 윤리 원칙 (익명성·자발성·녹음 동의)이 명시되어 있는가
