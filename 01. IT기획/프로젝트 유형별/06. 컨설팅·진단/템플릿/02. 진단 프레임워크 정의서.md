## 이 문서는

**"무엇을, 어떤 기준으로, 어떻게 평가할 것인가"를 정의하는 진단의 측정 체계 문서**.

진단 컨설팅이 인상비평으로 떨어지는 가장 큰 이유는 평가 기준이 없기 때문이다. "디지털 수준이 낮은 것 같다"가 아니라 **"5단계 성숙도 모델 기준 2단계(반응적 단계)"** 라고 말할 수 있어야 객관성이 확보된다.

프레임워크 정의서는 **컨설턴트의 주관을 배제하고, 다른 컨설턴트가 같은 진단을 해도 비슷한 결과가 나오도록 만드는 측정 자**다. 진단의 신뢰성 전체를 좌우한다.

## 진단 계획서와의 관계

|문서|역할|
|---|---|
|진단 계획서|무엇을·언제·누가·어떻게 (전체 합의)|
|**진단 프레임워크 정의서**|**무엇을 어떤 기준으로 측정할 것인가 (측정 도구)**|

진단 계획서가 "여행 계획"이라면, 프레임워크 정의서는 "지도와 나침반"이다. 계획서에 방법론 개요만 적고, 상세는 본 문서에서.

## 언제 만드나

진단 계획서 v1.0 합의 직후 (Phase 1 안에서).

타임라인:

1. 진단 계획서 v1.0 합의
2. **프레임워크 정의서 작성** ← 여기
3. 프레임워크 기반으로 인터뷰 가이드 설계
4. 진단 수행

프레임워크 없이 인터뷰부터 시작하면 무엇을 물어볼지 매번 즉흥. 결과 일관성 깨짐.

## 프레임워크의 4가지 구성 요소

좋은 진단 프레임워크는 다음 4가지를 모두 갖춰야 한다.

### 1. 평가 영역 (Domain)

무엇을 진단할 것인가. 보통 4~7개 영역으로 분해.

### 2. 평가 항목 (Criteria)

각 영역 안에서 구체적으로 측정할 항목들. 영역당 보통 3~10개.

### 3. 평가 척도 (Scale)

어떤 기준으로 점수를 매길 것인가. 보통 3~5단계.

### 4. 평가 방법 (Method)

어떤 데이터·근거로 평가할 것인가. 인터뷰·관찰·데이터·문서 등.

## 평가 척도 설계 (3가지 패턴)

### 패턴 A. 성숙도 모델 (Maturity Model) — 가장 흔함

5단계가 표준. 각 단계는 누적적·점진적.

|단계|일반적 이름|특징|
|---|---|---|
|1단계|Initial / Ad-hoc|무체계·즉흥적|
|2단계|Reactive / Repeatable|일부 체계화·반응적|
|3단계|Defined / Standardized|표준화·전사 적용|
|4단계|Managed / Optimized|측정·관리·개선|
|5단계|Optimizing / Innovative|지속적 개선·혁신|

**언제**: DX·IT 거버넌스·프로세스 영역

### 패턴 B. 점수 척도 (Score Scale)

|점수|의미|
|---|---|
|1|매우 미흡|
|2|미흡|
|3|보통|
|4|양호|
|5|매우 우수|

**언제**: 정성 평가가 많은 영역 (조직·문화·전략 등)

### 패턴 C. 이분법 (Yes/No)

|점수|의미|
|---|---|
|✅|충족|
|❌|미충족|
|⚠️|부분 충족|

**언제**: 체크리스트형 진단 (보안·컴플라이언스 영역)

**대부분의 진단은 A와 B를 조합**한다. 예: 성숙도 평가는 5단계, 보조 평가는 점수 척도.

## 평가 영역 설계 시 주의사항

- **상호 배타적·전체 망라적 (MECE)** — 영역 간 중복 없고 전체를 포괄
- **4~7개가 적정** — 너무 많으면 인지 부하, 너무 적으면 깊이 부족
- **각 영역의 무게는 다를 수 있음** — 본 사업에 중요한 영역은 더 깊이

## 평가 항목 설계 시 주의사항

- **관찰 가능 (Observable)** — 인터뷰·문서·데이터로 확인 가능해야
- **객관적** — "잘 한다" ❌, "월 1회 이상 KPI 측정" ⭕
- **각 단계의 차이가 명확** — 2단계와 3단계의 차이를 구분할 수 있어야

### 1.3 평가 척도 (5단계 성숙도)

|단계|명칭|정의|
|---|---|---|
|1|Initial (초기)|디지털 활동이 없거나 즉흥적·개인 의존. 체계 부재|
|2|Reactive (반응적)|일부 영역에 디지털 도입. 문제 발생 시 대응. 일관성 부족|
|3|Defined (정의됨)|디지털 표준이 정의되고 전사 적용. 측정 시작|
|4|Managed (관리됨)|디지털 활동이 측정·관리되고 지속 개선|
|5|Optimizing (최적화)|데이터 기반 자율 최적화·혁신. 외부 협업·생태계|

## 2. 평가 영역

### 2.1 평가 영역 목록

|#|영역|가중치|평가 항목 수|
|---|---|---|---|
|1|디지털 전략|20%|5개|
|2|데이터·분석|25%|5개|
|3|시스템·인프라|20%|5개|
|4|프로세스·자동화|20%|5개|
|5|조직·인력|15%|5개|
|**합계**||**100%**|**25개**|

### 2.2 가중치 산정 근거

- **데이터·분석 25% (최고)**: 제조업 DX의 핵심은 데이터 수집·분석. 고객사 요구도 데이터 협업 중심
- **디지털 전략 20%**: 2세 경영자 승계 시점, 전략 명확화가 향후 3년 좌우
- **시스템·인프라 20%**: 핵심 운영 시스템 (ERP·MES) 평가 필요
- **프로세스·자동화 20%**: 제조업 운영 효율의 핵심
- **조직·인력 15%**: 중요하나 단기 변화 어려움. 권고안의 부수 요소

## 3. 영역별 상세 (영역 2. 데이터·분석을 예시로)

### 영역 2. 데이터·분석

**영역 정의**: 조직이 데이터를 어떻게 수집·관리·분석·활용하여 의사결정에 반영하는가 **가중치**: 25% **평가 항목 수**: 5개

#### 평가 항목 2.1. 데이터 수집 체계

|단계|정의|
|---|---|
|1|수동·산발적 수집 (엑셀·종이). 부서별 따로따로|
|2|일부 시스템에서 자동 수집되나 영역 한정 (예: MES만 자동)|
|3|핵심 영역(생산·품질·재고) 모두 시스템 자동 수집. 수기 입력 비중 30% 이하|
|4|전 운영 영역 자동 수집. 실시간 또는 일 단위. 수기 입력 10% 이하|
|5|IoT·센서 등 실시간 수집 + 외부 데이터(고객·공급사) 통합 수집|

**평가 근거**: 정보화팀 인터뷰 + 시스템별 수집 데이터 목록 검토 + 현장 관찰 **핵심 질문**:

- "현재 어떤 데이터를 어떤 시스템에서 수집하고 있나요?"
- "수기 입력 비중은 대략 얼마나 되나요?"
- "실시간 수집되는 데이터가 있나요?" **증빙 자료**: 시스템 목록, 데이터 항목 명세, 수집 빈도 표

#### 평가 항목 2.2. 데이터 품질 관리

|단계|정의|
|---|---|
|1|데이터 품질 관리 활동 없음. 오류 발견 시 즉흥 수정|
|2|일부 시스템에 입력 검증 있음. 정기 점검 없음|
|3|핵심 시스템에 입력 검증·정합성 체크. 월 1회 이상 품질 점검|
|4|전 시스템에 자동 검증·정합성 체크. 품질 지표 관리 (정확도 등)|
|5|데이터 거버넌스 체계 운영. 마스터 데이터 통합 관리. 품질 KPI|

**평가 근거**: 정보화팀·품질팀 인터뷰 + 데이터 오류 발생 사례 **핵심 질문**:

- "데이터 오류는 어떻게 발견되고 수정되나요?"
- "데이터 품질 지표를 측정하시나요?"
- "마스터 데이터(품목·고객 등)는 어떻게 관리됩니까?" **증빙 자료**: 데이터 품질 보고서, 오류 발생 이력

#### 평가 항목 2.3. 데이터 통합·표준화

|단계|정의|
|---|---|
|1|부서별·시스템별 데이터 분리. 코드·양식 제각각|
|2|일부 시스템 간 연계. 코드 통일 일부|
|3|핵심 시스템 간 데이터 통합·코드 표준화. 통합 보고 가능|
|4|전 시스템 통합. 표준 코드 체계 운영. 통합 분석 가능|
|5|데이터 레이크/웨어하우스 운영. 외부 데이터(고객·시장) 통합|

**평가 근거**: 시스템 아키텍처 검토 + 정보화팀 인터뷰 **핵심 질문**:

- "ERP·MES·품질 시스템 간 데이터가 자동 연계되나요?"
- "동일 품목이 시스템마다 다른 코드로 관리되나요?"
- "통합 보고서 작성 시 데이터 정합 작업이 필요한가요?" **증빙 자료**: 시스템 아키텍처도, 통합 보고서 샘플

#### 평가 항목 2.4. 분석 도구·역량

|단계|정의|
|---|---|
|1|분석 도구 없음. 엑셀 수기 분석만|
|2|엑셀 고급 활용 (피벗·매크로). 분석 담당자 1~2명|
|3|BI 도구 도입·정기 리포트 자동화. 분석 담당 부서|
|4|BI 도구 전사 활용. 셀프 분석 가능. 통계 분석 일부|
|5|AI·머신러닝 분석 적용. 예측 분석 운영|

**평가 근거**: 분석 결과물 검토 + 인터뷰 **핵심 질문**:

- "어떤 분석 도구를 사용하고 계신가요?"
- "정기적으로 만들어지는 분석 리포트가 있나요?"
- "분석을 직접 하는 사람과 부서는?" **증빙 자료**: 정기 리포트 샘플, 분석 도구 목록

#### 평가 항목 2.5. 데이터 기반 의사결정

|단계|정의|
|---|---|
|1|의사결정이 경험·직관 중심. 데이터 참조 거의 없음|
|2|일부 의사결정에 데이터 참조 (예: 매출 보고만)|
|3|핵심 의사결정에 정기 데이터 사용. KPI 모니터링 운영|
|4|대부분 의사결정에 데이터 기반. KPI 대시보드·정기 리뷰|
|5|데이터 분석 결과가 자동으로 의사결정에 반영 (예: 자동 발주)|

**평가 근거**: 경영진·부서장 인터뷰 + 의사결정 회의록·KPI 자료 **핵심 질문**:

- "지난 분기 중요한 의사결정 시 어떤 데이터를 봤나요?"
- "KPI 대시보드가 운영되고 있나요? 누가 보나요?"
- "데이터를 보고 결정을 바꾼 사례가 있다면?" **증빙 자료**: 경영회의 자료, KPI 대시보드, 의사결정 사례

## 5. 종합 평가 방법

### 5.1 점수 산출 방식

- **항목 점수**: 1~5 정수 (해당 단계 그대로)
- **영역 점수**: 영역 내 항목 점수의 평균 (소수점 둘째 자리까지)
- **종합 점수**: Σ(영역 점수 × 영역 가중치)

**예시 계산**:

- 영역 2 (데이터·분석) 항목 점수: 2, 1, 1, 2, 2
- 영역 2 평균: (2+1+1+2+2) / 5 = **1.6**
- 영역 2 가중 점수: 1.6 × 25% = **0.40**

5개 영역 가중 점수 합 = 종합 점수 (1.0 ~ 5.0)

### 5.2 종합 평가 결과 해석

|종합 점수|단계|의미|
|---|---|---|
|1.0 ~ 1.8|1단계 (초기)|디지털 전환 시작 단계. 기초 체계 구축 시급|
|1.8 ~ 2.6|2단계 (반응적)|일부 디지털화. 전사 표준 필요|
|2.6 ~ 3.4|3단계 (정의됨)|표준 적용·전사 운영. 측정 강화 필요|
|3.4 ~ 4.2|4단계 (관리됨)|측정·관리·개선 운영. 혁신 단계 진입|
|4.2 ~ 5.0|5단계 (최적화)|데이터 기반 자율 최적화·혁신|

## 7. 객관성 확보 방안

### 7.1 평가자 일관성

- 영역별 1차 평가: 담당 컨설턴트 (1인)
- 최종 평가: 책임 컨설턴트가 검토·확정
- 평가 시 판단 근거 (왜 2단계로 평가했는지)를 항목별로 문서화

### 7.2 평가 편향 방지

- **다수 응답 패턴 기준** — 단일 인터뷰가 아닌 5명 이상의 응답 패턴으로 평가
- **정량 데이터로 교차 검증** — 인터뷰 답변(정성)과 시스템 데이터(정량)가 다르면 정량 우선
- **양측 합의 미팅** — 최종 평가는 ㈜OO제조 측 사업 책임자에게 사전 공유·합의

### 7.3 평가 보류 항목 처리

## 작성 팁

- **표준 모델 참조 후 조정** — 처음부터 만들지 말고 CMMI·DX 성숙도·COBIT 등 검증된 모델을 본 사업에 맞게 조정
- **각 단계의 차이를 구체적으로** — "잘 한다", "잘 못 한다"가 아니라 "수기 입력 30% vs 10%" 같은 명확한 차이
- **관찰 가능한 항목만** — 인터뷰·문서·데이터로 확인 가능한 것만. "마음가짐" ❌
- **가중치는 근거 명시** — "이 영역이 25%인 이유"가 설명되어야
- **고객 검토 필수** — 평가 항목·척도를 고객이 사전 검토하고 합의해야 결과 수용성 높음
- **너무 많은 항목 금기** — 25~30개가 한계. 50개 넘으면 평가도 보고도 부담
- **벤치마킹 자료 미리 확보** — 산업 평균 비교가 권고안의 설득력 좌우
- **평가 보류 규칙 명시** — 정보 부족 항목 처리 방법 미리 정해두기
- **프레임워크 자체도 자산화** — 본 프레임워크를 다음 사업에 재사용 가능. 일반화해서 템플릿화

## 자주 하는 실수

- **프레임워크 없이 인터뷰부터 시작** — 측정 기준 없으니 결과 일관성 깨짐
- **단계 정의 모호** — "잘 한다", "보통이다" 식 → 평가자마다 다른 결과
- **너무 많은 항목** — 50개 넘으면 평가도 보고도 무거움
- **가중치 임의 설정** — 근거 없이 "음 이 영역이 중요하니 30%" → 객관성 의심
- **표준 모델 무시** — 검증된 모델 안 보고 처음부터 만들기 → 시간 낭비·신뢰 낮음
- **고객 검토 생략** — 컨설턴트만 만들고 끝 → 결과 발표 시 평가 기준 자체에 이의 제기
- **데이터 수집 매핑 누락** — 항목별로 어떤 데이터·인터뷰가 필요한지 안 정해놓으면 진단 수행 시 즉흥
- **벤치마킹 누락** — "그래서 우리가 잘 한 거냐 못 한 거냐"에 답 못 함
