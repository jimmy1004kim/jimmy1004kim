## 이 문서는

AS-IS 분석·데이터 분석에서 정리된 **사실들로부터 "핵심 문제와 통찰"을 도출하는 문서**.

진단 컨설팅의 진짜 가치는 여기서 결정된다. 누구나 사실은 정리할 수 있다. 그러나 **사실에서 핵심 문제를 짚어내고, 표면 아래 통찰을 발견하는 것**은 컨설턴트의 역량.

"매출이 줄었다" = 사실 "매출 하락의 핵심 원인은 데이터 통합 부재로 인한 의사결정 지연이다" = 통찰

이 문서가 약하면 To-Be 권고는 일반론이 되고, 강하면 권고가 자연스럽게 도출된다.

## AS-IS 분석 리포트와의 차이

|구분|AS-IS 분석 리포트|문제 정의·인사이트|
|---|---|---|
|톤|서술적 (이런 상태다)|해석적 (이게 문제다)|
|컨설턴트 개입|최소 (사실 정리)|핵심 (통찰 도출)|
|분량|30~50p|10~15p|
|주관|배제|일정 부분 들어감 (단, 근거 기반)|

### 명확한 흐름

```
AS-IS 사실
   ↓ (해석)
문제 정의
   ↓ (분석)
인사이트
   ↓ (다음 단계)
To-Be 권고
```

## 문제와 인사이트의 차이

**자주 헷갈리는 부분**:

|구분|문제 (Problem)|인사이트 (Insight)|
|---|---|---|
|무엇|무엇이 잘못되었는가|왜 그렇게 되었는가, 본질은 무엇인가|
|형태|사실의 부정적 표현|패턴·근본 원인·역설|
|예시|"데이터 통합이 안 되어 있다"|"시스템은 충분하나 활용이 미흡한 것 — '도구 풍족, 데이터 빈곤' 역설"|

문제는 표면이고, 인사이트는 그 아래 패턴·구조다.

## 문제 정의의 5가지 조건

좋은 문제 정의는 다음을 충족해야 한다.

### 1. 사실 기반 (Evidence-based)

모든 문제 정의에 AS-IS 또는 데이터 분석의 구체적 근거를 매핑.

### 2. 영향 범위 명시 (Scoped Impact)

"무엇에 어떤 영향을 미치는가"가 구체적이어야.

### 3. 측정 가능 (Measurable)

"문제가 해결되었는지" 판단할 수 있는 기준이 있어야.

### 4. 행동 가능 (Actionable)

풀 수 있는 것만 문제로. 통제 불가능한 것은 "제약"이지 문제가 아님.

### 5. 우선순위 (Prioritized)

모든 문제를 동시에 해결할 수 없음. 영향·시급성 기반 우선순위.

## 인사이트 도출 4가지 패턴

### 패턴 1. 역설 (Paradox)

서로 모순되는 사실에서 본질 발견.

- "ERP·MES 다 있는데 데이터 활용은 미흡" → "시스템은 풍족, 데이터는 빈곤"

### 패턴 2. 근본 원인 (Root Cause)

표면 문제 너머의 진짜 원인.

- 표면: "납기 준수율 하락"
- 근본: "생산 계획 데이터와 실적 데이터의 통합 부재"

### 패턴 3. 패턴 (Pattern)

여러 사실의 공통 패턴.

- "데이터·분석, 조직, 변화관리 모두 인력 부족" → "공통 원인: DX 추진 조직 부재"

### 패턴 4. 시사 (Implication)

사실이 의미하는 미래.

- "데이터 오류율 증가 추세 + 고객 데이터 협업 요구 증가" → "방치 시 1~2년 내 고객 이탈 가능"

## 언제 만드나

AS-IS 분석 리포트·데이터 분석 리포트 완성 직후 (Phase 3 후반).

타임라인:

1. Phase 2: 인터뷰·데이터 수집
2. Phase 3 초: AS-IS 분석, 데이터 분석
3. **Phase 3 후반: 문제 정의·인사이트 도출** ← 여기
4. Phase 4: To-Be 권고

### 3.2 근본 원인 분석 (5 Whys) — 문제 1 사례

#### 표면 문제: 데이터 통합·표준화 부재

- **Why 1**: 왜 데이터가 통합되지 않았는가? → 시스템이 따로따로 도입되었기 때문
- **Why 2**: 왜 따로 도입되었는가? → 각 부서·시기별로 필요에 따라 도입했기 때문
- **Why 3**: 왜 통합 관점에서 계획하지 못했는가? → 전사 IT·DX 계획·거버넌스가 없었기 때문
- **Why 4**: 왜 거버넌스가 없었는가? → DX를 책임지고 추진할 조직·역할이 정의되지 않았기 때문
- **Why 5**: 왜 그 조직이 정의되지 않았는가? → DX의 전사적 중요성에 대한 경영 수준의 인식·결정이 부재했기 때문

→ **근본 원인: 전사 DX 거버넌스 부재 = 문제 #2와 동일**

## 4. 핵심 인사이트

### 인사이트 #1. "시스템은 풍족, 데이터는 빈곤" — 역설

|항목|내용|
|---|---|
|**유형**|역설 (Paradox)|
|**인사이트 요지**|㈜OO제조는 ERP·MES·QMS 등 핵심 시스템을 모두 보유하고 있으나, 이들 시스템의 데이터를 통합·분석·활용하는 능력은 매우 미흡하다. **"도구는 있는데 쓰지 못하는" 상태**다|
|**근거 사실**|• 시스템·인프라 평가 2.4 (산업 평균 2.5에 근접)<br>• 데이터·분석 평가 1.6 (산업 평균 2.2 대비 -0.6)<br>• 시스템 보유 vs 데이터 활용 격차 0.8점|
|**의미**|추가 시스템 도입보다 **기존 시스템의 활용도 제고가 우선**. 신규 투자보다 통합·표준화·분석 역량 강화가 효과적|
|**함의**|To-Be 권고는 "새 솔루션 도입"보다 "기존 시스템 통합·활용 강화"가 핵심 방향|

### 인사이트 #2. "DX 추진 주체 부재가 모든 문제의 공통 원인" — 근본 원인

|항목|내용|
|---|---|
|**유형**|근본 원인 (Root Cause)|
|**인사이트 요지**|7개 핵심 문제의 5 Whys 분석 결과, 모두 **"DX를 책임지고 추진할 거버넌스의 부재"** 라는 공통 근본 원인에 수렴한다|

### 인사이트 #3. "세대 격차 = 위기인 동시에 기회" — 패턴

|항목|내용|
|---|---|
|**유형**|패턴 (Pattern)|
|**인사이트 요지**|세대 간 인식 격차는 변화 저항(위기)이자 동시에 변화 동력(기회)의 양면성을 가진다. 30~40대의 변화 의향이 50~60대 대비 뚜렷이 높음|
|**근거 사실**|• 설문: 30대 이하 "DX 필요성 매우" 응답 50대 이상 대비 2.3배<br>• 2세 경영자(40대) vs 창업주(60대) 인식 격차<br>• AS-IS §6.1 (부서·계층별 인식 차이)|
|**의미**|**세대 격차를 갈등이 아닌 변화 거버넌스의 동력으로 전환** 가능. 30~40대를 DX 추진 핵심 인력으로, 50~60대를 도메인 전문성·검증자로 배치|
|**함의**|To-Be 권고 시 "세대 협력 거버넌스" 형태가 적합. 일방적 변화 강요는 저항 유발|

- **공통 원인 찾기** — 여러 문제가 한 원인에서 비롯되면 그 원인이 1순위
- **인사이트 패턴 4가지 의식** — 역설·근본 원인·패턴·시사
- **인사이트는 한 줄로** — 한 줄로 못 쓰면 인사이트 아님
- **데이터 근거 표기 필수** — 모든 문제·인사이트에 AS-IS·데이터 분석 출처
- **권고는 다음 단계로 미루기** — "이렇게 해야 한다" 표현 자제. To-Be에서
- **시각화 적극 활용** — 인과 다이어그램·우선순위 매트릭스·한 장 요약

## 자주 하는 실수

- **사실 나열로 끝남** — 문제·인사이트 도출 없이 AS-IS 반복
- **너무 많은 문제** — 20개 나열 → 우선순위 의미 없음
- **표면 문제에 머무름** — 5 Whys 없이 표면만
- **공통 원인 못 봄** — 7개 문제가 사실 한 원인에서 비롯되는데 따로 봄
- **인사이트 = 요약** — 인사이트는 통찰이지 요약이 아님
- **인사이트 너무 추상적** — "DX가 중요하다" 같은 일반론
- **데이터 근거 누락** — "이건 문제다" 만 있고 근거 없음
- **권고 미리 섞기** — "이렇게 해야 한다" → 다음 단계로
- **우선순위 미정의** — 모든 문제가 동일 비중이면 의사결정 못 함
- **시각화 부족** — 텍스트만으로 인과·우선순위 전달 어려움

## 작성 후 체크

- [ ] 문제가 5~10개로 압축되어 있는가
- [ ] 인사이트가 3~7개로 압축되어 있는가
- [ ] 모든 문제에 데이터 근거가 매핑되어 있는가
- [ ] 5 Whys로 근본 원인까지 도달했는가
- [ ] 문제 간 인과 관계가 다이어그램으로 표현되어 있는가
- [ ] 인사이트가 4가지 패턴 (역설·근본 원인·패턴·시사) 중 하나로 명확한가
- [ ] 각 인사이트가 한 줄로 표현 가능한가
- [ ] 우선순위 매트릭스로 우선순위가 명확한가
- [ ] 권고가 본 문서에 섞이지 않았는가 (To-Be 방향 시사만)
- [ ] 한 장 요약이 작성되어 있는가
- [ ] To-Be 권고 영역으로의 연결이 명시되어 있는가
