## 이 문서는

문제 정의·인사이트를 기반으로 **"어떻게 풀 것인가, 어떤 모습이 되어야 하는가"를 정의하는 권고 문서**.

진단의 결론은 여기서 형태를 갖춘다. AS-IS·인사이트가 "현재 무엇이 잘못되었는가"라면, To-Be는 **"어디로 가야 하고, 어떻게 갈 것인가"**.

좋은 To-Be는 두 가지를 갖춘다.

1. **방향이 명확** — 어떤 모습으로 변할 것인가
2. **실행 가능** — 이상론이 아닌 본 회사가 진짜 할 수 있는 것

이상론적 권고는 진단 컨설팅이 가장 쉽게 빠지는 함정. "디지털 전환이 필요합니다" 수준은 무가치.

## 문제 정의·인사이트와의 관계

```
문제 정의·인사이트
       ↓
   To-Be 방향
       ↓
  실행 방안 (How)
       ↓
   로드맵·우선순위
```

**모든 To-Be 권고는 문제·인사이트와 1:1로 연결**되어야 한다. 문제 없이 등장한 권고는 무근거.

## To-Be가 갖춰야 할 5가지 조건

### 1. 문제에서 출발 (Problem-driven)

모든 권고가 앞 단계의 문제·인사이트에 근거.

### 2. 실행 가능 (Actionable)

본 조직의 리소스·역량·문화에서 실제로 할 수 있는 것.

### 3. 측정 가능 (Measurable)

"성공했는지" 판단할 수 있는 KPI·지표 제시.

### 4. 단계적 (Phased)

모든 권고를 동시에 추진 불가. 우선순위·단계 명확화.

### 5. 변화 관리 포함 (Change-aware)

기술·시스템만이 아닌 조직·문화·인력 변화 포함.

## 컨설팅의 흔한 실수

진단 컨설팅이 자주 빠지는 함정:

|흔한 실수|문제|대안|
|---|---|---|
|일반론 권고|"DX가 필요합니다"|본 회사 특정 문제에 대한 구체적 권고|
|Best Practice 복사|"X사처럼 하면 됩니다"|본 회사 맥락에 맞춘 조정|
|기술 중심 권고|"AI를 도입하세요"|조직·문화·프로세스 포함|
|실행 무관심|"이상적으로 X가 되어야"|누가·언제·어떻게|
|단계 없음|"이 모든 것을 동시에"|3년 로드맵·우선순위|

## To-Be 권고의 4가지 차원

권고는 다음 4가지 차원을 모두 다뤄야 균형 잡힌다.

|차원|다루는 것|
|---|---|
|**Tech (기술)**|시스템·데이터·인프라|
|**Process (프로세스)**|업무 흐름·자동화·표준|
|**People (조직·인력)**|거버넌스·역량·문화|
|**Strategy (전략)**|비전·우선순위·투자|

기술 권고만 있는 To-Be는 흔히 실행 실패. **거버넌스(People)·전략 차원이 선행**되어야 기술 권고가 작동.

## 권고 구체화 4단계

각 권고는 다음 4단계로 구체화.

### 1. To-Be 모습 (What)

이상적 모습은 무엇인가.

### 2. 실행 방안 (How)

구체적으로 어떻게 할 것인가.

### 3. 추진 주체 (Who)

누가 책임지고 추진할 것인가.

### 4. 시점 (When)

언제 어느 단계로 진행할 것인가.

## 언제 만드나

문제 정의·인사이트 도출 후 (Phase 4).

타임라인:

1. Phase 2: 진단 수행
2. Phase 3: AS-IS·데이터 분석, 문제·인사이트
3. **Phase 4: To-Be 권고** ← 여기
4. Phase 5: 최종 보고서·발표

1. **거버넌스 우선** — 인사이트 #2 ("DX 추진 주체 부재가 모든 문제의 근본 원인")에 따라, 기술 권고 이전에 추진 체계 구축

4. **시급성 인식** — 인사이트 #4 ("1~2년 내 고객 이탈 리스크") 에 따라, 3년 로드맵의 Y1에 핵심 권고 집중

|**How**|• 위원회 구성 (위원장=2세 경영자, 위원=부서장 6+외부 1)<br>• 전담 팀 4~5명 신설 (정보화 2+신규 2~3)<br>• 3년 전략 문서화·분기별 점검<br>• 세대 협력 워킹그룹 운영|
|**Who**|• 의사결정: 대표이사 (2세)<br>• 실행 책임: 신설 전담 팀장|
|**When**|• Y1Q1: 위원회<br>• Y1Q2: 전담 팀·전략 v1.0<br>• Y1 지속: 정착|
|**예상 효과**|• DX 의사결정 책임 명확화<br>• 부서 간 협력 체계<br>• 외부 자문(본 컨설팅) 결과 실행 보장|
|**예상 투자**|• Y1: 인건비 (신규 2~3명) + 외부 자문 ≒ 3~4억<br>• Y2 이후 운영비|
|**리스크**|• 신규 인력 영입 어려움 → 내부 발탁 병행<br>• 창업주 저항 → 위원회 명예 위원으로 위촉|

## 작성 팁

- **모든 권고가 문제·인사이트와 연결** — 무근거 권고 절대 금지
- **거버넌스(People)부터 시작** — 기술 권고가 작동하려면 추진 주체 선행
- **What·How·Who·When 모두** — 한 가지라도 빠지면 실행 불가
- **3년 로드맵 권장** — 너무 짧으면 의미 없고 너무 길면 의미 약함
- **변화 관리 빠뜨리지 말 것** — 권고의 절반은 변화 관리. 기술만으론 안 됨
- **이해관계자별 우려 매핑** — 누가 왜 저항할지 미리
- **KPI 시점별 목표** — Y1·Y2·Y3 각각 목표값 명시
- **투자·ROI 개략 추정** — 정확한 견적 아니어도 의사결정 가능 수준
- **본 회사 맥락에 맞춤** — Best Practice 그대로 복사 ❌
- **세대 협력 등 본 진단 인사이트 반영** — 일반 권고와 차별화

## 자주 하는 실수

- **일반론 권고** — "DX 필요", "데이터 중요" 같은 추상어
- **Best Practice 복사** — "구글처럼", "삼성처럼" — 본 회사 맥락 무시
- **기술만 권고** — AI·BI 도입만 ❌. 조직·문화·전략 누락
- **실행 무관심** — "이상적으로 X가 되어야" — Who·When 없음
- **단계 없음** — 모든 권고 동시 추진 → 실행 불가
- **변화 관리 누락** — 기술 권고만으로 변화 일어난다는 착각
- **이해관계자 우려 무시** — 저항 예상 못 함
- **KPI 모호** — "잘 운영", "효과적 도입" — 측정 불가
- **투자 추정 회피** — "투자 필요" 만 있고 규모 없음 → 의사결정 못 함
