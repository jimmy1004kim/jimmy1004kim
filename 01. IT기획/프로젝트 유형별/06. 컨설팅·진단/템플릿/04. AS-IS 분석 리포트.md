## 이 문서는

진단에서 수집한 **모든 데이터·인터뷰·관찰 결과를 종합하여 "현재 어떤 상태인가"를 객관적으로 정리한 문서**.

AS-IS는 영어 "있는 그대로(as it is)"의 약자. **판단·평가·권고는 들어가지 않는다.** 오직 사실 기반 현황만 정리한다. 이게 흔들리면 이후의 문제 정의·인사이트·To-Be 권고가 모두 흔들린다.

이 문서는 진단 보고서의 **첫 번째 본격 산출물**이며, 분량도 가장 두꺼운 편이다.

## 다른 문서와의 관계

```
진단 계획서 → 프레임워크 → 인터뷰 가이드 → 인터뷰 수행
                                            ↓
                              데이터 수집 / 관찰
                                            ↓
                              【AS-IS 분석 리포트】← 여기
                                            ↓
                              문제 정의서 / 인사이트
                                            ↓
                              개선 방향 정의서 (To-Be)
```

AS-IS가 사실 정리라면, 문제 정의·To-Be는 해석·권고. **이 둘을 섞으면 안 된다.**

## AS-IS가 갖춰야 할 4가지 조건

### 1. 사실 기반 (Fact-based)

"느낌상 미흡함" ❌ / "5명 중 4명이 ~라고 응답" ⭕

### 2. 객관적 (Objective)

컨설턴트의 가치 판단 배제. "잘못된 운영" ❌ / "월 1회 점검, 표준 모델 권장은 주 1회" ⭕

### 3. 추적 가능 (Traceable)

모든 사실에 근거 출처 표기. "[인터뷰 EXEC-01]", "[2025년 운영 데이터]" 등

### 4. 구조화 (Structured)

프레임워크의 영역·항목 구조에 맞춰 정리. 산만한 나열 금지.

## 평가와 분석의 차이

**자주 헷갈리는 부분:**

|구분|AS-IS 분석|평가 (다음 단계)|
|---|---|---|
|무엇|"이런 상태다"|"이게 X단계다"|
|톤|서술적|판정적|
|예시|"데이터 입력은 70% 수기"|"수집 체계는 2단계(반응적)"|

AS-IS 분석 안에 일부 평가 결과는 포함될 수 있지만 (영역별 성숙도 점수), **권고·해석은 절대 들어가지 않는다.**

## 언제 만드나

진단 수행 (인터뷰·데이터 수집·관찰) 완료 직후 (Phase 3 시작).

타임라인:

1. Phase 2: 인터뷰·데이터·관찰 수행
2. Phase 3 Step 1: **AS-IS 분석 리포트 작성** ← 여기
3. Phase 3 Step 2: 문제 정의·인사이트 도출
4. Phase 4: To-Be 방향 수립

- **현황**:

## 작성 팁

- **사실과 평가를 분리** — AS-IS는 사실. 평가는 영역 끝의 별도 섹션에만
- **모든 사실에 근거 표기** — 인터뷰 코드·데이터 출처·관찰 시점
- **인용은 익명 코드로** — 누가 말했는지 추적 불가하게
- **정량 + 정성 혼합** — 인터뷰 답변에 숫자 데이터 곁들이면 신뢰도 ↑
- **시각 자료 적극 활용** — 레이더 차트·매트릭스·플로우 다이어그램
- **벤치마킹 데이터 확보** — 산업 평균 비교 없이 "잘함/못함" 판단 어려움
- **분석의 한계 솔직히** — 데이터 부재·표본 한계 등 명시하면 신뢰도 ↑
- **권고·해석 절대 금지** — "이를 개선해야 한다" 같은 표현 ❌. To-Be 단계에서
- **부서·계층 간 차이 별도 표시** — 단순 평균에 묻히는 인사이트 있음
- **읽기 편하게 — 분량은 30~50p 적정** — 100p 넘으면 안 봄

## 자주 하는 실수

- **사실과 권고 혼재** — "데이터 통합이 미흡하므로 BI 도입이 필요하다" → 다음 단계로 미루기
- **컨설턴트 주관 노출** — "회사가 너무 안일하다" 같은 표현 ❌. 객관 서술만
- **근거 없는 진술** — "전반적으로 미흡함" → 어떤 근거로? 명시 필수
- **인용 누락** — 인터뷰 답변을 본인 말처럼 표현 → 데이터의 가치 사라짐
- **익명성 어김** — 한 번이라도 실명·부서 노출 → 향후 인터뷰 신뢰 전부 잃음
- **시각 자료 부족** — 텍스트만으로 영역별 비교 어려움
- **벤치마킹 누락** — "잘하는 건지 못하는 건지" 판단 못 함
- **부서·계층 차이 묻힘** — 평균만 보면 인사이트 잃음. 세그먼트 분석 필요
- **분량 폭주** — 100p 넘으면 안 봄. 30~50p 적정
- **한계 숨김** — 데이터 부족·표본 부족을 숨기면 결론 시 의심받음

## 작성 후 체크

- [ ] 모든 사실에 근거 출처가 표기되어 있는가
- [ ] 사실과 권고가 분리되어 있는가 (권고는 일절 없음)
- [ ] 컨설턴트 주관이 배제되어 있는가
- [ ] 인용이 익명 코드로 표시되어 있는가
- [ ] 프레임워크의 모든 영역·항목이 다루어졌는가
- [ ] 정량 데이터가 정성 인터뷰와 함께 제시되어 있는가
- [ ] 영역별 평가 단계가 명시되어 있는가
- [ ] 종합 매트릭스가 시각화되어 있는가
- [ ] 벤치마킹 비교가 포함되어 있는가
- [ ] 부서·계층 간 인식 차이가 별도로 다루어졌는가
- [ ] 분석의 한계가 솔직히 명시되어 있는가
- [ ] 분량이 적정한가 (30~50p)
- [ ] 익명성이 일관되게 유지되었는가
