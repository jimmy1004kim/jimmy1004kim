## 이 문서는

T6의 **개별 산출물 (T6-1~10) 을 "언제·어떤 순서로·어떻게 연결해 진행하는가"의 전체 흐름·게이트·역할을 규정한 워크플로우 문서**.

T6 산출물 구조에서의 위치:

```
[T6-1~10 개별 산출물 (템플릿)]
        ↓
[T6-11 표준 절차] ← 본 문서 (전체 흐름·게이트)
[T6-12 인터뷰 절차] (핵심 활동 상세)
```

### 표준 절차 vs 개별 산출물

|구분|개별 산출물 (T6-1~10)|**T6-11 표준 절차**|
|---|---|---|
|답하는 질문|"이 문서 어떻게 쓰나"|**"전체를 어떻게 진행하나"**|
|범위|단일 산출물|**6주 전 과정**|
|강조|양식·작성법|**순서·게이트·역할·연결**|
|비유|레시피|**요리 전체 코스 계획**|

### 컨설팅·진단 표준 절차의 4대 역할

|역할|의미|
|---|---|
|**반복 가능성**|누가 해도 일정 품질|
|**게이트 통제**|단계별 검증·리스크 관리|
|**역할 명확**|컨설턴트 5명·고객 협업|
|**품질 보증**|산출물 연결·일관성|

### 진단 프로젝트의 5단계 (Phase)

```
[Phase 1: 착수·계획]
   ↓ G1
[Phase 2: 현황 조사 (인터뷰·설문·관찰·데이터)]
   ↓ G2
[Phase 3: 분석·진단 (AS-IS·문제·원인)]
   ↓ G3
[Phase 4: 개선 방향·로드맵]
   ↓ G4
[Phase 5: 보고·전달]
   ↓ G5
[종료·후속]
```

|**G4: 방향 합의**|Phase 4 종료|개선 방향·로드맵 CDO 합의|
|**G5: 보고 완료**|Phase 5 종료|최종 보고·발표·의사결정|

## 7. 가설 기반 접근 (Hypothesis-Driven)

### 가설 기반 진단의 흐름

```
[Phase 1] 초기 가설 수립
   - 사전 정보·RFP·킥오프 기반
   - "왜 이런 문제가 있을 것" 가설
        ↓
[Phase 2] 가설 검증 설계·데이터 수집
   - 인터뷰·설문·데이터로 검증 계획
        ↓
[Phase 3] 가설 검증·수정
   - 확인·기각·수정
   - 새 가설 발견 시 추가 검증
        ↓
[Phase 4~5] 결론·개선
```

### 가설 기반의 장점

|장점|의미|
|---|---|
|**효율성**|6주 안에 집중|
|**방향성**|무엇을 봐야 할지 명확|
|**유연성**|검증 결과 따라 수정|

### 주의 — 확증 편향 방지

- 가설에 맞는 데이터만 찾지 않기
- 가설 기각도 적극 수용
- CDO·다양한 인터뷰로 균형

### 회고 (Lessons Learned)

|항목|질문|
|---|---|
|잘된 점|무엇이 효과적이었나|
|개선점|무엇이 부족했나|
|프로세스|표준 절차 갱신 필요?|

### 후속 비즈니스 (진단 → 실행)

진단은 종종 **실행 컨설팅·구축 프로젝트** 로 이어짐:

- 데이터원더 → IM-1~4 실행 컨설팅 (12개월)
- 또는 데이터 플랫폼 구축 (T4 영역)

→ 진단의 후속 = 매출 확대 기회
