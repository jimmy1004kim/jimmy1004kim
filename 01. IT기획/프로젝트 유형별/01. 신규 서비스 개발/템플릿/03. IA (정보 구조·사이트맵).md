## 이 문서는

서비스의 **전체 페이지 구조와 메뉴 체계를 한눈에 보여주는** 지도.

"이 서비스에 어떤 페이지들이 있는가, 그것들이 어떻게 묶여 있는가, 사용자가 어디에서 무엇을 만나는가" 를 정리한다.

비슷한 산출물들과의 차이:

| 구분  | IA            | User Flow       | 화면 정의서            |
| --- | ------------- | --------------- | ----------------- |
| 대상  | 페이지 구조 (정적)   | 사용자 행동 흐름 (동적)  | 화면 단위 상세          |
| 단위  | 페이지·메뉴        | 행동·분기·결과        | 화면 1개             |
| 질문  | 어떤 페이지들이 있는가? | 사용자가 어떻게 이동하는가? | 이 화면은 무엇으로 구성되는가? |
| 깊이  | 전체 조감         | 시나리오별           | 컴포넌트·정책 수준        |

**핵심**: IA는 **건축물의 평면도**. User Flow는 사람의 동선, 화면 정의서는 방 하나의 설계도. 셋이 합쳐져야 설계가 완성된다.

## 언제 만드나

- PRD 합의 후, 기능 정의서·화면 정의서 작성 직전
- 서비스 컨셉 확정 직후 (구조가 머릿속에 그려질 때)
- v2.0급 대규모 개편 시
- 새 기능군이 기존 IA에 안 들어갈 때

**기준**: "이 서비스에 어떤 페이지가 있는지 한 페이지로 보여달라"는 질문에 답해야 할 때.

## 어떤 툴로

| 툴                              | 추천도  | 이유                |
| ------------------------------ | ---- | ----------------- |
| **Figma / FigJam**             | ⭐ 추천 | 트리·플로우 시각화, 협업 강함 |
| **노션 (트리 형식)**                 | 추천   | 문서와 연결 강함, 시각 약함  |
| **Whimsical / Miro / draw.io** | 추천   | IA 전용 도구, 빠른 작성   |
| Lucidchart                     | 보조   | 대규모 IA 적합         |
| Excel·Spreadsheet              | 보조   | 간단한 트리 표현         |

**팁**: 시각적 IA(Figma) + 텍스트 IA(노션) 둘 다 두는 게 가장 강력. 시각은 공유용, 텍스트는 검색·연결용.

## IA의 두 가지 표현 방식

### 1. 트리 다이어그램 (시각형)

```
홈
├── 둘러보기
│   ├── 카테고리 A
│   └── 카테고리 B
├── 마이페이지
│   ├── 프로필
│   └── 설정
└── 로그인/가입
```

### 2. 표 형식 (텍스트형)

|Depth 1|Depth 2|Depth 3|URL|페이지 ID|비고|
|---|---|---|---|---|---|
|홈|||/|P-001||
|둘러보기|카테고리 A||/browse/a|P-002||

둘 다 만들 것. 시각형은 공유·발표용, 표 형식은 검색·연결·관리용.

## 들어가야 할 것

- 전체 페이지 트리 (Depth 3~4까지)
- 각 페이지의 ID·URL·진입 권한
- 메뉴 그룹·라벨
- 공통 영역 (헤더·푸터·사이드바)
- 사용자 권한별 IA 차이 (필요 시)
- 모바일·PC 차이 (필요 시)
- 외부 진입점 (검색·SNS·딥링크)

## 작성 절차

1. **사용자 멘탈 모델 그리기** — 사용자가 머릿속으로 이 서비스를 어떻게 그릴지
2. **핵심 기능군 묶기** — 비슷한 기능끼리 그룹화
3. **트리 다이어그램 v0.1** — Figma·Whimsical로 빠르게
4. **표 형식 작성** — 각 페이지에 ID·URL·권한 부여
5. **사용자 흐름과 검증** — User Flow와 대조해 빠진 페이지 없는지
6. **이해관계자 리뷰** — 디자인·개발·CS·마케팅
7. **카드 소팅·트리 테스트 (선택)** — 실제 사용자로 분류 직관성 검증
8. **v1.0 확정 → 화면 정의서로 분기**

## 작성 팁

- **사용자 멘탈 모델 우선** — 우리가 정리하기 편한 구조 X, 사용자가 기대하는 구조 ⭕. 카드 소팅으로 검증 가능
- **Depth 3 한계** — 3단계 이상 깊이는 사용자가 못 찾음. 4단계 넘어가면 IA 재설계 신호
- **메뉴 라벨은 사용자 언어로** — "MyContents" ❌, "내 콘텐츠" ⭕. 내부 코드명을 노출하지 말 것
- **권한 분기를 반드시 명시** — 같은 페이지라도 게스트·로그인·관리자가 다르게 보면 IA 다르게 그려야
- **공통 영역(헤더·푸터)을 IA에 포함** — 페이지 트리만 그리고 공통 영역 누락 → 화면 정의서에서 폭발
- **외부 진입점 식별** — 사용자는 홈에서만 들어오지 않음. SNS·이메일·푸시 진입점도 IA의 일부
- **시각형 + 표 형식 둘 다** — 시각은 발표·합의용, 표는 검색·연결·관리용. 한 가지만 두면 한쪽이 약해짐
- **페이지 ID는 영원히 고정** — 페이지 삭제해도 번호 재사용 X. 추적성 깨짐
- **URL 패턴 일관성** — 명사 복수형, 케밥 케이스, 동사형 회피. `/biz/projects/new` ⭕, `/createProject` ❌
- **모바일과 PC가 다른 IA라면 별도 트리** — 작게 다르면 비고로, 크게 다르면 별도 트리
- **카드 소팅·트리 테스트 권장** — 실제 사용자 5~10명이 카테고리를 어떻게 묶는지 확인하면 IA 완성도 ↑

## 자주 하는 실수

- **사용자 멘탈 모델 무시** — 내부 조직 구조대로 IA 설계 → 사용자는 못 찾음
- **Depth 폭주** — 5단계, 6단계까지 깊이 → 사용자 도달률 0
- **메뉴 라벨이 내부 용어** — "Account", "Workspace" 같은 추상어 → 사용자 혼란
- **권한별 IA 누락** — 게스트·관리자 IA가 다른데 같은 트리만 그림 → 개발에서 추측으로 채움
- **공통 영역(헤더·푸터) 누락** — 페이지 트리만 그리고 끝 → 화면 정의서 단계에서 다시 작업
- **외부 진입점 누락** — 홈만 진입점으로 가정 → SEO·딥링크 설계 누락
- **시각형만 또는 표 형식만** — 한쪽만 두면 검색·합의 중 하나가 약해짐
- **페이지 ID 재사용** — 삭제된 페이지 번호를 새 페이지에 부여 → 추적 깨짐
- **URL 일관성 무시** — 어떤 페이지는 `/users`, 어떤 페이지는 `/user_list` → API·SEO·분석 모두 혼란
- **모바일 따로 그리고 안 함** — PC IA가 그대로 모바일에 적용 가능하다고 가정 → 모바일 UX 깨짐
- **IA 확정 없이 화면 정의서 시작** — IA 변경되면 화면 정의서 다시. 순서가 중요

## 작성 후 체크

- [ ] 모든 페이지에 ID·URL·진입 권한이 부여되었는가
- [ ] Depth가 4를 넘지 않는가
- [ ] 메뉴 라벨이 사용자 언어로 되어 있는가
- [ ] 권한별 IA 차이가 명시되어 있는가
- [ ] 헤더·푸터·사이드바 공통 영역이 정리되어 있는가
- [ ] 외부 진입점(검색·SNS·이메일·푸시)이 식별되어 있는가
- [ ] 시각형 + 표 형식 둘 다 있는가
- [ ] URL 패턴이 일관되어 있는가 (복수형·케밥 케이스 등)
- [ ] User Flow와 정합성이 검증되었는가 (빠진 페이지 없는가)
- [ ] 이해관계자 리뷰 (디자인·개발·CS·마케팅)가 끝났는가
- [ ] (선택) 카드 소팅·트리 테스트로 사용자 검증을 했는가
