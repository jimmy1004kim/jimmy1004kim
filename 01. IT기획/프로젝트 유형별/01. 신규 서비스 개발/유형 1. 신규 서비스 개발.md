## 정의

세상에 없던, 또는 우리 회사가 처음 내놓는 서비스를 처음부터 만드는 일. 
시장·사용자·해결할 문제가 아직 명확하지 않은 상태에서 출발하는 게 특징이다. 
흔히 말하는 "0에서 1을 만드는" 프로젝트.

## 발생 상황

- 신사업·신규 라인 추진
- 스타트업 창업 또는 신규 프로덕트 런칭
- 기존 사업의 확장 (예: B2C에서 B2B로, 단일 제품에서 플랫폼으로)
- 신규 기능이 아닌, 독립된 "서비스 단위"가 필요해진 경우

## 업무 흐름

```
문제 정의 → 컨셉 정의 → PRD 작성 → 구조·상세 설계 → 개발 → QA → 출시 → 운영 전환
```

|단계|핵심 작업|
|---|---|
|문제 정의|누구의 어떤 문제를 풀 것인지 정의, 타겟·KPI 설정|
|컨셉 정의|서비스의 한 줄 정의, 차별점, 비즈니스 모델 윤곽|
|PRD 작성|기능·정책·KPI·범위를 통합 문서로 정리|
|구조·상세 설계|IA, User Flow, 기능·화면·데이터·정책 명세화|
|개발|우선순위에 따라 구현, 변경 관리|
|QA|시나리오 기반 검증|
|출시|배포, 초기 모니터링·대응|
|운영 전환|데이터 기반 개선 사이클로 이관 (유형 3으로 전환)|

## 기획자 역할

- **문제와 가설 정의** — "누가 어떤 상황에서 무슨 문제로 고통받는가"를 한 문장으로 설명. 검증 가능한 가설로 만들기
- **PRD 작성과 유지** — 프로젝트의 단일 기준 문서. 시작부터 끝까지 살아있는 문서로 운영
- **MVP 범위 결정** — 욕심을 잘라내고 가장 작은 단위로 출시 가능한 범위 정의. 가장 어려운 일
- **구조·상세 설계 리딩** — IA, User Flow, 기능·화면·데이터·정책·권한 정의
- **우선순위·릴리즈 관리** — 백로그를 다루고, 무엇을 먼저 낼지 결정
- **개발 협업** — 개발자·디자이너와 일하면서 변경 요청과 일정을 관리
- **품질 검증** — QA 시나리오 작성, 검증 결과 반영
- **데이터·성과 설계** — 이벤트 트래킹과 KPI 측정 체계를 출시 전에 미리 설계
- **운영 인계** — 출시 후 유형 3(개선) 사이클로 매끄럽게 넘기기

## 주요 산출물 (✅ = 필수)

### 정의·전략

- ✅ 서비스 컨셉서 — 한 줄 정의, 타겟, 차별점
- ✅ PRD (제품 요구사항 문서) — 모든 것의 기준 문서
- ⬜ 시장·경쟁 분석서
- ⬜ 페르소나
- ⬜ JTBD (Job-to-be-Done)
- ⬜ 비즈니스 모델 (수익 구조)
- ⬜ 북극성 지표(NSM) 정의서

### 구조·상세 설계

- ✅ IA (사이트맵)
- ✅ User Flow (사용자 흐름도)
- ✅ 기능 정의서 (Feature Spec)
- ✅ 화면 정의서 (Screen Spec)
- ✅ 정책 정의서 (Business Rule)
- ✅ 데이터 정의서 (Data Spec)
- ⬜ User Scenario (실제 사용 맥락)
- ⬜ 상태 흐름도 (State Flow) — 주문·결제 등 상태가 중요한 경우
- ⬜ 권한 정의 (Role & Permission)
- ⬜ API 명세서

### 실행·관리

- ✅ MVP 범위 정의서
- ✅ 릴리즈 계획 / 로드맵
- ⬜ 개발 백로그 / 우선순위 리스트
- ⬜ 이슈 관리 대장

### 검증·측정

- ✅ QA 시나리오 / 테스트 케이스
- ✅ 이벤트 트래킹 정의 (Analytics 설계)
- ⬜ KPI 정의서
- ⬜ A/B 테스트·실험 설계서
- ⬜ 에러·예외 처리 정의
- ⬜ 출시 후 회고

## 특징

- **불확실성이 가장 높다** — 답이 정해지지 않은 상태에서 출발
- **기획자의 의사결정 영향이 크다** — 초기 선택이 서비스 운명을 좌우
- **MVP 정의가 성패를 가른다** — 욕심을 줄이는 게 가장 중요한 일
- **전 라이프사이클 관여** — 정의부터 운영 전환까지 길게 따라감
- **출시가 끝이 아니다** — 출시는 검증의 시작점, 진짜 일은 그 다음

## 자주 빠지는 함정

- 가설 없이 "있으면 좋을 것 같은" 기능 나열
- MVP가 MVP가 아닌, 욕심으로 가득 찬 1차 출시
- 측정 설계를 출시 후에 시작 → 데이터 공백 발생
- 페르소나가 추상적이라 의사결정 근거가 못 됨
- 비즈니스 모델 검토를 뒤로 미루다가 출시 후 수익 구조 부재
