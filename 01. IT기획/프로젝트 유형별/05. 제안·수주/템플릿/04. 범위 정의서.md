## 이 문서는

본 사업에서 **무엇이 포함되고 무엇이 포함되지 않는지를 명확히 선 긋는 문서**.

수주 후 가장 흔한 분쟁은 "이거 당연히 포함되는 거 아니에요?" vs "이건 별도 항목이에요"의 충돌이다. 범위 정의서는 이 분쟁의 사전 방어선이다.

**견적·일정·검수 기준의 근거 문서**가 되며, 변경 관리(Change Order)의 출발점이 된다.

## 다른 문서와의 관계

| 문서           | 역할                     |
| ------------ | ---------------------- |
| RFP 분석서      | 고객 요구 해석 (내부용)         |
| **범위 정의서**   | **포함·제외를 명확히 (대외 합의)** |
| 제안서          | 우리의 수행 방안              |
| 견적서          | 위 범위 기준 가격             |
| 계약서·SoW      | 범위 정의서를 부속으로 첨부        |
| Change Order | 범위를 벗어나는 요청 처리         |

**범위 정의서가 모든 후속 문서의 기준선(Baseline)이다.**

## 언제 만드나

제안 단계 또는 계약 직전. 두 시점이 가능하다.

|시점|특징|
|---|---|
|**제안서에 포함**|제안 단계부터 명확화. 공공·대형 사업 권장|
|**계약 직전 별도 작성**|계약서의 부속 문서로. 민간 사업 흔함|

**가장 안전한 방법**: 제안서 작성 시 초안 → 계약 직전 최종 합의.

## 어떤 툴로

|툴|추천도|이유|
|---|---|---|
|**MS 워드 / HWP**|⭐ 추천|계약 부속 문서로 첨부. 공식성 필요|
|노션|추천|내부 협의·초안 단계|
|엑셀|보조|범위 매트릭스 형태로 정리 시 강력|

**팁**: 노션·엑셀로 초안 → 워드/HWP로 최종 정리.

## 범위 정의의 5가지 영역

범위는 단순히 "기능 목록"이 아니다. 다음 5가지 영역을 모두 정의해야 분쟁이 없다.

### 1. 기능 범위 (Functional Scope)

- 어떤 기능을 만들 것인가
- **가장 흔히 정의됨, 가장 흔히 분쟁됨**

### 2. 비기능 범위 (Non-functional Scope)

- 성능·보안·가용성 등 품질 기준
- 명시 안 하면 "당연히 이 정도는" 분쟁

### 3. 산출물 범위 (Deliverable Scope)

- 어떤 문서·결과물을 납품할 것인가
- 코드·문서·교육·운영 인계 등

### 4. 서비스 범위 (Service Scope)

- 개발 외 서비스 (회의·교육·이관·유지보수)
- "회의는 몇 회까지?", "교육은 몇 시간?" 등 정량화

### 5. 책임 범위 (Responsibility Scope)

- 고객이 해야 할 일 vs 우리가 해야 할 일
- "데이터 이관은 누가?", "운영 환경 셋업은 누가?" 등

## 포함·제외 작성의 핵심 원칙

### 1. 포함보다 제외가 더 중요

"이건 안 합니다"가 명확해야 분쟁이 없다. 모호하면 무조건 고객 편으로 해석된다.

### 2. RFP 용어 그대로 사용

RFP에서 "통합 인사관리"라고 했으면 우리도 동일하게. 멋대로 줄이거나 바꾸지 말 것.

### 3. 정량적으로 표기

"적정량의 회의" ❌ "PM 정기 보고 회의 주 1회 × 24주 (총 24회)" ⭕

### 4. 가정·전제 명시

"고객사 ISMS-P 인증 자료를 우리에게 제공한다는 전제"처럼 우리가 의존하는 조건을 명시.

### 5. 향후 확장 가능성 분리

"이번 사업에는 없지만 추후 Phase 2에서"라는 표현으로 향후 사업 연결 가능성 시사.

## 자주 하는 실수

- **포함만 적고 제외 누락** — 모호한 부분 = 고객 편 해석 → 무상 추가 작업
- **추상적 표현** — "원활한 협업", "충분한 교육" 등 정량화 안 됨 → 분쟁 시 약함
- **RFP 용어 변경** — "통합 인사관리" → "HRMS"로 멋대로 바꿈 → 매칭 안 됨
- **고객 책임 누락** — "데이터는 당연히 고객이 주겠지" → 안 주면 우리가 책임
- **전제 조건 누락** — 외부 의존 조건 명시 안 함 → 일정 지연 시 우리 책임으로 귀결
- **합의·서명 생략** — "구두 합의"로 끝냄 → 사람 바뀌면 무효
- **변경 관리 절차 누락** — Change Order 없이 진행 → 추가 비용 청구 불가
