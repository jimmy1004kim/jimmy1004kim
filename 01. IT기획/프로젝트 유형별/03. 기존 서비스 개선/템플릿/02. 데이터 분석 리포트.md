## 이 문서는

운영 중인 서비스의 **데이터를 분석해서 인사이트·문제·기회를 도출**한 보고서.

T3 산출물 흐름에서의 위치:

```
[T3-1 문제 정의서] ←→ [T3-2 데이터 분석] → [T3-3 가설] → [T3-4 개선 기획]
        ↑                  ↓
   (데이터에서 문제 발견)  (분석으로 검증)
```

데이터 분석은 **문제 정의의 근거**이면서, 문제 정의에서 출발한 **심층 분석**도 됨. 양방향.

### 분석의 5가지 유형

|유형|목적|예시|
|---|---|---|
|**Descriptive (기술적)**|무엇이 일어났나|월 KPI 추이·세그먼트 분포|
|**Diagnostic (진단적)**|왜 일어났나|전환율 하락 원인·이탈 패턴|
|**Predictive (예측적)**|무엇이 일어날 것인가|이탈 예측·매출 전망|
|**Prescriptive (처방적)**|무엇을 해야 하나|추천 알고리즘·최적화|
|**Exploratory (탐색적)**|패턴 발견|코호트 분석·세그먼테이션|

이 가이드는 5가지 모두 다룰 수 있는 표준 형식. **Descriptive + Diagnostic** 중심.

### 좋은 분석 vs 나쁜 분석

|좋은 분석|나쁜 분석|
|---|---|
|명확한 질문에서 출발|"데이터 한 번 봐볼까"|
|가설·결론·근거 모두 포함|숫자 나열만|
|시각화 + 해석|차트만|
|한계·가정 명시|절대 진리처럼|
|다음 액션 제시|보고만|

### 분석가 vs PM의 역할

|역할|PM|데이터 분석가|
|---|---|---|
|질문 정의|**PM 주도**|협업|
|데이터 추출·정제|요청|**분석가 주도**|
|분석 실행|함께|**분석가 주도**|
|해석·인사이트|**함께**|함께|
|다음 액션|**PM 주도**|협업|

PM이 질문·해석·액션을 주도, 분석가가 실행. 협업 필수.

## 6. 핵심 발견 (Key Findings)

### Finding 1: 메시지→계약 단계가 병목

**무엇을 발견했나**:

- 매칭→메시지 전송률: **75%** (1,200건 매칭 중 900건 메시지)
- 메시지→계약 전환율: **43%** (900건 메시지 중 387건 계약)
- 매칭→계약 종합: 32%

**시각화**: Funnel 차트

```
[매칭 1,200건] → 75% → [메시지 900건] → 43% → [계약 387건]
                                       ↑ 병목
```

**해석**:

- 메시지 전송 단계까지는 사용자 활발 (75%)
- 메시지 전송 후 계약까지 가는 비율이 절반 미만 (43%)
- 사용자가 "메시지는 보냈으나 결국 계약 안 함" 상태

### Finding 2: 신뢰 신호 (검증 마크)가 전환에 결정적

**무엇을 발견했나**:

|세그먼트|메시지→계약 전환율|
|---|---|
|**검증 마크 보유 프리랜서**|**52%**|
|검증 마크 미보유 프리랜서|38%|
|**차이**|**+14pp (1.42배)**|

**해석**:

- 검증 마크 보유 여부가 전환에 큰 영향
- 그러나 현재 매칭 알고리즘에서 검증 마크 가중치는 15%에 불과

### Finding 3: 평가 누적이 신뢰의 핵심

**무엇을 발견했나**:

|평가 누적 수|메시지→계약 전환율|
|---|---|
|0건|28%|
|1~2건|36%|
|3~4건|47%|
|**5건 이상**|**58%**|
|10건 이상|64%|

**해석**:

- 평가 누적이 늘수록 전환율 급증
- 5건 누적이 전환의 임계점 (Threshold)
- 그러나 평가 누적의 알고리즘 가중치는 10%에 불과

### Finding 4: 매칭 알고리즘 가중치 분석

**현재 알고리즘 가중치**:

|요소|가중치|
|---|---|
|기술 스택 일치도|**40%**|
|검증 마크 보유|15%|
|평균 평가 점수|15%|
|평가 누적 수|10%|
|단가·예산 매칭|10%|
|위치·근무형태|10%|

**전환율과의 상관계수** (피어슨 상관):

|요소|전환율과 상관계수 (R²)|
|---|---|
|기술 스택 일치도|0.18 (낮음)|
|**검증 마크 보유**|**0.42 (중간 ↑)**|
|평균 평가 점수|0.35 (중간)|
|**평가 누적 수**|**0.48 (강함)**|
|단가·예산 매칭|0.12|
|위치·근무형태|0.08|

**해석**:

- **알고리즘 가중치가 전환율 영향력과 어긋남**
- 기술 일치도 (40%) → 전환 영향 0.18 (낮음)
- 평가 누적 수 (10%) → 전환 영향 0.48 (강함)
- **신뢰 신호 가중치 ↑·기술 가중치 ↓ 시 전환율 개선 가능성 ↑**

## 8. 인사이트·해석

### Insight 1: 신뢰가 전환의 핵심

전환율 32% 정체의 근본 원인은 매칭 추천 단계에서 **사용자가 신뢰할 만한 정보를 충분히 받지 못함**. 검증·평가·평가 누적이 전환에 결정적이나 알고리즘이 이를 충분히 반영하지 못함.

### Insight 2: 신규 기업이 가장 큰 기회 + 위험

신규 기업의 전환율 24%는 재방문(35%)·다회(42%) 대비 크게 낮음. **신규 기업의 신뢰 형성**이 NSM 도달의 핵심 레버.

### Insight 3: 알고리즘 가중치 조정 가능성 ↑

기술 일치도(40%) → 전환 영향 0.18, 평가 누적(10%) → 전환 영향 0.48. **가중치 ↔ 영향력 어긋남**이 명확. 조정 시 큰 개선 가능.

### Insight 4: 빠른 검증 가능

알고리즘 가중치 변경은 **코드 1주 작업** + 4주 A/B 테스트로 검증 가능. ROI 매우 높음.

- **질문에서 출발** — "데이터 봐볼까" ❌, "왜 전환율 정체?" ⭕
- **Executive Summary 한 페이지** — 의사결정자는 이거만 봄
- **시각화 + 해석** — 차트만 ❌. "그래서 뭐가 중요한가" 글로 정리
- **한계·가정 명시** — 분석 신뢰성·범위. 안 적으면 절대 진리처럼 오해
- **인과 vs 상관 구분** — 상관계수 0.5는 인과 아님. A/B 테스트로 인과 검증
- **재현 가능성** — SQL·코드·시각화 원본 공개. 다른 사람이 재현 가능해야
- **다음 액션** — 분석 → 문제 정의 → 가설 → 실험 흐름
- **PM 주도 + 분석가 협업** — PM은 질문·해석·액션, 분석가는 실행
- **세그먼트 분석 필수** — 평균만 ❌. 신규/기존·세그먼트별 분석
- **funnel 분석은 정의 명확** — 어떤 이벤트가 어느 단계인지
- **외부 요인 (계절성·시장) 고려** — 모든 변동이 우리 책임 아님
- **포트폴리오 자산** — 잘 쓴 분석은 PM·분석가의 강력한 케이스 스터디
