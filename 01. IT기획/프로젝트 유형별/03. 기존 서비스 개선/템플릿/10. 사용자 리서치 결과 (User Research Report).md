## 이 문서는

사용자 인터뷰·설문·관찰 등을 통해 얻은 **정성·정량 인사이트를 정리한 보고서**.

T3 산출물 흐름에서의 위치:

```
[T3-2 데이터 분석] ↔ [T3-10 사용자 리서치] → [T3-1 문제 정의] → [T3-3 가설]
        ↓                    ↓
   "무엇이 일어나는가"   "왜 사용자가 그렇게 행동하는가"
```

다른 산출물과의 비교:

|구분|T3-2 데이터 분석|T3-10 사용자 리서치|T3-3 가설 정의서|
|---|---|---|---|
|출발|**숫자에서**|**사람에서**|문제 정의 후|
|깊이|무엇이·어떻게 일어나는가|**왜 그렇게 행동하는가**|어떻게 해결|
|데이터|정량 (대량)|**정성 (소량·심층)** + 정량 (설문)|—|
|청중|PM·분석가·의사결정자|PM·디자인·전체 팀|팀·분석가|

**핵심**: 데이터 분석이 "What·How"라면, 사용자 리서치는 **"Why"**. 둘이 합쳐져야 진짜 인사이트.

### 데이터 vs 리서치의 보완 관계

```
[T3-2 데이터 분석]
- 매칭→계약 전환율 32% 정체
- 메시지→계약 단계 병목 (43%)
- 검증 보유자 전환율 1.42배 높음
   ↓ 사실 발견
[T3-10 사용자 리서치]
- "추천받은 5명 중 누가 진짜 신뢰할지 모르겠다" (60%)
- "검증 마크가 있지만 그게 얼마나 신뢰할 만한지 판단 어렵다" (45%)
- "평가 1~2개로는 부족하다" (52%)
   ↓ 왜 그런가 이해
[T3-3 가설 도출]
- 매칭 알고리즘 신뢰도 가중치 재조정
```

### 리서치의 5가지 유형

|유형|목적|방법|
|---|---|---|
|**사용자 인터뷰 (Generative)**|새 인사이트·문제 발견|1:1 60~90분, 5~30명|
|**사용성 테스트 (Usability)**|UI·UX 검증|과업 수행 관찰, 5~10명|
|**설문 (Quantitative)**|가설·패턴 검증|온라인 설문, 100~1,000명|
|**세션 녹화·히트맵**|실제 행동 관찰|Hotjar·Clarity, 50~200세션|
|**다이어리 스터디**|장기 사용 패턴|1~4주 일기 기록, 5~10명|

이 가이드는 5가지 모두 다룰 수 있는 표준 형식. **사용자 인터뷰**를 중심으로 설명.

### 인터뷰의 3가지 원칙

1. **객관성**: 리딩 질문 X, 답을 끌어내지 말 것
2. **심층성**: "왜?" 5번 — 표면 답에서 멈추지 말 것
3. **재현 가능성**: 인터뷰 가이드·녹취·정리 표준화

## 5. 핵심 발견

### Finding 1: 사용자 60%가 "누가 진짜 신뢰할지 모르겠다"

**무엇을 발견했나**:

- **17/28 (61%)** 가 매칭 결과에서 신뢰할 만한 사람을 식별하기 어렵다고 응답
- 매칭 결과 페이지에 머무는 시간 평균 8분 (다른 페이지 대비 매우 김)

**대표 인용**:

> "추천받은 5명이 다 비슷해 보여요. 누가 더 좋은지 모르겠어요." — P03 (스타트업 CTO, 첫 매칭) "이력서는 좋아 보이는데 진짜 일을 잘하는지는 안 보이거든요." — P12 (재방문 기업 사업팀) "기술 스택은 매칭됐다는데, 그게 진짜 우리한테 잘 맞는지는..." — P17 (다회 기업 CTO)

**관찰된 패턴**:

- 매칭 결과 페이지에서 사용자는 카드 5개를 여러 번 비교
- 한 카드 클릭 후 다시 돌아가 다른 카드와 비교 (90% 이상)
- 결정 부담으로 메시지까지 보내고도 망설임

**해석**:

- 알고리즘 점수가 추천 근거지만 사용자는 추가 신뢰 정보 필요
- 5명 추천이 "신뢰할 만한 5명"이 아니라 "어떻게 비교해야 할지 모르는 5명"

### Finding 2: 검증 마크 의미를 명확히 아는 사용자는 33%만

**무엇을 발견했나**:

- 검증 마크 의미 설명 요청 시 **9/28 (32%)** 만 정확히 설명
- 나머지: "그냥 좋은 사람 표시?" "회사가 보장하는 건가요?" 등 모호한 답변

**대표 인용**:

> "검증 마크가 뭔지 정확히 모르겠어요. 그냥 좋은 표시인가 보다 하는 거죠." — P05 "GitHub 검증이래도 그게 얼마나 신뢰할 만한 건지..." — P14 "검증 마크 있어도 평가가 1~2개면 별로 안 믿어요." — P09

**관찰된 패턴**:

- 검증 마크에 마우스 오버해도 툴팁 안 봄 (Think Aloud 결과)
- 검증 의미보다 평가 누적 수에 더 주목

**해석**:

- 검증 마크 UI가 "신뢰 시그널"로 작동 안 함
- 검증 의미·신뢰성 자체에 대한 사용자 학습 부족

### Finding 3: 평가 1~2개로는 신뢰 부족, 5개+가 임계점

**무엇을 발견했나**:

- **52% (15/28)** "평가 1~2개로는 부족하다"
- "신뢰할 만한 평가 누적 수"를 물었을 때:
    - 1~2개: 0%
    - 3~4개: 18%
    - **5~9개: 54%** (가장 많음)
    - 10개 이상: 28%

**대표 인용**:

> "평가 1~2개는 의미 없어요. 5개 이상은 돼야 신뢰가 가죠." — P11 "별점 4.8점이라도 평가가 2개면 잘 안 믿어요. 우연일 수도 있고." — P06

**해석**:

- 평가 누적 5건이 신뢰의 심리적 임계점
- 알고리즘에서 평가 누적 가중치 ↑ 필요

### Finding 4: 신규 기업이 가장 큰 신뢰 장벽 경험

**무엇을 발견했나**:

- 신규 기업 (1~2회 매칭) 10명 중 **8명 (80%)** 이 신뢰 부족 가장 크게 호소
- 재방문·다회 기업은 자체 판단 기준 형성

**대표 인용**:

> "처음 사용할 때는 누가 좋은지 정말 모르겠어요. 그냥 점수 높은 사람만 봤어요." — P02 (첫 매칭) "몇 번 해보니까 이제는 평가 수랑 검증 마크 같이 보면 감이 와요." — P22 (8회 매칭)

**해석**:

- 신규 기업 신뢰 형성이 NSM 도달 핵심 (전체 35%)
- 사용자 가이드·온보딩 강화 필요 (HYP-010 후보)

### Finding 5: "기술 일치"보다 "같이 일할 만한 사람"

**무엇을 발견했나**:

- "매칭 시 가장 중요한 기준"에 대한 답변:
    - 기술 스택 일치: 18% (4번째)
    - **같이 일할 만한 사람 (커뮤니케이션·태도): 68%** (1번째)
    - 평가·평판: 54%
    - 검증·신뢰: 46%

**대표 인용**:

> "기술 일치도가 80%여도 안 맞으면 의미 없어요. 같이 일하기 좋은 사람이 더 중요해요." — P19 "결국 사람이잖아요. 검증된 사람·평가 좋은 사람이 더 끌려요." — P08

**해석**:

- 매칭 알고리즘이 기술 일치도 40% 가중치 — 사용자 우선순위와 어긋남
- 신뢰·평가 가중치 ↑ 시 사용자 우선순위와 일치 (HYP-007의 강한 근거)

## 8. 인사이트·해석

### Insight 1: "신뢰의 양·질" 모두 부족

검증 마크는 있으나 사용자가 의미 이해 못 함 (질). 평가 누적이 적어 신뢰 형성 안 됨 (양). 둘 다 해결 필요.

### Insight 2: 사용자 우선순위와 알고리즘 가중치 어긋남

사용자는 "같이 일할 만한 사람"(68%) 우선. 알고리즘은 기술 일치(40%) 우선. 가중치 재조정 시 큰 개선 가능.

### Insight 3: 신규 기업이 가장 큰 레버

신규 기업 (35%) 의 신뢰 장벽이 가장 큼. 알고리즘 + UI + 온보딩 가이드의 복합 개선 필요.

### Insight 4: 평가 누적 5건이 임계점

심리적 임계점 5건 — 알고리즘 가중치·UI 강조 모두 5건 기준 활용 가능.

## 작성 팁

- **데이터와 짝** — 정량 (분석)과 정성 (리서치) 둘 다 — 보완 관계
- **인용 (Verbatim) 필수** — "사용자가 그렇게 말했다"는 강력한 근거
- **빈도 (정량화)** — "60% 응답" 등. 인용만 ❌
- **리딩 질문 X** — "검증 마크 좋죠?" ❌. 사용자 답 끌어내지 말 것
- **"왜?" 5번** — 표면 답에서 멈추지 말 것
- **녹화·전사** — 자료 영구 보관. Otter 자동 전사
- **태깅·affinity diagram** — 정성 데이터를 구조화. Miro·FigJam 활용
- **페르소나·여정 도출** — 추상 → 구체. 디자인·기능 결정의 기반
- **발언 vs 행동 차이 인식** — 말한 대로 행동 안 함. 행동 데이터 + 인터뷰 종합
- **표본 크기 5~10명도 OK** — 정성은 적은 표본으로도 패턴 발견 가능 (Nielsen)
- **다음 액션 명확** — 가설·디자인·문제 정의로 발전
- **포트폴리오 자산** — 사용자 인용·페르소나는 PM의 강력한 자산

## 자주 하는 실수

- **리딩 질문** — "이거 좋죠?" → 답 끌어냄 → 편향
- **표면 답에서 멈춤** — "왜" 안 묻고 끝 → 인사이트 X
- **인용 없음** — "사용자가 좋다 했음" → 설득력 X
- **빈도 정량화 누락** — 인용만 → "전체 의견인지" 모호
- **표본 너무 적음** — 3명만 → 일반화 어려움
- **표본 너무 많음** — 50명 인터뷰 → 정리 못 함 (정량 설문이 나음)
- **세그먼트 편향** — 한 세그먼트만 → 다른 세그먼트 인사이트 누락
- **녹화 안 함** — 메모만 → 정확성 ↓
- **affinity diagram 안 함** — 인용만 나열 → 패턴 발견 X
- **데이터·리서치 분리** — 정량·정성 따로 → 종합 인사이트 X
- **다음 액션 모호** — "검토 필요" → 실행 안 됨
- **포트폴리오 자산화 누락** — 인용·페르소나 다음 프로젝트에서 처음부터
