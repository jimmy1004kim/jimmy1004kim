## 이 문서는

A/B 실험·개선 프로젝트 종료 후 **"우리 팀이 무엇을 배웠는가"를 정리하는 회고 문서**.

T3 산출물 흐름에서의 위치:

```
[T3-11 A/B 결과] → [T3-12 실험 회고] → [T3-8 성과 분석] (3개월 후)
        ↓                 ↓                      ↓
   "무엇이 일어났나"  "우리가 무엇을 배웠나"   "장기 효과 어떤가"
```

다른 산출물과의 비교:

|구분|T3-11 결과 보고서|T3-12 실험 회고|C-08 회고 템플릿 (공통)|
|---|---|---|---|
|청중|의사결정자·전체 팀|**팀 (PM·개발·디자인·분석가)**|프로젝트 종료 시|
|강조|사실·의사결정|**학습·프로세스 개선**|프로젝트 전반 회고|
|산출물|Rollout 결정|**차기 실험 개선·자산화**|다음 프로젝트 가이드|
|시점|실험 종료 직후 (1주)|**실험·Rollout 완료 직후**|프로젝트 종료 후|

**핵심**: 결과 보고서가 **"무엇이 일어났는가"** 라면, 회고는 **"우리가 무엇을 배웠는가"**. 다음 실험을 더 잘하기 위한 자산.

### 결과 보고서 vs 실험 회고 — 왜 두 문서가 필요한가

|결과 보고서|실험 회고|
|---|---|
|외부 보고용 (의사결정자)|**내부 학습용 (팀)**|
|결과 중심|**프로세스 중심**|
|1회 작성 → 발효|**반복 활용** (다음 실험 가이드)|
|가설 검증 결과|**가설 자체의 질·실험 설계의 질**|

결과만 있고 회고 없으면 → 같은 실수 반복.

### 회고의 5가지 책임

1. **잘한 점·아쉬운 점 정리** — Keep·Drop·Try
2. **프로세스 개선 도출** — 다음 실험의 가이드
3. **개인·팀 학습 누적** — 개인 학습 + 팀 자산화
4. **실패도 학습** — 실패 가설은 성공보다 더 중요한 학습
5. **포트폴리오 자산화** — 케이스 스터디

### 실험 결과 4가지 시나리오별 회고 강조

|시나리오|회고 강조|
|---|---|
|🟢 **성공**|"왜 성공했나" 패턴 추출 → 차기 가설에 적용|
|🟡 **부분 성공**|"왜 일부만 성공했나" + 재실험·보완 방향|
|🔴 **실패**|"왜 실패했나" — 가설·실험 설계·외부 요인 분리|
|⚪ **무의미**|"왜 검증 불가했나" — 표본·기간·지표 정의 점검|

모든 시나리오에서 학습 가능. **실패가 가장 값진 학습** (이유 명확화하면 같은 실수 X).

### 회고 프레임워크 5종 (중 1~2개 선택)

|프레임워크|강조|
|---|---|
|**Keep·Drop·Try (KDT)**|단순, 빠른 회고|
|**Mad·Sad·Glad**|감정 + 행동|
|**Start·Stop·Continue**|행동 변화|
|**4Ls** (Liked·Learned·Lacked·Longed for)|학습 강조|
|**Fishbone (이시카와)**|실패 원인 심층 분석|

본 가이드는 **KDT + 4Ls** 조합 권장 (실험 회고에 적합).

## 언제 만드나

- A/B 실험 종료 + Rollout 결정 직후 (1주 이내)

## 4. 4Ls

### Liked (좋았던 점)

- 사용자 인터뷰에서 직접 들은 "60%가 신뢰 부족"이 가설로 발전 → 검증된 순간의 짜릿함
- 분기 1번 큰 개선이 실제로 성공한 케이스 — 팀 전체 자신감 ↑
- PM·분석가·디자인·개발 협업 정말 좋았음. 모두 같은 목표·언어 사용

### Learned (배운 점)

- **알고리즘 가중치는 사용자 우선순위와 정합해야 큰 효과** — 핵심 학습
- **신규 사용자 효과가 가장 큼** — 차기 가설 우선순위 명확해짐 (HYP-010)
- **단기 효과 ≠ 장기 효과** 가능성 인지 → 3개월 후 측정 중요성
- 통계적 유의성 (p=0.0008) 과 실무적 유의성 (+9.3pp) 둘 다 필요
- 사전 시뮬레이션이 실험 신뢰도 ↑ → 다음 실험부터 의무화

### Lacked (부족했던 점)

- 정성 인터뷰 다회 기업 (7명) 표본 부족 — 다회 기업 효과 (p=0.18) 검증 어려움
- 사전 부하 테스트 깊이 부족 → 5/12 캐시 미스 이슈 발생
- Rollout 모니터링 알람 사전 셋업 누락
- 운영 중 사용자 알아채는지 별도 모니터링 없었음 (학습 추적)

### Longed for (희망 사항)

- 더 빠른 사이클 (4주 → 3주)을 위한 실험 도구 자동화
- 정성 데이터 자동 태깅·affinity diagram 도구 (Dovetail 등)
- A/B 결과 자동 시각화 대시보드
- 차기 가설 후보 라이브러리 (백로그 인벤토리 강화)

## 5. 가설·실험 설계 회고

### 5.1 가설의 질

- ✅ **가설 명확** (If-Then-Because-Validation 4요소 모두)
- ✅ **근거 강함** — 데이터(DA-2028Q1-005) + 인터뷰(UR-2028Q1-003) + 외부(Upwork 등) 모두
- ✅ **검증 가능** — Primary 지표 명확, 통계 검정 가능
- 평가: **5/5**

### 5.2 실험 설계의 질

- ✅ **표본 적절** — 사전 계산 1,300명/그룹, 실제 1,300+명 확보
- ✅ **Primary·Secondary·Guardrail 잘 선정** — 4가지 시나리오 명확
- ✅ **성공·실패 기준 명확** — 사전 정의
- 🟡 **외부 요인 점검 시뮬레이션 부족** — 시뮬레이션을 4/28 (실험 1주 전)에 함. 더 일찍 (2주 전)이 안전
- 평가: **4/5**

### 5.3 운영의 질

- ✅ **중간 점검 일정 (1·2·3주차) 잘 작동**
- ✅ **조기 종료 함정 회피** — 2주차 좋아 보였지만 계획 사수
- 🟡 **5/12 응답 시간 이슈** — 사전 부하 테스트 부족 → 캐시 미스 발견 늦음

- 평가: **4/5**

## 9. 포트폴리오 자산화·케이스 스터디

### 9.1 자산화 가능 산출물

이번 실험은 **PM·분석가의 매우 강력한 케이스 스터디**가 될 것:

- 데이터 + 인터뷰 → 가설 → 실험 → 검증 → Rollout의 완벽한 흐름
- 매출 효과 +연 144억 추정 (정량 임팩트)
- 신규 기업 +11.6pp 효과 (세그먼트 인사이트)
- 4주 실험 + 4주 Rollout = 8주 사이클로 완료

### 9.2 포트폴리오 정리
