## 이 문서는

운영 중인 서비스에서 **개선이 필요한 문제를 명확히 정의하고 우선순위화**하는 문서.

T3 산출물 흐름의 출발점:

```
[T3-1 문제 정의서] → [T3-2 데이터 분석] → [T3-3 가설] → [T3-4 개선 기획] → 실행
```

다른 산출물과의 비교:

|구분|T3-1 문제 정의서|T3-3 가설 정의서|
|---|---|---|
|단위|**문제 1건** (PROB-XXX)|가설 1건 (HYP-XXX)|
|깊이|**무엇이·왜 문제**|어떻게 해결할 것|
|시점|가설 작성 전|문제 정의 후|
|결과물|우선순위 + 해결 방향 후보|검증 가능한 가설|

**핵심**: 문제 정의서는 **"무엇이·왜 문제인가"**, 가설 정의서는 **"어떻게 해결할 것인가"**. 문제 정의 없이 가설부터 가면 잘못된 문제 풀기 쉬움.

### "솔루션 점프" 의 함정

가장 흔한 실수 — 문제 정의 없이 해결책부터:

|흐름|결과|
|---|---|
|❌ "검색 기능을 개선하자" → 작업 → 출시 → 효과 없음|잘못된 문제 풀기|
|⭕ "검색 후 클릭률 12% (업계 35%)" → "왜?" → "검색 결과 품질 낮음" → 가설 → 검증|진짜 문제 해결|

문제 정의서는 **"솔루션 점프"를 막는 장치**.

### 문제의 5가지 출처

|출처|예시|
|---|---|
|**정량 데이터**|KPI 정체·이탈률 증가·전환율 감소|
|**정성 피드백**|CS 문의·사용자 인터뷰·NPS|
|**운영팀 관찰**|운영자가 매일 보는 패턴|
|**경쟁사·시장**|경쟁사 신기능·시장 트렌드|
|**내부 발견**|A/B 테스트·코호트 분석에서 우연 발견|

좋은 PM은 **5가지 모두 모니터링**.

### 문제의 표준 구조

```
1. 현상 (What) — 무엇이 일어나고 있는가
2. 근거 (Evidence) — 정량·정성 데이터
3. 영향 (Impact) — 비즈니스·사용자에 미치는 영향
4. 원인 가설 (Why) — 왜 일어나는가 (5 Why)
5. 영향 받는 사용자 (Who) — 누구의 문제인가
6. 긴급도·우선순위 (When)
```

# 📌 예시 — TalentMatch PROB-003 매칭→계약 전환율 정체

> 가상 사례. HYP-007의 출발점이 된 문제 정의

## 메타

|항목|내용|
|---|---|
|문제 ID|PROB-003|
|문제명|매칭→계약 전환율 1년간 32% 정체, NSM 목표 도달 불가|
|작성자|홍길동 (PM) + 김데이터|
|작성일|2028-04-05|
|상태|🟢 Defined (가설 HYP-007로 발전)|
|긴급도|🔴 Urgent|
|분류|비즈니스 KPI|

## 1. 현상

### 1.1 한 줄 정의

**매칭→계약 전환율이 1년간 32%에 정체되어 NSM(월 계약 수) 목표 500건 도달 불가능 상태.**

### 1.2 상세 설명

- 출시 시점 (2027-04) H1 검증값 30~32% → 1년 후 (2028-03) 여전히 32%
- 같은 기간 매칭 요청 수는 700건/월 → 1,200건/월로 71% 증가
- 매칭 풀(프리랜서 수)도 1,500명 → 3,800명으로 증가
- 그러나 **전환율은 변동 없음**
- 결과: 월 계약 280건 (목표 500건의 56%)

### 1.3 언제부터·얼마나 자주

- 시점: 2027-04 (정식 출시)부터 지속
- 빈도: 매월 모니터링
- 추세: **정체** (악화는 아니지만 개선도 없음)

## 2. 근거

### 2.1 정량 데이터

|지표|현재값 (2028-03)|출시 시점|1년 후 목표|출처|
|---|---|---|---|---|
|매칭→계약 전환율|**32%**|32% (H1 검증값)|40%|Amplitude funnel|
|월 계약 수 (NSM)|**280건**|30건|500건|자체 DB|
|월 매칭 요청 수|1,200건|100건|— (입력)|Amplitude|
|월 거래액|45억|5억|80억|자체 DB|
|매칭→메시지 전송률|75%|70%|—|Amplitude|
|**메시지→계약 전환율**|**43%** ⭐|43%|60%|Amplitude funnel|
|검증 보유자 전환율|미보유 대비 1.42배|1.45배|—|사용자 속성 코호트|

⭐ **병목 식별**: 메시지→계약 단계가 가장 큰 이탈 지점

### 2.2 정성 근거

#### 사용자 인터뷰 (2028-03, 28명)

- "추천받은 5명 중 누가 진짜 신뢰할 만한지 모르겠다" — **60%** 응답
- "검증 마크는 있지만 얼마나 신뢰할 만한지 판단 어렵다" — **45%**
- "평가 1~2개로는 부족하다, 더 많은 누적이 필요" — **52%**
- "기술 스택 일치는 잘 되는데, 결국 같이 일하기는 망설여진다" — **48%**

#### CS 문의 패턴 (2028-Q1, 약 380건 분석)

- "매칭 결과 신뢰 부족" 관련: **24%** (가장 많음)
- "추천 기준 모르겠음": 18%
- "검증 마크 의미 명확하지 않음": 14%

#### NPS·만족도 (2028-Q1)

- 기업 사용자 NPS: **22점** (출시 시점 35점에서 하락)
- "매칭 추천의 신뢰도" 영역 점수: **6.8/10** (가장 낮음)

#### 운영팀 관찰

- 매칭 후 메시지 보냈으나 계약까지 안 가는 경우 90% 이상이 **"신뢰 부족"** 사유

### 2.3 외부 비교

|출처|데이터|
|---|---|
|업계 평균 (글로벌 IT 프리랜서 플랫폼)|매칭→계약 전환율 35~45%|
|Upwork 공개 자료|평균 38%|
|자체 과거 (출시 시점 vs 현재)|32% → 32% (정체)|

## 3. 영향

### 3.1 비즈니스 영향

|영향 항목|추정값|
|---|---|
|**매출 손실**|전환율 32% → 40% 달성 시 월 계약 +70건, **월 거래액 +12억, 연 144억**|
|**NSM 영향**|월 계약 280 → 500 도달 가능성 (전환율 개선 + 풀 확장)|
|**운영 비용**|CS 문의 24% 감소 가능 (월 약 90건 ↓)|
|**신뢰·평판**|NPS 22 → 35+ 회복 가능|

### 3.2 사용자 영향

|영향|내용|
|---|---|
|영향 받는 사용자 수|월 매칭 요청 1,200건 (기업 600개사) + 추천 풀 3,800명|
|사용자 경험 영향|신뢰 부족 → 의사결정 부담 ↑ → 이탈|
|이탈 영향|기업 이탈률 35% (목표 25%) — 매칭 후 계약 안 되면 다음 매칭도 줄어듦|

## 4. 원인 가설 (5 Why)

### 5 Why 분석

|Why #|질문|답변|
|---|---|---|
|Why 1|왜 매칭→계약 전환율이 정체되었나?|메시지→계약 전환율 (43%)이 병목이기 때문|
|Why 2|왜 메시지→계약 전환율이 낮은가?|사용자가 추천받은 프리랜서에 대한 **신뢰 부족**|
|Why 3|왜 신뢰가 부족한가?|검증 마크 있어도 평가 누적 적으면 신뢰 못 함 + 매칭 결과에 신뢰 정보 비중이 낮음|
|Why 4|왜 매칭 결과에 신뢰 정보 비중이 낮나?|매칭 알고리즘이 **기술 일치도(40%) 중심**이고 신뢰 신호(검증·평가)는 25%에 불과|
|Why 5 (근본 원인)|왜 기술 일치도 중심으로 설계되었나?|출시 시점에 데이터 부족 (평가·누적 없음) → 기술 매칭 중심으로 시작 → 1년 후 신뢰 데이터 누적되었으나 알고리즘 가중치 미조정|

### 원인 후보 (병렬)

|#|원인|근거|가능성|
|---|---|---|---|
|1|매칭 알고리즘 가중치 부적절 (신뢰 < 기술)|5 Why + 인터뷰 결과|**高**|
|2|검증 마크 UI 신뢰도 표시 미흡|CS 문의 "검증 의미 모름" 14%|中|
|3|평가 시스템 자체 신뢰도 부족 (평가 누적 부족)|평가 5건 이상 보유자만 58% 전환|中|
|4|프리랜서 풀 자체 품질 (검증 마크 65%)|검증 보유 비율 정체|低~中|

## 작성 팁

- **솔루션 점프 금지** — "검색 개선하자" 같은 해결책 먼저 X. 문제부터
- **현상 + 근거 + 영향 + 원인 + 우선순위 5요소** — 하나라도 빠지면 문제 정의 X
- **정량 + 정성 모두** — 데이터만 ❌ (왜 모름), 인터뷰만 ❌ (영향력 모름)
- **5 Why로 근본 원인** — 표면 원인에서 멈추지 말 것
- **외부 비교 (업계·경쟁사) 활용** — 우리 32%가 좋은지 나쁜지 알기 위해
- **세그먼트 분석** — "모든 사용자" ❌. 누구의 문제인지 구체적으로
- **긴급도·우선순위 점수화** — 다른 문제와 비교 가능
- **해결 방향 다수** — 가설 후보 여러 개. 최선 1개만 ❌
- **다음 액션 명확** — 가설 정의서·리서치·실행 등. 담당·기한 포함
- **문제 정의 → 가설 → 실험 흐름 추적** — 산출물 ID로 연결
- **포트폴리오 자산** — 잘 정의된 문제는 케이스 스터디의 출발점

## 자주 하는 실수

- **솔루션 점프** — 문제 정의 없이 해결책부터 → 잘못된 문제 풀기
- **현상만, 원인 없음** — "전환율이 낮다" → 왜 낮은지 모름
- **데이터 없는 문제 정의** — 직관·감만 → 우선순위 결정 못 함
- **인터뷰 없는 데이터** — 숫자만 보고 → 왜 그런지 모름
- **5 Why 1~2단계에서 멈춤** — 근본 원인 미도달
- **세그먼트 분석 X** — "모든 사용자" → 타겟 모호
- **외부 비교 누락** — 우리 32%가 좋은지 나쁜지 모름
- **긴급도 점수 없음** — 다른 문제와 비교 불가
- **해결 방향 1개만** — 다양한 가설 후보 누락
- **다음 액션 모호** — "검토 필요" → 누가·언제 X
- **문제·가설·실험 연결 안 됨** — 산출물 ID 없음 → 추적 불가
- **포트폴리오 자산화 누락** — 잘 정의된 문제 케이스 스터디 손실
