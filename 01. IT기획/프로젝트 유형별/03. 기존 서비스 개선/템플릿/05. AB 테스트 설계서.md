## 이 문서는

가설을 **실험으로 검증하기 위한 설계 청사진**.

T3 산출물 흐름에서의 위치:

```
[T3-3 가설] → [T3-4 개선 기획] → [T3-5 A/B 설계서] → 구현 → 실험 → [T3-11 결과] → [T3-12 회고]
```

다른 산출물과의 비교:

|구분|T3-3 가설 정의서|T3-5 A/B 설계서|T3-11 결과 보고서|
|---|---|---|---|
|단위|가설 1건|**실험 1건 (설계)**|실험 1건 (결과)|
|시점|가설 도출 시|**실험 시작 전**|실험 종료 후|
|깊이|If-Then-Because|**어떻게 실행할 것인가**|무엇이 일어났는가|
|효력|실험의 근거|**실험 실행의 청사진**|의사결정 근거|

**핵심**: 가설은 "무엇을 검증할 것인가", 설계서는 **"어떻게 검증할 것인가"** 의 구체. 설계서 없이 실험 X.

### 좋은 A/B 테스트의 5가지 조건

1. **명확한 가설** (HYP-XXX 연결)
2. **충분한 표본 크기** — 통계적 유의성 보장
3. **공정한 무작위 배정** — 편향 없음
4. **단일 변수** — 1번에 1가지만 변경 (다중 변수는 다변량 테스트)
5. **사전 정의된 성공·실패 기준** — 결과 모호 X

### A/B 테스트 vs 다변량 테스트 (Multivariate)

|구분|A/B 테스트|다변량 테스트 (MVT)|
|---|---|---|
|변수|**1개** (단일)|2~4개 (조합)|
|표본 요구|적음|많음|
|인과 추론|명확|복잡|
|적용|일반적|표본 풍부할 때만|

이 가이드는 **A/B 테스트** 중심. MVT는 보조.

### A/B 테스트의 4가지 함정

|함정|증상|본 절차의 대응|
|---|---|---|
|**조기 종료 (Early Stopping)**|좋은 결과 보고 일찍 끝냄|사전 정의된 기간·표본 사수|
|**p-hacking**|여러 지표 검증해 우연히 유의 발견|Primary 지표 1개 사전 고정|
|**표본 부족**|검정력 부족 → 무의미한 결과|사전 표본 크기 계산|
|**외부 요인**|마케팅·계절성 영향 혼동|동시 운영 + 무작위 배정|

본 설계서는 위 4가지를 모두 막는 장치.

### 1.1 한 줄 정의

매칭 알고리즘 가중치를 **기술 일치도 ↓ + 신뢰도(검증·평가·누적) ↑** 로 재조정해 매칭→계약 전환율을 향상시키는지 검증.

### 1.2 가설 (HYP-007 요약)

- **변경**: 기술 가중치 40%→30% / 검증·평가·누적 25%→40% / 단가·위치 20%→10%
- **기대**: 매칭→계약 전환율 32% → 40% (+8pp, 25% 향상)
- **근거**: 검증 보유자 전환율 1.42배 + 평가 누적 5건+ 전환율 1.6배 (DA-2028Q1-005·UR-2028Q1-003)
- **검증**: 4주 A/B 테스트, p<0.05

### 1.3 비즈니스 임팩트 (예상)

- **성공 시**: 월 계약 280 → 360건 (+80건), 월 거래액 +12억, 연 144억
- **실패 시**: 가설 폐기, HYP-008 (UI 개선) 진행

## 작성 팁

- **가설 (HYP-XXX) 연결 필수** — 설계서는 가설의 실행. 가설 없이 실험 X
- **단일 변수 (A/B)** — 한 번에 1개만. 여러 개 변경 시 인과 추론 어려움
- **표본 크기 사전 계산** — 도구 활용 (Evan Miller·Amplitude). 표본 부족하면 무의미한 결과
- **Primary 지표 1개 사전 고정** — p-hacking 방지. 여러 지표 본 후 "이게 통과" X
- **Guardrail 필수** — Primary만 보면 부작용 놓침. 1~3개 사전 정의
- **성공·실패·무의미 4가지 기준 사전 정의** — 결과 모호하지 않게
- **조기 종료 함정 주의** — 중간에 좋아져도 사전 정의된 기간·표본 사수
- **사전 QA 체크리스트** — 배정 무작위성·Sticky·이벤트 추적 검증
- **외부 영향 사전 점검** — 마케팅·계절성·신기능 출시 시점 확인
- **백업 측정** — 도구 장애 대비 자체 DB에도 기록
- **롤백 절차 사전 정의** — Guardrail 악화 시 자동 롤백
- **Rollout 단계적** — 성공 시 50% → 75% → 100% (1~2주 분산)
- **세그먼트 분석** — 전체뿐 아니라 신규/재방문 등 세그먼트별 효과 다를 수 있음
- **재현 가능성** — 코드·SQL·시뮬레이션 모두 공개
- **포트폴리오 자산** — 잘 설계된 실험은 PM·분석가의 강력한 자산

- **사전 QA 부족** — 배정 무작위성 검증 X → 편향
- **롤백 절차 없음** — Guardrail 악화 시 우왕좌왕
- **Rollout 일시에** — 성공 후 100% 한번에 → 위험
- **세그먼트 분석 X** — 평균만 봄 → 세그먼트별 다른 효과 놓침
- **재현 가능성 X** — 코드·SQL 공유 안 함 → 재현 못 함
- **포트폴리오 자산화 누락** — 실험 흐름 다음 프로젝트에서 처음부터
