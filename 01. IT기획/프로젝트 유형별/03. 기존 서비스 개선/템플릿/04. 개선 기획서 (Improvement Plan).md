## 이 문서는

가설을 **실행 가능한 개선 프로젝트로 구체화**한 종합 기획 문서.

T3 산출물 흐름에서의 위치:

```
[T3-1 문제] → [T3-2 분석] → [T3-3 가설] → [T3-4 개선 기획서] → [T3-5 A/B 설계] → [T3-6 기능 변경] → [T3-7 화면 변경]
                                            ↑
                                  개선 1건의 종합 청사진
```

다른 산출물과의 비교:

|구분|T3-3 가설 정의서|T3-4 개선 기획서|T3-5 A/B 설계서|
|---|---|---|---|
|단위|가설 1건 (HYP-XXX)|**개선 프로젝트 1건** (IMP-XXX)|실험 1건 (EXP-XXX)|
|깊이|무엇을 → 어떤 결과|**무엇을·어떻게·언제·얼마**|실험 설계만|
|청중|분석가·팀|**의사결정자·전체 팀**|데이터 분석가·개발|
|효력|실험의 근거|**실행의 청사진**|실험의 청사진|
|범위|가설|가설 + 일정 + 인력 + 비용 + 일정 + 영향 + 리스크|실험 단독|

**핵심**: 개선 기획서는 **"가설 + 실행 계획"**을 합친 종합 문서. 가설만으로는 실행 불가, 기획서가 있어야 실행 가능.

### 가설 vs 개선 기획서 — 왜 두 문서가 필요한가

|가설 정의서|개선 기획서|
|---|---|
|1주 만에 작성|2~3주 작업|
|분석가·PM 작성|PM 주도 + 디자인·개발·법무 협업|
|의사결정 안 함|**GO/NO-GO 의사결정**|
|구체 일정·인력·비용 없음|**상세 일정·인력·비용**|
|실험 진행 안 함|**실행 청사진**|

가설은 "할 만한 일인가" 결정, 기획서는 "어떻게 할 것인가" 결정.

### 개선 기획서의 5가지 책임

1. **가설 + 실행 합치기** — 분석에서 실행 청사진까지
2. **전체 영향 파악** — 화면·기능·정책·데이터·외부 의존성 모두
3. **의사결정자 GO/NO-GO** — 비용·일정·리스크 포함
4. **이해관계자 공통 합의** — PM·디자인·개발·법무·운영
5. **실행 추적의 기준** — 일정·예산·범위 변경 시 기준

### 가벼운 개선 vs 큰 개선

|구분|가벼운 개선|큰 개선|
|---|---|---|
|예시|버튼 색·텍스트 변경|알고리즘 재설계·신규 페이지|
|인력|1~2명, 1~3일|3~10명, 2~8주|
|영향|1~2개 화면·기능|다수 화면·기능·정책|
|문서|가설 정의서만으로 OK|**개선 기획서 필수**|
|의사결정자|PM 단독|**CTO·PO 합의**|

이 가이드는 **큰 개선**용. 가벼운 개선은 가설만으로 진행.

## 메타

|항목|내용|
|---|---|
|개선 ID|IMP-2028Q2-001|
|개선명|매칭 알고리즘 신뢰도 가중치 재조정|
|관련 가설|HYP-007|
|관련 문제 정의서|PROB-003|
|작성자|홍길동 (PM)|
|작성일|2028-04-18|
|상태|🟢 Approved (2028-04-20 GO 결정)|
|우선순위|🔴 Critical|
|분류|알고리즘|
|실행 시작일 (예정)|2028-04-22|
|실행 종료일 (예정)|2028-06-30 (Rollout 완료)|
|총 예산|11,200,000원|

## Executive Summary

### 한 줄 정의

**매칭 알고리즘의 신뢰도(검증·평가·평가 누적) 가중치를 ↑·기술 일치도 가중치를 ↓로 재조정해 매칭→계약 전환율 32% → 40% 향상.**

### 배경·기회

- 출시 1년 후 매칭→계약 전환율 32% 정체 (목표 40%)
- 메시지→계약 단계 병목 (43%) — 신뢰 부족이 주원인
- 사용자 인터뷰: "누가 신뢰할지 모르겠다" (60%)
- 알고리즘 가중치 vs 전환 영향력 어긋남 (DA-2028Q1-005 검증)

### 핵심 변경

1. **매칭 알고리즘 가중치 재조정** (기술 40%→30%, 신뢰 25%→40%, 단가·위치 20%→10%)
2. A/B 테스트로 4주 검증 후 단계적 Rollout
3. 매칭 결과 페이지·관리자 모니터링 강화 (보조)

### 기대 효과

- 매칭→계약 전환율 32% → **40%** (+8pp)
- 월 계약 280 → **360건** (+80건)
- 월 거래액 +12억, **연 144억**
- NSM(월 계약 500) 도달 가능성 ↑

### 필요 자원

- 일정: **약 10주** (구현 1주 + QA 1주 + A/B 4주 + 분석 1주 + Rollout 3주)
- 인력: 2.4 M/M (백엔드 1, 분석가 0.5, QA 0.4, PM 0.5)
- 비용: **11,200,000원**

### 리스크 (Top 3)

## 1. 배경·문제·가설

### 1.1 문제 (PROB-003 요약)

매칭→계약 전환율이 1년간 32%에 정체. NSM(월 500 계약) 목표 미달 (현재 280, 56%).

### 1.2 데이터 근거 (DA-2028Q1-005 요약)

- 메시지→계약 단계 병목 (43%)
- 검증 보유자 전환율 1.42배·평가 누적 5건+ 1.6배 높음
- 알고리즘 가중치 vs 전환 영향력 어긋남 (기술 일치도 40% 가중치 → 영향 0.18 / 평가 누적 10% 가중치 → 영향 0.48)

### 1.3 사용자 인사이트 (UR-2028Q1-003 요약)

- "추천받은 5명 중 누가 신뢰할지 모르겠다" 60%
- "검증 마크 의미 모르겠다" 45%, "평가 1~2개 부족" 52%
- "기술 일치보다 같이 일할 만한 사람이 중요" 68%

### 1.4 가설 (HYP-007 요약)

**If** 매칭 알고리즘 가중치를 기술 ↓·신뢰 ↑로 재조정하면, **Then** 매칭→계약 전환율 32% → 40% (+8pp), **Because** 검증·평가 누적이 전환에 결정적이나 알고리즘이 충분히 반영 못 함, **Validation** 4주 A/B 테스트, p<0.05, +8pp 이상.

- **변경 사항 누락** — 데이터·API 빠뜨림 → 일정 폭증
- **범위 모호** — 작업 폭증·일정 깨짐
- **일정만, 인력·비용 없음** — 의사결정 못 함
- **영향 분석 누락** — 회귀 영향 모름 → 출시 후 부작용
- **리스크·완화 누락** — 실패 시 대응 못 함
- **롤백 절차 없음** — Guardrail 악화 시 우왕좌왕
- **후속 산출물 안 적음** — 누가·언제 작성할지 모름
- **단독 결정** — CTO·PO 미참석 → 막판 거절
- **회고·자산화 누락** — 같은 실수 다음 프로젝트

## 작성 후 체크

- [ ] 가설 (HYP-XXX) 연결되었는가
- [ ] Executive Summary 한 페이지에 들어갔는가
- [ ] 배경·문제·가설·사용자 인사이트 요약되었는가
- [ ] 범위 (포함·제외) 명확한가
- [ ] 변경 사항 5분류 (기능·화면·정책·데이터·API) 모두 포함되었는가
- [ ] 일정·마일스톤 명확한가
- [ ] 인력 (M/M)·비용 정량화되었는가
- [ ] 영향 분석 4가지 (사용자·시스템·운영·회귀) 있는가
- [ ] 리스크 5~7개 + 완화 방안 있는가
- [ ] 롤백 절차 정의되었는가
- [ ] GO/NO-GO 회의·결정 명시되었는가
- [ ] 후속 산출물 (A/B·기능·화면·회귀·회고) 계획되었는가
- [ ] 관련 산출물 (PROB·DA·UR·HYP) 연결되었는가
- [ ] 의사결정자 (CTO·PO) 승인되었는가
- [ ] 포트폴리오 자산화 절차 있는가
