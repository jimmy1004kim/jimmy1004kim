## 이 문서는

기존 서비스에 변경을 가할 때 **기존 기능·화면이 깨지지 않는지 검증하는 체크리스트**.

T3 산출물 흐름에서의 위치:

```
[T3-4 개선 기획] → [T3-6 기능 변경] + [T3-7 화면 변경] → [T3-9 회귀 테스트] → 실험·Rollout
                                                            ↑
                                                "변경이 기존을 깨지 않는지"
```

### 회귀 테스트가 왜 핵심인가

신규 서비스 (T1) vs 기존 서비스 개선 (T3) 의 결정적 차이:

|구분|신규 서비스|기존 서비스 개선|
|---|---|---|
|QA 강조|신규 기능 검증|**신규 검증 + 기존 깨짐 검증**|
|영향 범위|신규 코드만|**기존 코드도 영향 가능**|
|사용자|처음 사용|**이미 사용 중**|
|실패 영향|출시 미뤄짐|**운영 중 사용자 영향**|

**핵심**: 운영 중 서비스의 변경은 **기존 사용자 행동·데이터·통합을 깰 위험**이 있다. 회귀 테스트가 이를 막는 마지막 방어선.

### 회귀의 4가지 유형

|유형|의미|예시|
|---|---|---|
|**기능 회귀**|기존 기능이 더 이상 작동 안 함|매칭 알고리즘 변경 후 기존 매칭 결과 페이지 깨짐|
|**시각 회귀 (Visual)**|기존 UI 레이아웃·디자인 깨짐|카드 변경 후 다른 페이지의 카드 레이아웃 깨짐|
|**성능 회귀**|응답 시간·처리량 악화|알고리즘 변경 후 응답 시간 5초 → 8초|
|**데이터 회귀**|기존 데이터 손상·호환성 깨짐|스키마 변경 후 기존 데이터 조회 안 됨|

본 체크리스트는 **4가지 모두** 검증.

### 회귀 테스트의 5가지 수준

|수준|의미|적용|
|---|---|---|
|**Level 1. 영향 범위 식별**|무엇이 영향받는가|모든 변경|
|**Level 2. 핵심 흐름 검증**|Critical 사용자 흐름|모든 변경|
|**Level 3. 직접 영향 기능**|변경된 기능·인접 기능|Modify·Migrate|
|**Level 4. 간접 영향 식별**|데이터·API 통합·외부 의존|데이터·API 변경 시|
|**Level 5. 자동화 회귀 슈트**|E2E·단위 테스트 자동 실행|모든 변경 (장기)|

### 회귀 발견 시점에 따른 비용

|시점|발견·수정 비용|
|---|---|
|**개발 중**|1× (가장 저렴)|
|**QA 중 (회귀 테스트)**|5~10×|
|**Stage 환경**|10~20×|
|**A/B 실험 중**|50~100×|
|**Rollout 후 운영**|**100~500×** (가장 비쌈)|

**회귀 테스트는 가장 비용 효율적인 품질 보증**.

## 언제 만드나

- 기능 변경·화면 변경 정의서 (T3-6·T3-7) 작성 완료 후
- A/B 실험 시작 1~2주 전 (M2 — 개발 완료 직전)
- 큰 개선의 Rollout 직전 (최종 점검)

**기준**: 개발 완료 + QA 본격 시작 직전.

- **시각 회귀는 자동화 (Percy·Chromatic)** — 수동만으로는 한계
- **성능 회귀 정량 기준** — "비슷함" ❌. ±10% 이내·P95 등 명확
- **데이터·API 호환성 검증** — Breaking Change 없는지
- **브라우저·OS 회귀** — 모든 환경 검증 (특히 모바일)
- **반응형 회귀** — 데스크탑·태블릿·모바일 모두
- **Severity 분류 명확** — Critical·High·Medium·Low
- **자동화 슈트 누적** — 매 개선마다 자동 슈트 확장 (장기 자산)
- **회귀 발견 시 처리 절차 사전** — 우왕좌왕 X
- **A/B·Rollout 진입 결정의 근거** — 회귀 통과가 게이트

## 자주 하는 실수

- **신규 기능만 검증** — 기존 깨짐 발견 못 함 → 출시 후 부작용
- **핵심 흐름 누락** — Critical 사용자 흐름 안 봄 → 큰 사고
- **시각 회귀 수동만** — 자동화 안 함 → Diff 놓침
- **성능 회귀 정량 기준 없음** — "비슷함" 판정 → 누적 악화
- **데이터·API 호환성 안 봄** — Breaking Change 출시 후 발견
- **브라우저·OS 한정** — Chrome만 본다 → Safari·iOS 깨짐
- **Severity 분류 없음** — 모든 회귀 동일 취급 → 일정 폭주
- **자동화 슈트 없음** — 매번 처음부터 수동 → 비용 ↑↑
- **회귀 발견 시 절차 없음** — 우왕좌왕 → A/B 진입 결정 모호
- **A/B·Rollout 진입 게이트 모호** — 회귀 안 봐도 진입 → 부작용
- **포트폴리오 자산화 누락** — 회귀 슈트는 PM·QA의 자산
