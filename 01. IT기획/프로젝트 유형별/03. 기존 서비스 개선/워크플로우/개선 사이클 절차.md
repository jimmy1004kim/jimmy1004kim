## 이 문서는

운영 중인 서비스를 **데이터·가설 기반으로 지속 개선하는 표준 사이클**.

"문제 발견부터 개선 효과 측정까지 어떤 순서·게이트로 진행하는가" 를 정리.

T1·T2 워크플로우와의 비교:

|구분|T1 (신규 서비스)|T2 (외주 / 구축)|T3 (기존 개선)|
|---|---|---|---|
|라이프사이클|Discovery → Operate|Pre-Sales → Closure|**사이클 (반복)**|
|시작|문제·기회|영업·수주|**데이터·문제 발견**|
|종료|운영 전환|하자 보수 종료|**다음 사이클로 (반복)**|
|청중|자체 사업|양 당사자|**운영팀·전체 조직**|
|강조|가설 검증·MVP|계약·검수·인계|**반복·학습 누적**|

**핵심**: T3는 **사이클 (Cycle)**. 한 번 끝나지 않고 반복. 매 분기·매 월 반복하며 학습 누적.

### 개선 사이클의 7개 Phase

```
Phase 0. Discovery (문제·기회 발견)
   ↓ Gate 1: 문제 정의 확정
Phase 1. Diagnose (분석·리서치)
   ↓ Gate 2: 가설 정의 확정
Phase 2. Hypothesize (가설 도출·우선순위)
   ↓ Gate 3: 개선 기획 GO/NO-GO
Phase 3. Design (개선 기획·기능·화면 변경)
   ↓ Gate 4: A/B 실험 진입 (회귀 통과)
Phase 4. Build & Test (구현·QA·실험 운영)
   ↓ Gate 5: Rollout 결정
Phase 5. Rollout (단계적 출시)
   ↓ Gate 6: 안정화 통과
Phase 6. Measure & Learn (장기 측정·회고)
   ↓
다음 사이클로 (Phase 0)
```

각 Phase에 명확한 산출물·게이트·의사결정 기준.

### Phase 한눈에

|Phase|기간|핵심 활동|핵심 산출물|
|---|---|---|---|
|0. Discovery|상시|데이터·KPI 모니터링·문제 발견|T3-1 문제 정의서|
|1. Diagnose|1~2주|데이터 분석·사용자 리서치|T3-2·T3-10|
|2. Hypothesize|1주|가설 도출·우선순위|T3-3 가설 정의서|
|3. Design|1~3주|개선 기획·기능·화면 변경|T3-4·T3-6·T3-7|
|4. Build & Test|4~8주|구현·QA·A/B 실험|T3-5·T3-9·T3-11|
|5. Rollout|2~4주|단계적 Rollout|(Rollout 가이드)|
|6. Measure & Learn|1·3·6개월|장기 측정·회고|T3-8·T3-12|
|**사이클 합계**|**약 3~6개월**|||

### 사이클의 4가지 리듬

|리듬|활동|
|---|---|
|**일일**|KPI 모니터링·이상 감지|
|**주간**|진행 상황·소통|
|**월간**|백로그 그루밍·우선순위 재평가|
|**분기**|회고·차기 분기 계획·자산화|

T3는 동시에 여러 사이클 진행 가능 (병렬). 분기 단위로 통합 관리.

### 다른 워크플로우와의 관계

|워크플로우|위치|
|---|---|
|**새 프로젝트 시작** (공통)|Phase 3 진입 시|
|**프로젝트 종료** (공통)|Phase 6 사이클 종료 시|
|**자산화** (공통)|Phase 6 회고 직후|
|**T3-14. A/B 테스트 진행 절차**|Phase 4 세부|

## 자주 하는 실수

- **사이클 1회만** — 분기·월 반복 X
- **Discovery 건너뛰기** — 데이터 모니터링 없이 가설부터
- **게이트 무시** — 통과 없이 다음 Phase 진입
- **Phase 3 (Design) 건너뛰기** — 큰 개선도 기획서 없이
- **회귀 테스트 누락** — 부작용 출시 후 발견
- **A/B 없이 Rollout** — 검증 안 함
- **장기 측정 누락** — 단기만, 1·3·6개월 측정 X
- **회고 안 함** — 학습 손실
- **자산화 누락** — 같은 실수 반복
- **백로그 그루밍 X** — 우선순위 무용지물
- **외부 요인 점검 X** — 마케팅·시즌과 혼동
