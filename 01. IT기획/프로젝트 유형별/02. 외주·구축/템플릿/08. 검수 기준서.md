## 이 문서는

외주 프로젝트의 **각 산출물·기능·화면이 "완성됐다"고 판단할 객관적 기준**을 정리한 공식 문서.

다른 산출물과의 관계:

|구분|요구사항 정의서|화면 정의서 (AC 섹션)|검수 기준서|
|---|---|---|---|
|단위|요구사항 1건|화면 1개|**검수 단위 전체 (산출물·마일스톤)**|
|깊이|무엇을 원하는가|화면별 AC|**전체 검수 절차·기준·통과 조건**|
|청중|양 당사자|개발·QA·고객|**양 당사자 + 법무**|
|효력|작업 근거|화면 단위 검수|**결제·잔금 조건의 근거**|

**핵심**: 검수 기준서는 **"검수 통과·실패의 객관적 판단 기준"**. 모호하면 잔금 못 받음. 외주 프로젝트의 가장 분쟁 잦은 영역.

### 검수의 4가지 단위

| 단위              | 의미                          | 시점          |
| --------------- | --------------------------- | ----------- |
| **산출물 검수**      | 1 산출물 단위 (요구사항·기능·화면 정의서 등) | Phase 1·2   |
| **기능·화면 검수**    | 개별 기능·화면 단위                 | Phase 3·4   |
| **마일스톤 검수**     | M1~M5 단위 (다수 산출물 묶음)        | Phase별 종료 시 |
| **최종 검수 (UAT)** | 프로젝트 전체 단위                  | 출시 직전·직후    |

각 단위마다 기준·절차·통과 조건이 다르다.

### 검수 기준의 3가지 원칙

1. **객관적 측정 가능** — "잘 작동" ❌, "P95 3초 이내" ⭕
2. **사전 합의** — 작업 시작 전에 기준 합의. 작업 후 기준 추가 X
3. **추적 가능** — 요구사항·기능·화면·테스트 케이스와 매핑

### 외주 검수의 함정

|함정|증상|대응|
|---|---|---|
|**고객의 기준 변동**|"이거 더 좋아져야 해" → 끝없는 보완|검수 기준서로 객관 기준 합의|
|**검수 무응답**|검수 안 하고 끔 → 잔금 지연|검수 기한·자동 통과 조항|
|**모호한 기준**|"좋아 보이게" → 측정 불가|측정 가능 형태로 정의|
|**소급 적용**|검수 후 "이것도 안 되네" → 무한 추가|검수 후 변경은 CR|

검수 기준서는 위 4가지를 모두 막는 장치.

## 언제 만드나

- 요구사항 정의서·기능 리스트 합의 후 (Phase 1 후반)
- 화면 정의서 작성과 병행 (Phase 2)
- 계약·SoW 첨부 시 (검수 기준 첨부)
- 마일스톤 검수 직전 (해당 마일스톤 기준 재확인)

**기준**: SoW에 명시된 검수 절차의 세부 기준이 필요한 모든 시점.

## 어떤 툴로

|툴|추천도|이유|
|---|---|---|
|**노션 DB**|⭐ 강력 추천|기준 1개 = 1행. 검수 시 체크리스트|
|Excel·Google Sheets|추천|검수 실행 시 빠른 작성·인쇄|
|Word·PDF|추천|계약 첨부·서명용|
|Jira (Acceptance Criteria 필드)|보조|개발 추적 강함|

**최적**: 노션 DB (관리·검색) + PDF (계약 첨부·서명) + Excel (검수 실행 체크리스트).


## 작성 팁

- **객관적·측정 가능** — "잘 작동" ❌, "P95 3초 이내" ⭕. 기준이 모호하면 검수 분쟁
- **사전 합의 절대 원칙** — 작업 시작 전 합의. 작업 후 기준 추가 X
- **자동 통과 조항 필수** — 갑이 검수 안 끌고 끄는 상황 방지. 잔금 보호 장치
- **재검수·분쓴 절차 명시** — 협의 1차 → 의사결정자 2차 → 법원 3차 단계화
- **마일스톤 = 결제 트리거 명문화** — M2 = 중도금, M5 = 잔금. 모호하면 결제 지연
- **화면별 AC 활용** — 화면 정의서의 AC 섹션이 곧 검수 기준. 따로 만들지 말 것
- **UAT 시나리오 별도 합의** — UAT는 사용자 흐름 단위. 사전에 합의·고정
- **통과·조건부 통과·실패 3단계** — 흑백 X. 조건부 통과로 일정 유연성 확보
- **법무 검토 필수** — 결제 트리거에 영향. 한 문장이 큰 손해
- **검수 결과 기록·서명** — 매 검수마다 결과 기록 + 양 당사자 서명. 분쟁 시 결정적 증거
- **검수 기준은 살아있는 문서** — CR 발생 시 갱신. v1.1, v1.2로 버전 관리
- **포트폴리오 자산** — 잘 만든 검수 기준서는 다음 수주에서 70%+ 재사용

## 자주 하는 실수

- **모호한 기준** — "좋아 보이게" → 객관 판단 불가 → 검수 무한 반복
- **사후 기준 추가** — 작업 후 새 기준 도입 → 우리만 손해
- **자동 통과 조항 없음** — 검수 안 하고 끔 → 잔금 지연
- **재검수·분쟁 절차 없음** — 이견 발생 시 협의 무한 반복
- **결제 트리거 모호** — M2 통과 ≠ 중도금 청구 권리 미명시
- **화면별 AC 누락** — 50개 화면인데 검수 기준 없음 → 검수 못 함
- **UAT 시나리오 사전 합의 없음** — 출시 직전 "이거도 됐어야 하는데"
- **통과·실패만** — 조건부 통과 없음 → 일정 유연성 손실
- **법무 검토 누락** — 결제 조항에 영향 → 분쟁 시 패배
- **검수 결과 기록 없음** — 누가·언제·통과인지 추적 불가
- **CR 시 갱신 안 함** — 변경 후 기존 기준 그대로 → 정합성 깨짐
- **포트폴리오 자산화 누락** — 다음 수주에서 처음부터
