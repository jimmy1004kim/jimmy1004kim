## 이 문서는

외주 프로젝트에서 **계약 범위·일정·비용 변경을 합의·실행하는 공식 절차**를 정리한 문서.

공통 변경 관리(C-07)와 T2 Change Order의 차이:

|구분|공통 변경 관리 (C)|T2 Change Order (본 문서)|
|---|---|---|
|청중|내부 팀|**양 당사자 (고객 + 우리)**|
|효력|작업 변경 합의|**계약 변경 (법적 효력)**|
|영향|작업 일정|**계약 금액·기간·산출물**|
|처리|회의록·이슈|**부속 SoW (v1.1, v2.0)**|
|변경 단위|작업 1건|**CR 1건 = 계약 부속 문서**|

**핵심**: Change Order는 **계약 변경의 공식 절차**. 모든 외주 프로젝트에서 가장 자주 분쟁 발생하는 영역. 절차가 명확해야 양 당사자 보호.

### 왜 Change Order가 필요한가

외주 프로젝트의 80%에서 변경이 발생한다:

- 고객 요구 추가·변경 ("이거도 해주세요")
- 외부 의존성 변화 (API 변경, 일정 지연)
- 기술적 발견 (예상보다 복잡함)
- 시장·법규 변화 (출시 직전 법 개정)

**Change Order 없으면**:

- 무료 추가 작업 → 우리 손해
- "이거 합의했는데?" → 분쟁
- 일정 지연·예산 초과 → 책임 모호
- 검수·결제 단계에서 폭발

### Change Order의 3가지 효력

1. **계약 변경의 법적 근거** — 계약 본문 안 건드리고 SoW 부속으로 갱신
2. **추가 청구의 근거** — 무상 흡수 vs 추가 견적 기준 명확화
3. **일정 보호의 근거** — "이 변경으로 일정 +___일 지연" 양 당사자 합의

### Change Order의 4가지 유형

|유형|의미|처리|
|---|---|---|
|**추가 (Add)**|신규 기능·산출물 추가|추가 견적 + 일정 영향 평가|
|**변경 (Modify)**|기존 항목 변경|영향 평가 → 무상 흡수 또는 추가 견적|
|**삭제 (Remove)**|범위에서 제외|환불·정산 또는 다른 항목으로 대체|
|**일정 (Reschedule)**|일정만 조정 (범위 변경 X)|영향 평가 + 합의|

## 언제 사용하나

- 고객·우리 측에서 변경 요청 발생 시 (작업 범위·일정·비용에 영향)
- SoW에 명시된 범위 외 요청 시
- 일정·예산에 영향 큰 발견·이슈 시
- 외부 의존성 변화 시

**기준**: "SoW 범위·견적서 항목에 영향이 있는 모든 변경".

## Change Order vs 무상 흡수

|변경 규모|처리|
|---|---|
|**소규모** (텍스트·UI 미세 변경, 1~2일 작업)|무상 흡수 (월 1~2건 한도)|
|**중규모** (3~10일 작업)|Change Order + 추가 견적|
|**대규모** (10일 초과·기능 추가·아키텍처 변경)|Change Order + 추가 견적 + 일정 재조정|

이 기준은 계약·SoW에 사전 명시 (T2-3 참조).

## 어떤 툴로

|툴|추천도|이유|
|---|---|---|
|**노션 DB (CR 추적)**|⭐ 강력 추천|CR 1건 = 1행. 진행 상태·영향 평가·결정 추적|
|**Word + PDF (CR 정식 문서)**|⭐ 추천|양 당사자 서명용|
|전자 계약 (DocuSign 등)|추천|서명 자동화|
|Jira|보조|작업 영향 추적|

**최적**: 노션 (CR 관리) + Word·PDF (정식 문서·서명).

## Change Order 표준 구성

```
1. CR 메타 (CR 번호·일자·요청자)
2. 변경 내용 (무엇을 어떻게)
3. 변경 배경·사유
4. 영향 평가
   4.1 산출물·범위 영향
   4.2 일정 영향
   4.3 비용 영향
   4.4 리스크 영향
5. 변경 옵션 (대안 2~3개)
6. 합의 결정
7. 부속 SoW 발효 (v1.1·v2.0 등)
8. 양 당사자 서명
```

## 들어가야 할 것

- CR 번호·요청 일자·요청자
- 변경 내용·배경
- 영향 평가 (4가지: 산출물·일정·비용·리스크)
- 대안 옵션 (해당 시)
- 결정 결과 (승인·거절·연기)
- 부속 SoW 발효 효력
- 양 당사자 서명

## Change Order 작업 절차 (5단계)

```
1. 요청 (Request)
   ↓ 양식 작성
2. 영향 평가 (Impact Analysis)
   ↓ 5영업일 이내
3. 견적·옵션 제시 (Quote)
   ↓ 무상 흡수 또는 추가 견적
4. 합의 (Approval)
   ↓ 양 당사자 의사결정자 서명
5. 부속 SoW 발효 (Activation)
   ↓ 작업 착수
```

각 단계는 명확한 SLA(기한)과 책임이 있다.

# 🔲 양식 1 — Change Order 절차

## Step 1. 변경 요청 (Request)

### 요청 주체

- **갑 (고객)**: 추가 요구·변경 요청
- **을 (수주)**: 발견된 이슈·기술적 변경 제안·일정 영향 보고

### 요청 양식

- CR 양식 작성 (양식 2 참조)
- 이메일 또는 노션 페이지로 공식 등록

### SLA

- 요청 후 24시간 이내 접수 통보

---

## Step 2. 영향 평가 (Impact Analysis)

### 평가 주체

- **을 (수주)**: 영향 평가 책임. PM이 진행

### 평가 항목 (4가지)

|항목|평가 내용|
|---|---|
|**산출물·범위 영향**|추가·변경·삭제될 산출물 명시 (D-XXX, F-XXX, P-XXX)|
|**일정 영향**|마일스톤·전체 일정 영향 (±___일)|
|**비용 영향**|추가 작업 인일·견적 (___원)|
|**리스크 영향**|새로 발생·증가될 리스크 (R-XXX)|

### SLA

- **요청 접수 후 5영업일 이내** 영향 평가 완료

---

## Step 3. 견적·옵션 제시 (Quote)

### 견적 처리

|변경 규모|처리|
|---|---|
|**소규모** (1~2일 작업)|무상 흡수 가능 여부 확인 → 흡수 또는 추가 견적|
|**중규모** (3~10일)|추가 견적|
|**대규모** (10일 초과·아키텍처 변경)|추가 견적 + 일정 재조정|

### 옵션 제시

가능한 경우 **2~3개 옵션** 제시:

- 옵션 1: 그대로 진행 (비용·일정 모두 증가)
- 옵션 2: 다른 항목 축소 (대안 trade-off)
- 옵션 3: v1.1·v2 패치로 연기 (출시일 보호)

### SLA

- 영향 평가 완료 후 2영업일 이내 견적·옵션 제시

---

## Step 4. 합의 (Approval)

### 합의 절차

|Step|활동|주체|
|---|---|---|
|1|CR 의사결정 회의 (필요 시)|양 당사자 의사결정자|
|2|견적·일정·옵션 합의|양 당사자|
|3|결정 결과 명시|우리 측 PM 작성|
|4|양 당사자 서명|의사결정자|

### 결정 결과 3가지

- 🟢 **승인 (Approved)**: 작업 진행, 부속 SoW 발효
- 🔴 **거절 (Rejected)**: 작업 진행 안 함, CR 종결
- 🟡 **연기 (Deferred)**: 추후 재논의 (보통 v1.1·v2 단계로 이연)

### SLA

- 견적 제시 후 5영업일 이내 합의 (의사결정 지연 시 작업 일정 영향)

---

## Step 5. 부속 SoW 발효 (Activation)

### 부속 SoW 작성

승인된 CR은 **부속 SoW 형태**로 정리:

- 기존 SoW v1.0 → CR 반영하여 **v1.1, v1.2, v2.0** 등
- 변경된 산출물·일정·비용 모두 명시
- 양 당사자 서명

### 후속 처리

- 작업 착수 (수주 측)
- 추가 견적 청구 (해당 시)
- 일정·산출물 인덱스 갱신 (납품 산출물 리스트·검수 기준서·기능 리스트 등)
- 회의록·CR 추적 갱신

# 📌 예시 — CR-008 인기 검색어 추가 (StyleHaus 자사몰)

> 가상 사례. T2-7 회의록 예시 2번에서 발생한 CR을 정식 문서화

## CR 메타

|항목|내용|
|---|---|
|CR 번호|CR-008|
|요청 일자|2026-11-10|
|요청자|김상무 (StyleHaus 사업개발팀장)|
|분류|**추가 (Add)**|
|우선순위|🟠 High|
|상태|🟢 Approved (2026-11-15 합의)|
|영향 평가 완료일|2026-11-15|
|합의 일자|2026-11-15 (M2 검수 회의 시)|
|부속 SoW 버전|**v1.1**|

## 1. 변경 내용

### 요청 내용

StyleHaus 자사몰의 **메인 페이지와 검색 페이지에 "인기 검색어" 기능 추가**.

**구체적 요구**:

- 메인 페이지 헤더 검색창 클릭 시: 최근 인기 검색어 10개 표시
- 검색 결과 페이지: "이 검색어와 비슷한 다른 사람들이 검색한 키워드" 5개 표시
- 인기 검색어 계산 로직: 최근 24시간 검색량 Top 10 (관리자가 수동 조정 가능)
- 검색어 클릭 시 해당 검색 결과 페이지로 이동

### 배경·사유

- (김상무) **출시 직후 마케팅 임팩트** 강화 필요. 인기 검색어가 있으면 사용자 검색 행동 유도 + 트렌드 노출 효과
- 마케팅 캠페인과 연계 (예: 신규 라인 키워드 인기 검색어 노출)
- 기존 검색 기능(F-012)은 키워드 검색만. 추천·트렌드 기능 없음

### 기대 효과

- 검색 → 클릭 전환율 향상 (예상 +15%)
- 신규 라인·기획전 마케팅 효과 증대
- 사용자 체류 시간·페이지뷰 증가

## 2. 영향 평가 (BuildCo 작성, 2026-11-15)

### 2.1 산출물·범위 영향

|영향 항목|변경 내용|
|---|---|
|**추가 산출물**|DEV-016 인기 검색어 시스템 (코드)|
|신규 기능 ID|**F-070 → F-071 인기 검색어** (신규 부여)|
|영향 기능|F-012 (상품 검색·키워드), F-013 (상품 필터·정렬)|
|영향 화면|**P-001 (홈), P-102 (검색 결과)** 두 화면 — 시안·정의서 갱신|
|추가 화면|없음 (기존 화면 내 영역 추가)|
|영향 정책|POL-014 (인기 검색어 산정·관리 정책) 신규|
|영향 데이터|search_logs 테이블 인덱스·집계 추가|
|영향 API|GET /api/search/popular (신규), GET /api/search/related (신규)|

### 2.2 일정 영향

|항목|영향|
|---|---|
|영향 받는 마일스톤|**M3 (개발 완료)**|
|일정 영향|**+5~7일** (백엔드 4일 + 프론트엔드 2일 + QA 1일)|
|M3 일정 조정|2026-12-31 → **2027-01-07** (1주 지연)|
|M4 일정 조정|2027-01-20 → 2027-01-27 (M4 일정도 1주 조정)|

## 작성 팁

- **CR 절차를 사전 합의** — 계약·SoW에 절차·SLA·비용 기준 명시. 매번 협상 X
- **모든 변경은 CR로 기록** — 작은 변경도 누적되면 큰 변경. 무상 흡수도 CR-XXX 부여
- **요청 양식 표준화** — 노션 페이지·이메일 양식. 요청자가 작성 쉽게
- **영향 평가 5영업일 SLA 사수** — 지연되면 작업 일정 영향. PM의 책임
- **4가지 영향 평가** — 산출물·일정·비용·리스크. 하나도 빠뜨리지 말 것
- **옵션 제시 (대안)** — "이거밖에 없어요" ❌. 옵션 2~3개 제시하면 의사결정자도 협조적
- **출시일 보호 옵션 반드시** — 출시일 사수가 최우선. v1.1 연기 옵션 항상 포함
- **무상 흡수 한도 사전 명시** — 월 1~2건. 그 이상은 추가 견적. 모호하면 협상 무한
- **부속 SoW로 갱신** — 본 계약 안 건드리고 SoW v1.1, v1.2 등으로
- **산출물 인덱스 동시 갱신** — 기능 리스트·납품 산출물 리스트·검수 기준서 등 모두 갱신
- **외부 의존 일정 변경도 CR로** — 우리 책임 아니지만 합의 기록 필수 (예: CR-005)
- **CR 추적 표 정기 갱신** — 월말·마일스톤별 누계 확인. 누적 영향 모니터링
- **법무 검토 (대규모 CR)** — 비용·기간 큰 변경은 법무 검토 권장
- **포트폴리오 자산** — 잘 관리된 CR 흐름은 포트폴리오의 큰 가산점

## 자주 하는 실수

- **CR 절차 없음** — 매번 협상 → 시간 낭비, 분쟁 자주
- **모든 변경 무상 흡수** — 누적되면 큰 손실. 무상 흡수 한도 명시 필수
- **영향 평가 늦음** — 5영업일 SLA 사수 안 함 → 작업 일정 영향
- **옵션 1개만 제시** — 의사결정자 압박 → "거절" 가능성 ↑
- **출시일 보호 옵션 누락** — 출시일 사수 못 함 → 사업 임팩트 손실
- **무상 흡수 한도 모호** — "작은 거니까" → 누적되면 적자
- **부속 SoW 안 쓰고 본 계약 수정** — 매번 계약서 재서명 → 행정 부담
- **산출물 인덱스 갱신 누락** — CR 발효됐는데 기능 리스트 그대로 → 검수 분쟁
- **외부 의존 일정 변경 CR 안 함** — 우리 책임 아닌데 합의 기록 없음 → 분쟁 시 입증 어려움
- **CR 추적 표 없음** — 누적 영향 모름 → 계약 금액·일정 통제 못 함
- **법무 검토 누락** — 대규모 CR도 법무 안 보고 진행 → 분쟁 시 패배
- **포트폴리오 자산화 누락** — CR 처리 노하우 다음 수주에서 처음부터
