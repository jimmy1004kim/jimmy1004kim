## 이 문서는

외주 구축 프로젝트에서 **각 화면의 구조·요소·동작·검수 기준을 정리한 합의 문서**.

T1 화면 정의서와 다른 점은 **고객 합의·검수·소유권 이전이 핵심**이라는 것.

### T1 화면 정의서 vs T2 화면 정의서

| 구분     | T1 (신규 서비스)  | T2 (외주 구축)        |
| ------ | ------------ | ----------------- |
| 주된 청중  | 내부 개발·디자인·QA | **고객 + 내부**       |
| 효력     | 설계 기준        | **계약·검수 기준**      |
| 변경 절차  | PRD CR       | **Change Order**  |
| 디자인 합의 | 내부 자율        | **고객 시안 합의 필수**   |
| 검수 기준  | QA 시나리오      | **화면별 검수 기준 명시**  |
| 소유권    | 자체 보유        | **계약 종료 시 고객 이전** |

**핵심**: T2 화면 정의서는 **계약 산출물 + 검수 기준 + 소유권 이전 대상**. T1보다 더 엄격하고 정형화된 합의 문서.

### 외주 화면 정의서의 4가지 책임

1. **고객과의 합의** — 화면당 시안·정의·동작 모두 고객 서명 합의
2. **검수의 객관적 기준** — 화면이 정의 대로 작동하는지가 검수 통과 기준
3. **개발의 입력** — 개발자가 추측 없이 만들 수 있는 수준
4. **소유권 이전 대상** — 계약 종료 시 고객에 이전되는 산출물

## 언제 만드나

- 요구사항 정의서·기능 리스트 합의 후
- Phase 2 (기획·설계) 단계
- 화면당 디자인 시안 도착 후 통합
- Change Order 발생 시 (관련 화면 갱신)

**기준**: 요구사항·기능 리스트 합의 후, 개발 착수 직전.


## 작성 절차

1. **기능 리스트 기반 화면 도출** — 1 기능 → 1~N 화면 매핑

8. **이해관계자 리뷰** — 개발·디자인·QA·고객
9. **양 당사자 승인** — 정식 발효
10. **변경은 CR로** — 새 시안·요소 변경 시 v1.1, v1.2

## 9. 검수 기준 (Acceptance Criteria) ⭐

P-110 화면 검수는 다음 모두 통과 시 완료:

### 9.1 기능 검수

- [ ] **AC-1**. 상품 데이터 (이름·브랜드·가격·이미지) 정상 표시
- [ ] **AC-2**. 컬러·사이즈 옵션 정상 선택 가능
- [ ] **AC-3**. 컬러 선택 시 메인 이미지 자동 교체
- [ ] **AC-4**. 사이즈 선택 시 재고 표시 자동 갱신
- [ ] **AC-5**. 매장 선택 변경 시 재고 표시 자동 갱신
- [ ] **AC-6**. 매장별 재고가 POS와 1분 이내 동기화 (정합성 99.5%+)
- [ ] **AC-7**. 위시리스트 토글 정상 작동 (비회원 → 로그인 유도)
- [ ] **AC-8**. 장바구니 담기 시 사이즈·컬러 미선택 검증 후 진행
- [ ] **AC-9**. 바로 구매 시 결제 페이지로 정상 이동
- [ ] **AC-10**. 리뷰 5개씩 표시 + 더보기로 추가 로드
- [ ] **AC-11**. 관련 상품 4개 표시, 클릭 시 해당 P-110 이동

### 9.2 UI·UX 검수

- [ ] **AC-12**. 디자인 시안 v1.0 (Figma) 과 100% 일치
- [ ] **AC-13**. PC (1280px+), Tablet (768~1279px), Mobile (~767px) 반응형 정상
- [ ] **AC-14**. Mobile 하단 고정 CTA (장바구니·바로 구매) 정상 작동
- [ ] **AC-15**. 모든 요소가 디자인 시스템 (color·typography·spacing) 표준 준수

### 9.3 비기능 검수

- [ ] **AC-16**. 페이지 로딩 3초 이내 (P95 기준, NFR-001)
- [ ] **AC-17**. 매장 재고 API 응답 1초 이내 (NFR-002)
- [ ] **AC-18**. Chrome·Safari·Edge·Firefox 최신 2버전 정상 작동
- [ ] **AC-19**. 접근성 WCAG AA 통과 (alt 텍스트·키보드 네비·스크린리더)

### 9.4 분기·예외 검수

- [ ] **AC-20**. 로딩 시 스켈레톤 UI 정상 표시
- [ ] **AC-21**. 상품 없음 (404)·전체 품절·특정 사이즈 품절 모두 정상 처리
- [ ] **AC-22**. POS 연동 실패 시 fallback 처리 (전체 재고만 표시)
- [ ] **AC-23**. 에러 발생 시 사용자 친화적 메시지 + 재시도

### 9.5 데이터 검수

- [ ] **AC-24**. 가격·할인율·재고 수치 정확 (관리자 시스템과 일치)
- [ ] **AC-25**. 최근 본 상품에 정상 기록 (localStorage)

## 작성 팁

- **디자인 시안 합의가 가장 중요** — Phase 2 첫 2주에 절대 사수. 늦으면 전 일정 흔들림
- **시안 합의 기록 명문화** — 합의 일자·서명자·범위 명시. "이거 합의 안 한 건데" 분쟁 방지
- **검수 기준을 화면별로** — 각 화면이 "완성됐다"를 객관적으로 판단할 기준. 모호하면 검수 무한 반복
- **검수 기준 AC-XX 번호 부여** — 추적 가능. 검수 시 체크리스트로 활용
- **시안·정의 양쪽 모두 보관** — Figma 종속 회피. PDF·이미지로도 백업 (계약 종료 시 소유권 이전)
- **반응형 명시** — PC·Tablet·Mobile 모두 검수. Mobile 누락 흔함
- **분기·예외 시나리오 빠뜨리지 말 것** — 로딩·빈 상태·에러·권한 없음·만료 → QA 케이스로 직결
- **외부 의존 요소 표시** — POS·PG·외부 API 등 연동 요소는 fallback 명시
- **소규모 변경 룰 합의** — 월 2건 무상 흡수 등. 명시 안 하면 매번 분쟁
- **시안 변경은 CR로** — 시안 합의 후 변경은 Change Order. 비용·일정 영향 평가
- **소유권 이전 대상 명시** — 계약 종료 시 화면 정의서·Figma 파일 이전. 시안 종속성 사전 해소
- **데이터 ↔ 화면 매핑** — API·DB·정책과 어떻게 연결되는지. 개발자가 추측 X
- **포트폴리오 자산** — 유사 도메인(자사몰·관리자) 다음 수주에서 60~70% 재사용

## 자주 하는 실수

- **디자인 시안 합의 미루기** — Phase 2 첫 2주 사수 못함 → 전 일정 흔들림
- **시안 합의 기록 없음** — 합의 일자·서명자 없음 → "이거 합의 안 했어요" 분쟁
- **검수 기준 모호** — "디자인대로 작동" → 객관적 판단 불가 → 검수 무한 반복
- **반응형 누락** — PC만 정의 → Mobile 검수 단계 발견 → 일정 폭증
- **분기·예외 누락** — 정상 흐름만 정의 → 출시 후 사용자가 발견
- **외부 의존 fallback 없음** — POS·PG 장애 시 처리 안 함 → 출시 후 장애
- **시안 변경 CR 안 함** — 시안 합의 후 임의 변경 → 비용 손실
- **소유권 이전 누락** — 계약 종료 시 시안 파일 이전 안 함 → 분쟁
- **데이터·API 매핑 누락** — 개발자가 추측 → 잘못 구현
- **소규모 변경 룰 없음** — 텍스트 1글자 변경에도 협상 → 시간 낭비
- **포트폴리오 자산화 누락** — 같은 화면 다음 수주에서 처음부터 작성
- **Figma 종속** — Figma만 있고 백업 없음 → 계약 종료 후 시안 손실 위험
