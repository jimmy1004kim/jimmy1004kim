## 정의

외부 고객사가 의뢰한 서비스·시스템을 정해진 범위·일정·비용 안에서 만들어 납품하는 일. 
계약이 존재하고, 결과물이 명확하게 정의되어 있는 프로젝트.

신규 서비스 개발과 결정적으로 다른 점은 **"의사결정의 최종 권한이 고객에게 있다"** 는 것. 
기획자는 만드는 사람이 아니라, 고객 요구를 정확히 받아내서 만들 수 있게 풀어주는 사람에 가깝다.

## 발생 상황

- 기업 홈페이지·랜딩페이지 제작 의뢰
- 자사몰·쇼핑몰 구축
- 사내 관리자 시스템 개발 의뢰
- 노후 시스템 리뉴얼·재구축
- B2B 솔루션 커스터마이징 구축

## 업무 흐름

```
영업·문의 → 제안 → 계약 → 요구사항 정의 → 기획·설계 → 개발 → QA → 검수·납품 → (선택) 유지보수
```

|단계|핵심 작업|
|---|---|
|영업·문의|고객 니즈 사전 파악, 적합성 판단|
|제안|기능 윤곽·견적·일정 제시 (유형 5와 결합)|
|계약|범위·일정·비용·산출물·검수 기준 확정|
|요구사항 정의|고객 요구를 기능 단위로 구조화·명확화|
|기획·설계|IA·화면·정책·데이터 명세화|
|개발|변경 관리하며 진행|
|QA|요구사항 기준 검증|
|검수·납품|검수 기준 충족 확인, 산출물 인계|
|유지보수|계약에 따라 일정 기간 대응|

## 기획자 역할

- **요구사항 분석·구조화** — 고객의 모호한 말을 기능 단위로 풀어내는 일. 가장 중요한 능력
- **범위 정의 (Scope Definition)** — 무엇이 들어가고 무엇이 안 들어가는지 명확히 선 긋기. 모호하면 나중에 분쟁
- **제안 단계 지원** — 영업이 가져온 건에 대해 기능·일정·견적 산정 도움
- **고객 커뮤니케이션 주도** — 정기 미팅, 진행 보고, 변경 협의의 주체
- **변경 관리** — 진행 중 들어오는 추가 요청이 범위 변경인지 확인하고 견적·일정 조정 협의
- **상세 설계** — IA, User Flow, 기능·화면·정책·데이터·예외 처리
- **개발 협업·일정 관리** — 내부 개발팀과 일정·산출물·이슈 관리
- **검수 대응** — 고객 검수에 대비한 자체 점검 → 실제 검수 진행 → 보완

## 주요 산출물 (✅ = 필수)

### 제안·계약

- ✅ 제안서 — 서비스 개요·기능 범위·일정·견적
- ✅ 견적서
- ✅ 계약서 / SoW (작업 명세서)
- ⬜ 범위 정의서 — 포함·제외 사항 명확화 (계약 부속)

### 요구사항·기획

- ✅ 요구사항 정의서 (Requirement Spec) — 가장 중요한 단일 문서
- ✅ 기능 리스트 (Feature List)
- ✅ IA (사이트맵)
- ✅ User Flow
- ⬜ 페르소나·시나리오 (B2C 사이트면 필요)

### 상세 설계

- ✅ 기능 정의서 (Feature Spec)
- ✅ 화면 정의서 (Screen Spec)
- ✅ 정책 정의서 (Business Rule)
- ⬜ 데이터 정의서 (Data Spec)
- ⬜ API / 외부 연동 정의서
- ⬜ 권한 정의 (Role & Permission)

### 실행·관리

- ✅ 일정 계획 / WBS
- ✅ 회의록 / 커뮤니케이션 로그
- ✅ 변경 관리 대장 (Change Request / Change Log)
- ⬜ 이슈 관리 대장
- ⬜ 리스크 관리 대장

### 검증·납품

- ✅ QA 체크리스트 / 테스트 시나리오
- ✅ 검수 기준서
- ✅ 납품 산출물 리스트
- ⬜ 인계 확인서 / 검수 확인서
- ⬜ 운영 매뉴얼 (납품 범위에 따라)

## 특징

- **계약이 모든 것을 지배한다** — 범위·일정·비용이 문서로 묶여 있음
- **고객 커뮤니케이션 비중이 압도적** — 만드는 시간보다 협의·조율 시간이 길 때도 많음
- **변경 요청 관리가 수익을 좌우** — 범위 변경에 대응 못 하면 적자 프로젝트
- **종료 시점이 명확하다** — 납품하면 끝 (유지보수는 별도)
- **운영보다 납품이 목표** — 출시 후 개선보다 검수 통과가 목적

## 자주 빠지는 함정

- 요구사항 정의가 모호한 채로 개발 진입 → 막판에 "이게 아닌데"
- 검수 기준이 계약에 없어서 검수 단계에서 무한 보완 요청
- Scope Creep — 한두 개씩 늘어난 요청을 거절 못 해서 적자
- 일정 지연 패널티만 있고 검수 지연 패널티는 없는 계약 → 고객 검수가 늦어도 우리만 손해
- 산출물 인계 책임이 모호해서 끝나고도 계속 호출됨
