## 이 문서는

외주 프로젝트에서 **고객과의 모든 커뮤니케이션 원칙·채널·상황별 대응**을 정리한 워크플로우.

다른 워크플로우와의 관계:

| 워크플로우                           | 역할                      |
| ------------------------------- | ----------------------- |
| **T2-12. 외주 프로젝트 표준 절차**        | 전체 라이프사이클의 큰 흐름         |
| **T2-13. 고객 커뮤니케이션 가이드 (본 문서)** | 전 Phase에서 매일 적용되는 소통 원칙 |
| **T2-14. 검수 진행 절차**             | 검수 시점의 세부               |
| **T2-7. 회의록**                   | 정식 협의의 기록 산출물           |

**핵심**: T2-12가 "무엇을 만드는가" 라면, 본 문서는 **"어떻게 소통하는가"**. 외주 프로젝트 성패의 50%가 커뮤니케이션에 달려있다.

### 외주 커뮤니케이션의 5가지 함정

|함정|증상|대응|
|---|---|---|
|**구두 합의 의존**|"이거 김 부장님이 OK 하셨는데" → 분쟁|모든 합의 서면화|
|**응답 지연**|우리 응답 늦으면 → 고객 불안 ↑|SLA (4시간·24시간) 사수|
|**악소식 늦게 전달**|일정 지연을 D-3에 통보 → 폭발|조기 경보·정직한 보고|
|**채널 혼란**|Slack·이메일·메신저·전화 혼용 → 추적 불가|채널별 용도 합의|
|**이해관계자 우회**|실무자만 만나고 의사결정자 미접촉 → 막판 거절|핵심 이해관계자 정기 접촉|

이 가이드는 위 5가지를 모두 막는 장치.

### 외주 커뮤니케이션의 3가지 책임

1. **신뢰 구축** — 일관성·투명성·예측 가능성
2. **위험 조기 식별** — 작은 신호를 놓치지 않기
3. **합의의 영구 기록** — 분쟁 시 결정적 증거

## 언제 사용하나

- 외주 프로젝트 전 Phase (계약 직후 ~ 하자 보수 종료)
- 신규 PM·기획자 온보딩 시
- 분쟁·갈등 발생 시 (절차 점검)
- 회고 시점 (소통 평가)

# 🔲 양식 1 — 커뮤니케이션 5대 원칙

## 원칙 1. 투명성 (Transparency)

**모든 정보를 숨기지 않고 공유한다**

- 진행률·이슈·블로커를 그대로 보고
- 늦어지면 늦어진다고 말함 (숨기지 않음)
- 우리 실수도 솔직히 공개
- 단, 비공개 정보 (다른 고객·내부 인사·재무)는 마스킹

**왜**: 신뢰의 기반. 숨기다 들키면 회복 불가.

## 원칙 2. 일관성 (Consistency)

**약속한 채널·시간·형식을 유지한다**

- 주간 회의 일정 사수 (특별 사유 외 변경 X)
- 응답 SLA 사수 (4시간·24시간)
- 보고 형식 통일 (포맷·시각·길이)
- PM 1명이 단일 채널 (다중 창구 혼란 방지)

**왜**: 예측 가능성. 고객이 "언제·어디서·어떻게" 알 수 있어야 안심.

## 원칙 3. 정직성 (Honesty)

**좋은 소식만이 아니라 나쁜 소식도 빠르고 정직하게**

- 일정 지연 가능성 발견 즉시 통보 (대응책 함께)
- "곧 됩니다" → 안 됨 → 신뢰 손상
- "이번 주 안 됩니다, 다음 주까지" + 대응 옵션 → 협력 가능
- 실수·미흡 인정 + 개선 약속

**왜**: 정직한 악소식 > 위장된 호소식. 외주 분쟁 1위는 "왜 미리 안 알려줬어?"

## 원칙 4. 적극성 (Proactivity)

**고객이 질문하기 전에 먼저 알린다**

- 진행률·이슈·결정 사항 정기 보고
- 외부 의존성 변화 (PG·POS·법무) 즉시 공유
- 위험 신호 조기 경보 (D-30·D-14 등)
- 의사결정자에게 사전 브리핑

**왜**: 고객이 묻기 전에 알리면 신뢰 ↑↑. 묻고 답하면 의존 ↑.

## 원칙 5. 기록 우선 (Document First)

**모든 합의는 서면으로**

- 구두 합의 → 즉시 이메일·메신저로 정리
- 회의 → 24시간 내 회의록 (T2-7)
- 변경 → CR 정식 문서 (T2-11)
- 검수 → 검수 확인서·인계 확인서 (T2-9)

**왜**: 분쟁 시 결정적 증거. "내가 그렇게 말 안 했는데" 분쟁 방지.

# 🔲 양식 2 — 채널별 용도·SLA

## 채널별 표준 용도

|채널|용도|SLA (응답 시간)|영구 기록 여부|
|---|---|---|---|
|**이메일**|공식 문서 송부·결재·계약·서명·정식 합의·외부 보고|평일 24시간 이내|✅ 영구 기록|
|**Slack·메신저**|일상 소통·빠른 질의·진행 공유·간단한 의사결정|**평일 4시간 이내**, 24h 응대 (긴급 시)|⚠️ 90일~1년 (정책 의존)|
|**노션·Confluence**|산출물·회의록·문서 공유|비실시간|✅ 영구|
|**Zoom·Meet**|정기 회의·검수·시연·UAT·이슈 협의|사전 일정|⚠️ 녹화 시만 (회의록 필수)|
|**Figma·GitHub**|디자인·코드 코멘트 협업|평일 24시간|✅ 영구|
|**전화**|긴급 상황·복잡한 협의|즉시|❌ **반드시 후속 이메일·메신저 기록**|

## 채널 사용 원칙

### "모든 공식 합의는 이메일·서명 문서로"

- Slack 합의 → 이메일로 정리·확인 받기
- 전화 합의 → 통화 후 30분 내 이메일·메신저 정리
- 회의 합의 → 24시간 내 회의록 공유·확인

### "긴급도별 채널 선택"

|긴급도|채널|예시|
|---|---|---|
|🔴 즉시 (1시간 내)|전화 + 메신저|장애·결제 오류·법적 이슈|
|🟠 4시간 내|Slack·메신저|기능 작동 이슈·일정 변경|
|🟡 24시간 내|이메일|일반 협의·산출물 검토 요청|
|🟢 주간 회의|Zoom|진행률·계획·결정|

### "1 PM = 1 단일 창구"

- 우리 측 단일 창구: **PM 1명** (백업 1명 지정)
- 고객 측 단일 창구: **사업 책임자 또는 IT 담당** (PM이 정기 만나는 사람)
- 다른 인력은 PM 경유 또는 사전 합의된 채널

**예외**: 기술 협의는 개발 리드 직접, 디자인 협의는 디자인 리드 직접. 단 PM이 cc.

   - 일정: +5일
   - 비용: 추가 견적 필요

## 다음 단계
- 11/12 (화) 주간 회의에서 옵션 1·2 의사결정 요청
- 그 전에 POS 사 측 Webhook 가능 여부 확인 진행

홍길동
```

**원칙**:

- **이슈 + 영향 + 옵션 + 의사결정 시점** 모두 한 메일에
- 옵션 2~3개 제시 (대안 trade-off)
- 추천안 명시 (PM의 판단)
- 의사결정 요청 시점 명확

## 상황 3. CR (Change Request) 요청 접수

### 즉시 응답 → 영향 평가 → 견적·옵션 → 합의

T2-11 Change Order 절차 그대로 적용.

```
[제목] CR 접수 — 인기 검색어 추가 (CR-008)

안녕하세요 김상무님,

11/10 회의에서 말씀하신 "인기 검색어" 기능 추가 요청 정식 접수했습니다.

## 처리 일정
- 영향 평가 완료: 11/15 (5영업일 이내)
- 견적·옵션 제시: 11/16
- 의사결정 요청: 11/18 (화) 주간 회의

## 평가 진행
- 산출물·기능·일정·비용·리스크 4가지 평가
- 옵션 2~3개 제시 예정

추가 정보 필요 시 언제든 연락 부탁드립니다.

홍길동
```

## 상황 4. 갈등·불만 응대

### "경청 → 인정 → 사실 확인 → 대응안" 4단계

```
[상황] 김상무님이 "디자인이 우리가 원한 게 아닌데?" 불만 제기

[Step 1. 경청] 회의 또는 통화로 충분히 듣기
- "어떤 부분이 원하셨던 것과 다른지 자세히 말씀해주실 수 있을까요?"

[Step 2. 인정] 감정 인정 (책임 시인 X)
- "그 부분이 답답하셨겠어요. 저희도 더 좋게 만들고 싶었는데..."

[Step 3. 사실 확인] 객관적 사실로
- "10/10 디자인 합의 회의에서 시안 v1.0 합의되었던 자료 다시 보내드릴까요? 그 시점에 합의된 것과 현재의 어떤 부분이 다른지 확인하면 좋겠습니다"

[Step 4. 대응안] 옵션 제시
- "만약 변경이 필요하시면 다음 옵션이 있습니다:
  옵션 1. 미세 변경 (1~2일) — 무상 흡수 가능
  옵션 2. 큰 변경 — Change Order 절차 (영향 평가)
  옵션 3. v1.1 패치로 연기 — 출시일 보호
  어느 옵션이 좋으실까요?"
```

**원칙**:

- 감정에 감정으로 반응 X
- 사실은 객관적으로 (회의록·합의 문서 인용)
- 대응안은 옵션으로 (강제 X)
- 그래도 안 풀리면 → 양 측 의사결정자 협의

## 상황 5. 외부 의존성 변화 보고

```

안녕하세요 김상무님,

토스페이먼츠로부터 심사 일정 지연 통보 받았어 공유드립니다.

## 상황
- 당초 심사 완료: 11/15 예상
- 변경: 11/22 (약 1주 지연)
- 사유: 토스 사 내부 사정 (외부 요인)

## 영향
- F-021 결제 통합 작업 시작 1주 지연

- 11/22 심사 완료 후 즉시 결제 통합 진행
- M3 일자 영향은 11/22 시점에 재평가

추가 협의 필요 시 알려주세요.

홍길동
```

**원칙**:

- 우리 책임 아니어도 **즉시 공유** (T2-11 CR로 기록 가능)
- 영향·대응안 함께
- 우리는 책임 외이지만 **노력하는 자세** 보임

# 🔲 양식 5 — 이해관계자 관리

## 이해관계자 매핑

|역할|직책·소속|영향력|관심도|접촉 빈도|
|---|---|---|---|---|
|**의사결정자**|대표·CXO|高|高|**월 1회 + 마일스톤 시**|
|**사업 책임자**|사업개발팀장|高|高|**주 1회** (정기 회의)|
|**운영 책임자**|운영팀장|中|高|**주 1회**|
|**IT 담당**|IT 매니저|中|中|격주 또는 필요 시|
|**실사용자 (대표)**|매장 직원 등|低|中|UAT·교육 시|
|**법무·보안**|외부 자문|中|低|필요 시|

## 이해관계자 별 소통 전략

### 의사결정자 (대표·CXO)

- **빈도**: 월 1회 + M2·M5 검수 시
- **형식**: 짧고 핵심 (1~2 페이지)
- **내용**: 진행률·KPI·리스크·결정 필요 사항
- **PM이 직접 사전 브리핑**

### 사업 책임자 (주 1회 정기 회의 참석자)

- **빈도**: 주 1회 + 수시
- **형식**: 회의 + 주간 보고서
- **내용**: 진행·이슈·결정·CR
- **신뢰의 핵심 인물**

### 운영 책임자

- **빈도**: 주 1회 + 운영 인계 시
- **형식**: 회의 + 노션
- **내용**: 운영 영향·재고·CS·인계
- **출시 후 핵심 인물**

### IT 담당

- **빈도**: 격주 + 인프라·계정 협의 시
- **형식**: 회의 + Slack
- **내용**: 기술·계정·인프라
- **인계 시 핵심**

### 실사용자 (UAT·교육)

- **빈도**: UAT 1~2주 + 교육 2회
- **형식**: 오프라인·Zoom
- **내용**: 사용성·피드백
- **운영팀 자립의 핵심**

### 법무·보안

- **빈도**: 필요 시 (계약·정책·법규)
- **형식**: 서면 자문
- **내용**: 약관·개인정보·보안

## "의사결정자 우회" 절대 금지

실무자만 만나고 의사결정자 미접촉 → 막판 거절 폭증. 의사결정자 **월 1회 + 마일스톤 시** 반드시 접촉.

## 구두 합의 → 즉시 서면화

```
[Slack 합의 → 이메일로 정리 예시]

**원칙**:

- 협의 후 30분~24시간 내 정리

# 🔲 양식 7 — 회고·평가

## 프로젝트 중간 회고 (Phase 종료 시)

각 Phase 종료 시 커뮤니케이션 점검:

- 약속한 SLA 사수율 (응답 시간·정기 회의)
- 고객 만족도 (간단 조사 또는 회의 시)
- 우리 측 개선 사항

## 프로젝트 최종 회고 (T2-12 Phase 6)

- 전체 커뮤니케이션 평가
- 잘된 점·아쉬운 점
- 다음 프로젝트 개선 사항
- 케이스 스터디 (포트폴리오)

## 고객 만족도 지표 (참고)

- 응답 시간 SLA 사수율
- 정기 회의 결정 사항 실행률
- 약속한 산출물 적시 납품률
- 고객 측 추가 요청 응대 만족도
- 분쟁·갈등 발생 건수
- 다음 프로젝트 의향

## 작성 팁

- **PM 1명이 단일 창구** — 다중 창구 혼란 방지. 백업 1명 지정 (휴가·병가 대비)
- **응답 SLA 사수** — 4시간·24시간 사수. 늦으면 미리 "오늘 안에 답변 드리겠습니다" 통보
- **나쁜 소식 일찍** — 늦게 알리면 폭발. 작은 신호 발견 즉시 보고
- **구두 합의 즉시 서면화** — Slack·전화·회의 합의 → 이메일로 정리
- **이메일은 핵심 + 첨부** — 본문 짧게, 첨부 풍부하게
- **회의 24h 내 회의록** — 기억 휘발 전. 양 당사자 회람·확정
- **이해관계자 매핑 사전 작성** — 누가 의사결정자·영향력·관심도. 접촉 빈도 차별화
- **의사결정자 월 1회 사전 브리핑** — 막판 거절 방지
- **외부 의존성 변화 즉시 공유** — 우리 책임 아니어도 신뢰 ↑
- **갈등은 사실로 풀기** — 감정 대 감정 X. 회의록·합의 문서 인용
- **6개월 유지보수 영업 사수** — 인계 시점이 적기. 관계 끊기지 마라
- **회고·자산화** — 커뮤니케이션 평가 → 다음 프로젝트 개선
- **포트폴리오 가치** — 좋은 커뮤니케이션 흐름은 PM의 가장 강력한 가산점

## 자주 하는 실수

- **PM이 단일 창구 아님** — 여러 사람이 다른 답변 → 혼란
- **응답 늦음** — 24시간 응답 SLA 안 지킴 → 신뢰 하락
- **나쁜 소식 늦게** — D-3에 일정 지연 통보 → 폭발
- **구두 합의만** — Slack 합의 → 이메일 정리 안 함 → "그렇게 말 안 했는데" 분쟁
- **이메일 너무 길음** — 본문 5페이지 → 안 읽음 → 핵심 누락
- **회의록 늦음** — 1주일 후 작성 → 기억 휘발·왜곡
- **이해관계자 우회** — 의사결정자 미접촉 → 막판 거절
- **외부 의존성 숨김** — 우리 책임 아니어도 알려야 → 안 알리면 우리 책임으로 오해
- **감정 대응** — 갈등 시 감정으로 응대 → 분쟁 폭증
- **6개월 유지보수 미영업** — 관계 끊기면 신규 영업 시작 → 비용·시간 ↑↑
- **회고·자산화 누락** — 같은 실수 다음 프로젝트에서 반복
- **포트폴리오 정리 안 함** — 가장 비싼 자산 손실
