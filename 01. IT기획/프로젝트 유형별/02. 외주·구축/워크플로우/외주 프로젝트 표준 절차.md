## 이 문서는

외주 구축 프로젝트를 **수주 영업부터 인계·하자 보수 종료까지** 진행하는 표준 절차.

"제안·계약부터 출시·인계, 하자 보수 종료까지 어떤 순서·게이트로 진행하는가" 정리.

T1 워크플로우와의 비교:

| 구분     | T1 (신규 서비스)         | T2 (외주 / 구축)            |
| ------ | ------------------- | ----------------------- |
| 라이프사이클 | Discovery → Operate | **Pre-Sales → Closure** |
| 시작     | 문제 정의               | **영업·수주**               |
| 종료     | 운영 전환               | **하자 보수 종료**            |
| 청중     | 자체 사업               | **양 당사자 (고객 + 우리)**     |
| 강조     | 가설 검증·MVP           | **계약 사수·검수·인계**         |

**핵심**: T2는 **계약·검수·인계의 3대 게이트**가 명확해야 함. 모호하면 잔금 지연·분쟁 폭증.

### 외주 프로젝트의 6개 Phase

```
Phase 0. Pre-Sales (영업·수주)
   ↓ Gate 1: 수주 확정 (계약 체결)
Phase 1. Discovery (요구사항)
   ↓ Gate 2: 본격 설계 진입 (M1)
Phase 2. Design (기획·설계)
   ↓ Gate 3: 개발 착수 (M2 — 중도금)
Phase 3. Build (개발)
   ↓ Gate 4: QA 진입 (M3)
Phase 4. Validate (QA·UAT)
   ↓ Gate 5: 출시 (M4)
Phase 5. Launch (출시·안정화)
   ↓ Gate 6: 인계 (M5 — 잔금)
Phase 6. Closure (하자 보수)
   ↓
프로젝트 종료
```

각 Phase에 명확한 산출물·결제 트리거·게이트 의사결정 기준.

## 각 Phase 한눈에

|Phase|기간|핵심 활동|핵심 산출물|결제|
|---|---|---|---|---|
|0. Pre-Sales|1~3개월|영업·제안·견적·계약|제안서·견적서·계약서·SoW|—|
|1. Discovery|2~4주|요구사항 수집·확정|요구사항 정의서·기능 리스트|—|

|3. Build|8~16주|개발·통합|코드·외부 연동|—|
|4. Validate|2~4주|QA·UAT·검수|QA 보고서·UAT 통과|—|
|5. Launch|1~2주|출시·안정화|운영 매뉴얼·인계 자료|—|
|6. Closure|2~4주|인계·종료|인계 확인서|**M5 잔금**|
|(6+. 하자 보수)|6개월|하자 대응|하자 보수 기록|—|

## 작성 팁

- **Gate 의사결정 엄격히** — Gate 통과 없이 다음 Phase 진입 X. "대충 됐으니" 가장 흔한 실패
- **3대 결제 트리거 (계약금·중도금·잔금) 명확화** — Gate 1·3·6과 정합. 모호하면 결제 지연
- **공통 워크플로우 활용** — 새 프로젝트 시작·종료·자산화 등 공통에서 활용
- **외부 의존성 사전 협의** — PG·인증·POS 등은 Phase 1·2에 미리 시작. 늦으면 일정 지연
- **CR 절차 가동** — T2-11 절차 매번 적용. 즉시 처리 X, 임시 합의 X
- **출시일 절대 사수** — Phase 5 출시는 사업 영향 큼. 가능한 한 정시
- **인계 1주 전 점검** — Phase 6 진입 1주 전 인계 항목 점검. 누락 발견 시점 확보
- **하자 보수 6개월 적극 운영** — 신규 영업 기회. 만족도 높이면 다음 수주 가능성 ↑
- **각 Phase 회고 + 마지막 회고** — 회고가 자산화로 이어짐
- **포트폴리오 가치** — 외주 프로젝트 1회 완주는 PM의 가장 강력한 케이스 스터디
- **Phase 비율 균형** — Discovery 4주 + Design 6주 + Build 9주 + Validate 4주 + Launch 4주 + Closure 2주 = 약 6개월. 비율 깨지면 위험
- **고객 응답 시간 사전 합의** — 1~2영업일. 명시 안 하면 우리 일정 깨짐

## 자주 하는 실수

- **Discovery 건너뛰기** — 계약 → 바로 설계 → 요구 모호 → 검수 분쟁
- **Gate 무시** — 통과 없이 다음 Phase → "대충 됐으니" 폭주
- **결제 트리거 모호** — M2·M5 통과 ≠ 결제 청구 권리 미명시 → 결제 지연
- **외부 의존성 늦음** — Phase 3·4에 PG 협의 시작 → 일정 폭증
- **CR 임시 처리** — "이거 작은데 그냥" → 누적되면 큰 손실
- **출시일 미사수** — 사업 영향 큰 출시 늦춤 → 신뢰 손상
- **인계 항목 누락** — 계정·라이선스 빠뜨림 → 출시 후 분쟁
- **하자 보수 무관심** — 신규 영업 기회 손실
- **회고·자산화 누락** — 다음 프로젝트에서 같은 실수
- **Phase 비율 불균형** — Design 짧고 Build 길면 부실 → Build 폭증
- **고객 응답 시간 가정 없이** — 우리 일정만 → 지연 책임 우리 부담
- **결제 카드·이메일 변경 누락** — 계정 이전했는데 비용 우리 청구
- **포트폴리오 정리 안 함** — 가장 비싼 자산 손실
