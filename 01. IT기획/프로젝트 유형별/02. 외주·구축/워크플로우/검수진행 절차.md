## 이 문서는

외주 프로젝트에서 **검수를 실제로 어떻게 진행할 것인가**의 표준 절차.

다른 산출물·워크플로우와의 관계:

| 산출물·워크플로우                  | 역할                          |
| -------------------------- | --------------------------- |
| **T2-8. 검수 기준서**           | 검수의 **기준** (객관적 합격 조건)      |
| **T2-9. 검수 확인서·인계 확인서**    | 검수의 **결과 기록** (서명 문서)       |
| **T2-14. 검수 진행 절차 (본 문서)** | 검수의 **실행 절차** (어떻게 진행할 것인가) |
| **T2-12. 외주 프로젝트 표준 절차**   | 전체 라이프사이클 (검수 시점 명시)        |

**핵심**: 검수 기준서 (기준) → 검수 진행 절차 (실행) → 검수 확인서 (결과). 3가지 모두 있어야 외주 검수가 작동.

### 외주 검수의 5가지 함정

|함정|증상|본 절차의 대응|
|---|---|---|
|**고객의 기준 변동**|"이거 더 좋아져야 해" → 무한 반복|검수 기준서 기반·사전 합의된 기준만|
|**검수 무응답**|검수 안 하고 끔 → 잔금 지연|검수 기한·자동 통과 룰|
|**모호한 검수**|"잘 작동" → 측정 불가|항목별 체크리스트·정량 기준|
|**검수 직전 발견 폭증**|직전에 큰 이슈 발견 → 일정 폭주|사전 점검·내부 사전 QA|
|**소급 적용**|검수 후 "이것도 안 되네" → 무한 추가|검수 후 변경은 CR로 분리|

본 절차는 위 5가지를 모두 막는 장치.

### 검수의 4가지 단위 (T2-8과 동일)

|단위|시점|본 절차 적용|
|---|---|---|
|**산출물 검수**|Phase 1·2|산출물별 절차|
|**기능·화면 검수**|Phase 3·4|개별 검수 절차|
|**마일스톤 검수**|M1·M2·M3·M4·M5|**마일스톤 검수 절차** (핵심)|
|**UAT (최종)**|Phase 4 출시 직전|**UAT 절차** (핵심)|

본 절차는 4가지 모두 포함. 특히 **마일스톤 검수 + UAT**가 핵심.

## 언제 사용하나

- 각 마일스톤 검수 시점 (M1·M2·M3·M4·M5)
- UAT 진행 시점 (Phase 4)
- 산출물 검수 시점 (Phase 1·2)
- 검수 분쟁 발생 시 (절차 점검)

## 검수의 5단계 절차

```
1. 검수 사전 준비
   ↓ 5~7영업일 전
2. 검수 환경·자료 셋업
   ↓ 3영업일 전
3. 검수 진행
   ↓ 검수 일자
4. 결과 정리·통보
   ↓ 검수 후 ___영업일
5. 보완·재검수 또는 확인서 서명
```

# 🔲 양식 1 — 마일스톤 검수 절차

## 마일스톤 검수 표준 절차

### 적용 마일스톤

- M1. 요구사항 확정
- M2. 설계 완료 ⭐ (중도금 트리거)
- M3. 개발 완료
- M4. QA·UAT 통과
- M5. 출시·인계 ⭐ (잔금 트리거)

### Step 1. 검수 사전 준비 (D-7 ~ D-3)

#### 사전 준비 활동

- [ ] **을 (수주) 측 내부 사전 점검** — 검수 기준 충족 여부 자체 확인
- [ ] 미충족 항목 사전 보완
- [ ] 검수 자료 정리 (산출물·진행 상태·이슈)
- [ ] 검수 일정·장소·참석자 사전 협의
- [ ] **갑 (고객) 측 사전 자료 공유** (검수 1주 전)

#### 사전 공유 자료 (을 → 갑)

- 검수 대상 산출물 (PDF·노션·Figma 링크)
- 검수 기준서 (해당 마일스톤 부분)
- 진행 상태 보고서
- 잔존 이슈 리스트 (있다면 사전 공개)
- 검수 회의 안건·예상 시간

#### 갑의 사전 검토 (을이 자료 공유 후)

- [ ] 자료 사전 검토 (3~5영업일)
- [ ] 사전 질의 사항 정리 → 을에게 사전 공유
- [ ] 검수 회의 참석자 확정

### Step 2. 검수 환경·자료 셋업 (D-3 ~ D-1)

- [ ] 회의 장소·Zoom 셋업
- [ ] 시연 환경 (Stage·Production) 준비
- [ ] 시연 시나리오 사전 리허설 (을 내부)
- [ ] 검수 체크리스트 인쇄·노션 페이지
- [ ] 검수 확인서 초안 (서명 부분 제외)

### Step 3. 검수 진행 (D-Day)

#### 회의 진행 (60~180분, 마일스톤별 다름)

|Step|활동|시간|
|---|---|---|
|1|인사·개요 (을 PM 발표)|10분|
|2|산출물별·기능별 발표·시연|30~120분|
|3|검수 기준 점검 (체크리스트 진행)|30~60분|
|4|Q&A·이슈 협의|20~40분|
|5|검수 결과 합의 (통과·조건부·실패)|10~20분|

#### 검수 진행 방식

- **을 PM이 진행** (산출물 발표·시연·체크리스트 안내)
- **갑이 검수 기준 확인** (체크리스트 항목별 ✓)
- **이견 발생 시 즉석 협의 또는 보류** (회의 종료 후 추가 협의)

### Step 4. 결과 정리·통보 (검수 후 ___영업일)

#### 결과 정리

검수 결과는 **3가지 중 하나**:

|결과|의미|후속|
|---|---|---|
|🟢 **통과**|모든 검수 기준 충족|**검수 확인서 즉시 서명** → 결제 트리거 (해당 시)|
|🟠 **조건부 통과**|일부 미충족 (Critical·High 아님)|보완 기한 합의 → 보완 후 자동 통과|
|🔴 **실패**|다수 미충족 또는 Critical 미충족|전면 재작업 → 일정·견적 협의|

#### 결과 통보

- 검수 회의 종료 후 **24시간 이내** 결과 정리 이메일 송부 (을 → 갑)
- 회의록 + 검수 결과 + 후속 절차 명시
- 양 측 의사결정자에게 사본 (cc.)

### Step 5. 보완·재검수 또는 확인서 서명

#### 통과 시

- 검수 확인서 (T2-9) 양 당사자 서명
- 결제 트리거 시 (M2·M5) → 청구 절차 진행
- 다음 Phase 진입

#### 조건부 통과 시

- 보완 작업 계획서 (보완 항목·기한)
- 을의 보완 작업 (보통 ___영업일 이내)
- 재검수 (보통 ___영업일 이내)
- 통과 시 → 검수 확인서 서명

#### 실패 시

- 양 당사자 의사결정자 회의 (1주 이내)
- 전면 재작업 계획·일정·견적 협의
- 큰 영향 시 → 계약 조정 (Change Order)
- 재검수 일자 합의

#### 검수 무응답 시 (갑이 검수 안 하거나 결과 통보 안 함)

- **검수 기한 (___영업일) 내 응답 없을 시 자동 검수 통과**
- 단, 을은 검수 기한 만료 ___영업일 전 갑에게 통지 의무

# 🔲 양식 2 — UAT (User Acceptance Test) 절차

## UAT는 무엇이 다른가

|구분|일반 검수|UAT|
|---|---|---|
|검수자|고객 의사결정자·핵심 이해관계자|**실사용자** (운영팀·매장 직원 등)|
|방법|발표·시연·체크리스트|**사용자가 직접 사용**|
|시간|1~3시간|**1~2주**|
|발견 이슈|정의·기능 미충족|**사용성·UX·실 운영 이슈**|
|결과|마일스톤 통과|**출시 GO·NO-GO 의사결정**|

UAT는 **출시 직전 마지막 관문**. 사용자가 실제로 쓰는지 검증.

## UAT 7단계 절차

```
1. UAT 시나리오 합의 (D-7)
2. UAT 환경·데이터 셋업 (D-3)
3. UAT 사용자 교육 (D-1)
4. UAT 진행 (1~2주)
5. 발견 이슈 분류·수정
6. UAT 재검증
7. UAT 통과 확인 + 출시 의사결정
```

### Step 1. UAT 시나리오 합의 (D-7)

#### 시나리오 정의

- **사용자 흐름 단위**: 회원가입 → 구매 → 배송, 관리자 주문 처리 등
- 보통 **8~15개 핵심 시나리오** (서비스 규모에 따라)
- 각 시나리오: **목적·전제 조건·기대 결과·검증 기준**

#### 양식

```
[시나리오 1] 회원 가입 → 첫 구매

목적: 신규 회원이 가입부터 첫 결제까지 완료
사용자: 신규 사용자 (StyleHaus 운영팀 ___님)
전제 조건: 이메일 계정, 본인 인증 가능, 결제 카드
기대 결과: 가입 → 본인 인증 → 상품 검색 → 장바구니 → 결제 완료
검증 기준:
- 각 단계 정상 작동
- 응답 시간 3초 이내
- 에러·예외 처리 정상
- 이메일·SMS 발송 정상
```

#### 합의 절차

- 을이 초안 작성 → 갑 검토 (3영업일) → 양 당사자 합의

### Step 2. UAT 환경·데이터 셋업 (D-3)

#### 환경 셋업

- **Stage 환경** 또는 **별도 UAT 환경**
- 실 사용 환경에 가깝게 (Production-like)
- 외부 의존성 (PG·POS·인증) 테스트 모드 또는 실 모드

#### 테스트 데이터

- 사용자 계정 (UAT 참여자별 + 테스트용)
- 상품·재고 데이터 (실 데이터 또는 시드 데이터)
- 결제 카드 (테스트 카드 또는 소액 실 카드)
- 매장 정보 (실제 6개 매장)

#### 셋업 검증

- 을 PM·QA가 사전 시나리오 1회 실행
- 발견 이슈 사전 수정

### Step 3. UAT 사용자 교육 (D-1)

#### 교육 내용 (30분~1시간)

- UAT 목적·기간·일정 안내
- 시나리오 설명
- 이슈 보고 방법 (양식·채널·우선순위 분류)
- 질문 응대 채널 (을 PM Slack 또는 전용 채널)

#### 사용자 준비 사항

- 계정 정보·테스트 카드·UAT URL
- 이슈 보고 양식 (간단하게)

### Step 4. UAT 진행 (1~2주)

#### 일일 운영

|활동|빈도|주체|
|---|---|---|
|사용자 시나리오 실행|매일|갑 측 사용자|
|발견 이슈 보고|발생 즉시|갑 사용자 → 을 PM|
|일일 진행 회의 (10~15분)|매일 14:00|양 측 PM|
|즉시 수정 가능 이슈 처리|발견 시|을 개발|
|일일 리포트|매일 종료 시|을 PM|

#### 이슈 분류 (UAT 기간 내)

|분류|의미|처리|
|---|---|---|
|🔴 Critical|사용자 흐름 완전 차단|**즉시 수정** (24시간 내)|
|🟠 High|기능 정상 작동 안 함|UAT 기간 내 수정|
|🟡 Medium|UX·사용성 이슈|출시 후 v1.1 또는 협의|
|🟢 Low|미세 개선|v1.1 또는 자체 처리|

### Step 5. 발견 이슈 분류·수정

#### 우선순위

- Critical·High → 즉시 수정 (UAT 기간 내)
- Medium → 양 당사자 협의 (UAT 통과 후 v1.1 또는 출시 전 수정)
- Low → 자체 판단

#### 수정 작업

- 을 측 개발팀이 수정
- 수정 후 즉시 UAT 환경에 배포
- 해당 사용자에게 재검증 요청

### Step 6. UAT 재검증

- 수정된 이슈에 대해 사용자가 재검증
- 모든 Critical·High 이슈 해결 확인
- Medium·Low 이슈는 잔존 이슈 리스트로 정리

### Step 7. UAT 통과 확인 + 출시 의사결정

#### UAT 통과 기준 (모두 충족)

- [ ] 모든 핵심 시나리오 (___개) 정상 작동
- [ ] Critical·High 이슈 0건
- [ ] 비기능 (성능·보안·접근성) NFR 충족
- [ ] 사용자 만족도 ___ 이상 (5점 만점)
- [ ] 잔존 이슈 (Medium·Low) 처리 합의

#### 출시 의사결정 회의 (D-Day, M4)

- 양 측 의사결정자 + PM 참석
- UAT 결과 발표 (을 PM)
- 잔존 이슈 처리 합의
- **GO·NO-GO 결정**
- T2-9 검수 확인서 (M4) 서명

## 작성 팁

- **을 내부 사전 점검 사수** — 검수 1주 전 자체 점검. 사전 보완해야 검수 통과율 ↑
- **사전 자료 공유 (D-7)** — 갑이 사전 검토 시간 확보. 회의에서 헛 발견 줄임
- **사전 코멘트 → 회의에서 답변** — 회의 효율 ↑
- **사전 리허설 (D-3)** — 시연 환경·시나리오 검증. 실수 줄임
- **검수 기준서 기반** — 사전 합의된 기준만. 임의 기준 추가 X
- **즉석 협의·보류 분리** — 작은 이견은 즉석, 큰 이견은 별도 협의
- **24시간 내 결과 통보** — 검수 회의 직후 결과 이메일·회의록
- **자동 통과 룰** — 갑 무응답 시 자동 통과. 사전 합의 + 만료 통지
- **UAT는 사용자 직접** — 우리 측이 대신 X. 실 사용자 검증이 핵심
- **UAT 사용자 교육 D-1** — 사전 교육 없으면 헤맴
- **일일 회의 (UAT 기간)** — 매일 14:00 10~15분. 빠른 이슈 처리
- **이슈 분류 (Critical·High·Medium·Low)** — 우선순위 명확. Medium·Low는 v1.1 분리
- **잔존 이슈 합의** — UAT 통과 시 잔존 이슈 처리 방안 명확히
- **출시 의사결정자 양 측 참석** — 양 측 GO·NO-GO 명확
- **포트폴리오 자산** — 잘 진행된 UAT는 PM의 가장 강력한 케이스 스터디

- **사전 자료 공유 안 함** — 갑이 회의 당일 처음 봄 → 효율 ↓
- **검수 기준서 기반 X** — 임의 기준 추가 → 분쟁

- **출시 의사결정자 미참석** — GO·NO-GO 결정 모호
- **회의 시간 부족** — M2 검수 1시간만 잡음 → 다 못 봄
- **시연 환경 사전 점검 X** — 검수 당일 환경 다운 → 검수 못 함
- **포트폴리오 자산화 누락** — 다음 프로젝트에서 처음부터
