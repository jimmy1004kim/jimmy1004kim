## 이 문서는

직무 전문성 노션 워크스페이스의 **전체 폴더 구조와 어디에 무엇을 넣는지** 정의하는 가이드.

명명 규칙이 "이름 어떻게 쓰는가"라면, 폴더 구조 가이드는 "어디에 넣는가" 다. 둘이 합쳐져야 자산이 정리된다.

## 전체 구조 (큰 그림)

```
📁 직무 전문성 (최상위)
│
├── 📁 공통                ← 영역 약어: C
├── 📁 유형별              ← T1 ~ T6
├── 📁 툴 / 환경           ← TE
├── 📁 커리어              ← CA
└── 📁 자료 모음           ← RES
```

각 폴더의 역할과 하위 구조는 아래에서 상세히.

---

## 📁 공통 (C)

> 유형·도구 무관, 항상 쓰는 것

### 폴더 구조

```
📁 공통
│
├── 📄 (직속 문서들)
│   ├── 기획 유형 분류
│   ├── 명명 규칙
│   └── 폴더 구조 가이드
│
├── 📁 공통 템플릿        ← 양식 + 예시
└── 📁 공통 워크플로우    ← 절차
```

### 무엇이 들어가나

|위치|들어가는 것|예시|
|---|---|---|
|직속 문서|영역 자체에 대한 메타 정보|기획 유형 분류, 명명 규칙, 폴더 구조 가이드|
|공통 템플릿|양식 (들어가야 할 항목과 예시)|Charter, RACI, WBS, 회의록, 회고, ADR 등|
|공통 워크플로우|절차 (단계와 체크리스트)|새 프로젝트 시작, 프로젝트 종료, 자산화|

### 들어가는 기준

- "유형 가리지 않고 모든 프로젝트에서 쓰는가" → YES면 공통

---

## 📁 유형별 (T1~T6)

> 각 기획 유형에 특화된 자산

### 폴더 구조

```
📁 유형별
│
├── 📁 T1. 신규 서비스 개발
│   ├── 📄 유형 정의 페이지
│   ├── 📁 템플릿       ← 이 유형 특화 산출물 양식
│   ├── 📁 워크플로우   ← 이 유형 표준 진행 절차
│   └── 📁 프로젝트들   ← 실제 진행한 프로젝트
│
├── 📁 T2. 외주 / 구축
│   └── (동일 구조)
│
├── 📁 T3. 기존 서비스 개선
│   └── (동일 구조)
│
├── 📁 T4. 내부 시스템 구축
│   └── (동일 구조)
│
├── 📁 T5. 제안 / 수주
│   └── (동일 구조)
│
└── 📁 T6. 컨설팅 / 진단
    └── (동일 구조)
```

### 무엇이 들어가나

|위치|들어가는 것|예시 (T4 기준)|
|---|---|---|
|유형 정의 페이지|유형 자체 설명|T4 = "내부 시스템 구축이란..."|
|템플릿|이 유형 산출물 양식 + 예시|AS-IS 분석서, TO-BE 설계서, ROI 분석서|
|워크플로우|이 유형 표준 진행 절차|"내부 시스템 구축 표준 절차"|
|프로젝트들|실제 진행한 프로젝트 폴더|2026-shopling-automation|

### 프로젝트 폴더 내부 구조

```
📁 2026-shopling-automation
│
├── 📄 (프로젝트 메타 페이지)   ← 최상위 페이지 = 산출물 인덱스
├── 📁 Phase 1. Discovery
│   ├── AS-IS 업무 분석서
│   ├── 요구사항 정의서
│   └── ROI 분석서
├── 📁 Phase 2. 설계
│   ├── IA
│   ├── 기능 정의서
│   └── ...
├── 📁 Phase 3. 개발
├── 📁 Phase 4. QA·도입
└── 📁 산출물 (Phase 무관)
    ├── Charter
    ├── RACI
    ├── WBS
    ├── 회의록 DB
    ├── 회고
    └── ADR DB
```

또는 Phase 구분 없이 산출물 카테고리로:

```
📁 2026-shopling-automation
│
├── 📄 (메타 페이지 = 산출물 인덱스)
├── 📁 분석·전략
├── 📁 구조·상세 설계
├── 📁 실행·관리
└── 📁 검증·전환
```

**선택 기준**: Phase 흐름이 강한 프로젝트 → Phase별 / 산출물 카테고리가 명확한 프로젝트 → 카테고리별

### 들어가는 기준

- 특정 유형에서만 쓰는가 → YES면 유형별

---

## 📁 툴 / 환경 (TE)

> 도구 의존성이 큰 자산. 그 도구를 안 쓰면 의미 없는 것들

### 폴더 구조

```
📁 툴 / 환경
│
├── 📁 노션
├── 📁 Jira
├── 📁 Figma
├── 📁 Slack
├── 📁 Confluence (선택)
├── 📁 GitHub / GitLab (선택)
└── 📁 기타 도구
    ├── Playwright
    ├── Notion AI / Claude / ChatGPT
    └── Miro / FigJam
```

### 무엇이 들어가나

|위치|들어가는 것|예시|
|---|---|---|
|노션|노션 셋업·자동화·템플릿|DB·뷰·속성 셋업 가이드|
|Jira|Jira 셋업·JQL·대시보드|이슈 유형별 템플릿, JQL 모음|
|Figma|Figma 구조·디자인 시스템|파일 구조 표준, 컴포넌트 라이브러리 관리|
|기타 도구|도구별 가이드|Playwright 자동화 가이드|

### 들어가는 기준

- 도구가 바뀌면 못 쓰는가 → YES면 툴/환경
- 도구 여러 개에서 쓰는가 → 공통 또는 유형별

---

## 📁 커리어 (CA)

> 본인의 커리어 자산

### 폴더 구조

```
📁 커리어
│
├── 📄 이력서
├── 📁 포트폴리오 사이트 (외부 공개용)
├── 📁 케이스 스터디 모음   ← 프로젝트별 정제 버전
└── 📁 학습 로그·인사이트
```

### 무엇이 들어가나

|위치|들어가는 것|
|---|---|
|이력서|최신 이력서 (v로 관리)|
|포트폴리오 사이트|외부 공개용 사이트 콘텐츠·디자인|
|케이스 스터디 모음|프로젝트 종료 후 정제된 케이스 (포트폴리오 자료)|
|학습 로그·인사이트|책·강의·아티클에서 얻은 인사이트 누적|

### 케이스 스터디 vs 프로젝트 폴더

- 프로젝트 폴더 (유형별 > 프로젝트들) = **작업 원본**. 회의록·이슈·미해결까지 다 있음
- 케이스 스터디 (커리어 > 케이스 스터디 모음) = **정제된 외부용 요약**. 정량·정성 성과·역할·학습 중심

---

## 📁 자료 모음 (RES)

> 인풋 (책, 아티클, 강의)

### 폴더 구조

```
📁 자료 모음
│
├── 📁 책 정리
├── 📁 아티클 / 블로그
├── 📁 강의 / 부트캠프 자료
├── 📁 영감받은 사례
└── 📁 도구·서비스 레퍼런스
```

### 무엇이 들어가나

|위치|들어가는 것|
|---|---|
|책 정리|책 핵심 요약 + 본인 인사이트|
|아티클 / 블로그|외부 글의 핵심 요약 + 출처 링크 (출처 페이지 사라져도 자산 보존)|
|강의 / 부트캠프 자료|강의 노트, 다운로드 자료|
|영감받은 사례|잘 만든 서비스·제품·문서 사례|
|도구·서비스 레퍼런스|"이런 게 있다" 수준의 도구·서비스 메모|

### 들어가는 기준

- 본인이 만든 게 아니라 외부에서 받은 것인가 → YES면 자료 모음

---

## 분류 의사결정 트리

새 문서를 만들 때 어디에 넣을지:

```
Q1. 본인이 만든 자산인가, 외부 자료인가?
  외부 → 자료 모음 (RES)
  본인 자산 → Q2

Q2. 본인의 커리어 정체성에 관한 것인가?
  YES → 커리어 (CA)
  NO  → Q3

Q3. 특정 도구·환경에서만 쓰는가?
  YES → 툴 / 환경 (TE)
  NO  → Q4

Q4. 특정 기획 유형에서만 쓰는가?
  YES → 유형별 (T1~T6)
  NO  → 공통 (C)
```

## 분류 애매할 때 룰

|상황|처리|
|---|---|
|공통 vs 유형별|일단 공통 → 1년 후 다른 유형에서 안 쓰면 유형별로 이동|
|공통 vs 툴·환경|도구 의존성이 큰가가 기준 (도구 바뀌면 못 쓰는 건 툴)|
|프로젝트 폴더 vs 자산|프로젝트 종료 시 자산화 워크플로우로 자산 폴더로 이동|
|두 영역에 모두 속할 때|메인 위치 1개 + 다른 위치엔 링크|

## 폴더 구조 점검 체크

새 폴더 만들 때:

- [ ] 위 5개 영역 중 어디에 속하는가 (강제로 1개 선택)
- [ ] 명명 규칙에 맞는가
- [ ] 기존 폴더와 중복되지 않는가
- [ ] 1년 후에도 이 위치가 적절한가

# 🔄 기존 문서에 두 규칙 적용하기

## 적용해야 할 것 (정리)

지금까지 만든 자산을 명명 규칙·폴더 구조 가이드에 맞춰 정렬:

### 1. 명명 규칙 적용 — 페이지 제목 변경

지금까지 만든 페이지 제목들이 일관되지 않을 수 있어요. 다음 형식으로 통일:

**공통 템플릿 (14개)** — 형식: `[문서 종류] 템플릿`

- 프로젝트 개요서 (Charter) 템플릿
- 이해관계자 분석 (RACI) 템플릿
- WBS / 일정 계획 템플릿
- 회의록 템플릿
- 이슈 관리 대장 템플릿
- 리스크 관리 대장 (RAID) 템플릿
- 변경 관리 대장 템플릿
- 회고 (Retrospective) 템플릿
- 사후 분석 (Post-mortem) 템플릿
- 킥오프 자료 템플릿
- 의사결정 기록 (ADR) 템플릿
- 산출물 인덱스 / 진행 현황판 템플릿
- 인터뷰 가이드 템플릿
- 보고서 양식 템플릿

**공통 워크플로우 (3개)** — 형식: `[워크플로우 이름] 워크플로우`

- 새 프로젝트 시작 워크플로우
- 프로젝트 종료 워크플로우
- 자산화 워크플로우

**유형별 정의 페이지 (6개)** — 형식: `T[번호]. [유형 이름]` (또는 현재 그대로)

- T1. 신규 서비스 개발
- T2. 외주 / 구축
- T3. 기존 서비스 개선
- T4. 내부 시스템 구축
- T5. 제안 / 수주
- T6. 컨설팅 / 진단

**공통 직속 (3개)**

- 기획 유형 분류
- 명명 규칙
- 폴더 구조 가이드

### 2. 폴더 구조 적용 — 페이지 위치 확인

각 페이지가 올바른 폴더에 있는지 확인:

```
📁 직무 전문성
│
├── 📁 공통
│   ├── 📄 기획 유형 분류         ✅
│   ├── 📄 명명 규칙              ⭐ 신규
│   ├── 📄 폴더 구조 가이드        ⭐ 신규
│   ├── 📁 공통 템플릿            (14개 페이지)
│   └── 📁 공통 워크플로우         (3개 페이지)
│
├── 📁 유형별
│   ├── 📁 T1. 신규 서비스 개발
│   │   ├── 📄 (유형 정의)
│   │   ├── 📁 템플릿              (아직 비어 있음)
│   │   ├── 📁 워크플로우          (아직 비어 있음)
│   │   └── 📁 프로젝트들           (아직 비어 있음)
│   ├── 📁 T2. 외주 / 구축        (동일 구조)
│   ├── 📁 T3. 기존 서비스 개선   (동일 구조)
│   ├── 📁 T4. 내부 시스템 구축   (동일 구조)
│   ├── 📁 T5. 제안 / 수주        (동일 구조)
│   └── 📁 T6. 컨설팅 / 진단      (동일 구조)
│
├── 📁 툴 / 환경                   (아직 비어 있음)
├── 📁 커리어                      (아직 비어 있음)
└── 📁 자료 모음                   (아직 비어 있음)
```

### 3. 상태 태그 부여

모든 완료 문서에 🟢 확정 v1.0 표시.

### 4. 약어 사전 갱신

새 프로젝트·새 약어 만날 때마다 명명 규칙의 약어 사전에 추가.

## 적용 실행 체크리스트

노션에서 한 번에 수행할 작업:

- [ ] 공통 폴더에 명명 규칙·폴더 구조 가이드 페이지 추가
- [ ] 공통 템플릿 14개 제목을 위 형식대로 일관화
- [ ] 공통 워크플로우 3개 제목 일관화
- [ ] 모든 완료 페이지에 🟢 확정 v1.0 태그 부여
- [ ] 유형별 폴더 내부에 `📁 템플릿`, `📁 워크플로우`, `📁 프로젝트들` 하위 폴더 생성 (아직 비어 있어도 OK)
- [ ] 툴/환경, 커리어, 자료 모음 빈 폴더 생성
- [ ] 약어 사전에 현재 사용 중인 약어 등록
