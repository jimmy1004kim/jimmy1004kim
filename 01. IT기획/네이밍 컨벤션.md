## 이 문서는

페이지·파일·문서 ID·버전·상태 태그를 **일관된 규칙으로 명명**하기 위한 표준.

명명 규칙이 없으면 1년 후 본인이 본인 문서를 못 찾는다. 검색·필터·정렬이 다 깨진다. **자산화의 전제 조건**이 명명 규칙이다.

## 기본 원칙

1. **사람이 읽고 검색할 수 있게** — 사람·기계 모두 친화적
2. **앞에서부터 좁혀지게** — 큰 분류 → 작은 분류 → 고유명
3. **공백 대신 언더스코어(_) 또는 하이픈(-)** — URL·파일시스템 호환
4. **한글·영문 혼용 OK** — 가독성 우선. 검색에 유리한 쪽 선택
5. **약어는 합의된 것만** — 본인만 아는 약어 X
6. **버전·상태를 명명 안에 넣지 말 것 (예외 있음)** — 별도 속성으로 관리

## 1. 문서·페이지 명명 규칙

## 2. 프로젝트 폴더·페이지 명명

### 2-1. 프로젝트 폴더

**형식**: `[연도]-[프로젝트 약어]` (소문자, 하이픈)

|좋은 예|
|---|
|2026-shopling-automation|
|2026-newshop-launch|
|2026-internal-hr-system|

**규칙**:

- 연도는 프로젝트 시작 연도
- 약어는 영문 소문자 + 하이픈
- 한 단어 길이는 2~6자 권장

### 2-2. 프로젝트 메타 페이지

프로젝트 폴더 최상위 페이지. 산출물 인덱스·진행 현황·요약 정보가 모이는 곳.

**형식**: 프로젝트 폴더명 그대로 사용 (예: `2026-shopling-automation`)

## 3. 버전 관리 규칙

### 3-1. 버전 번호

**형식**: `v[Major].[Minor]`

|버전|의미|예시|
|---|---|---|
|**v0.1, v0.2 ...**|초안 단계|작성 중|
|**v1.0**|첫 확정|이해관계자 합의 완료|
|**v1.1, v1.2 ...**|부분 수정 (Minor)|오타·세부 보완|
|**v2.0**|주요 개정 (Major)|구조 변경·내용 대폭 수정|

### 3-2. 버전 표기 위치

- **파일·페이지 이름**에는 **최신 확정 버전만** 표기 (예: `T4_AS-IS_shopling_v1.0`)
- **변경 이력**은 페이지 내부의 별도 섹션에 누적

### 3-3. 버전을 올리는 기준

|변경 종류|버전 변경|
|---|---|
|오타·서식·표현 다듬기|같은 버전 유지 (no bump)|
|세부 내용 보완·추가|Minor 증가 (v1.0 → v1.1)|
|구조 변경·정책 변경|Major 증가 (v1.x → v2.0)|
|폐기 후 신규 작성|새 페이지 (v1.0) + 원본 🔴 폐기 표시|

## 4. 상태 태그

문서·산출물의 현재 상태를 한눈에. 페이지 제목 옆 또는 속성에 표시.

|태그|의미|
|---|---|
|🟡 **초안**|v0.x, 작성 중|
|🟠 **검토**|초안 완료, 이해관계자 검토 받는 중|
|🟢 **확정**|v1.0 이상, 사용 가능|
|🔵 **갱신**|확정 후 추가 수정 중|
|🔴 **폐기**|더 이상 안 씀 (사유 메모 필수)|
|⚫ **N/A**|해당 프로젝트엔 미적용|

**팁**: 노션 DB의 Status 속성으로 두면 필터·뷰가 자유로움.

## 6. 노션 DB·속성 명명

## 8. 명명 규칙 적용 체크

새 문서·페이지 만들 때:

- [ ] 어느 영역(공통/유형별/툴·환경/커리어/자료)에 속하는가
- [ ] 명명 형식이 위 규칙과 맞는가
- [ ] 약어가 약어 사전에 있는가 (없으면 추가)
- [ ] 버전 표기가 일관된가
- [ ] 상태 태그를 부여했는가
