## 이 문서는

프로젝트를 작은 단위로 쪼개서(Work Breakdown Structure) 일정과 함께 정리한 표.

**"언제 무엇을 끝낼 것인가"의 약속**이자, 진행 중 "지금 어디까지 왔는가"를 확인하는 도구.

## WBS 란

큰 프로젝트를 작은 작업 단위로 계층적으로 쪼개는 방법.

기본 구조:

- **Level 1**: 단계 (Phase) — Discovery, Design, Build 같은 큰 묶음
- **Level 2**: 산출물 또는 주요 활동
- **Level 3**: 작업 단위 (가능하면 1~5일 안에 끝낼 단위)

작업 ID는 계층 그대로 번호를 매긴다: `1.`, `1.1.`, `1.1.1.`

## 언제 만드나

프로젝트 시작 시. Charter 합의 직후, RACI와 같이 또는 바로 뒤에.

큰 변경(범위·인력 변동)이 생기면 갱신.

## 어떤 툴로

|툴|추천도|이유|
|---|---|---|
|**노션 (DB + Timeline 뷰)**|⭐ 추천|간트 차트처럼 시각화. 칸반·테이블 등으로도 전환 자유. 후속 문서와 링크|
|구글 시트|추천|가볍게 만들기 좋고 동시 편집. 작업 30개 이하면 충분|
|MS Project|보조|정통 PM 툴. 선후관계·자원배분 정밀. 학습 곡선 있음|
|Jira|보조|개발 중심 프로젝트면 강력. 기획자 단독 사용엔 과함|
|엑셀|보조|공식 보고·결재용|

가장 흔한 조합: **노션 DB로 만들고, Timeline 뷰로 간트처럼 보기**

## 들어가야 할 것

기본 8개 항목으로 충분하다.

|항목|설명|
|---|---|
|작업 ID|1, 1.1, 1.1.1 형태의 계층 번호|
|작업명|무엇을 하는지 동사로|
|담당자|책임자 (RACI의 R)|
|시작일|시작 예정일|
|종료일|종료 예정일|
|공수 (MD)|소요 일수 (Man-Day). 1MD = 1명이 1일 풀로 일한 양|
|선행 작업|이 작업 시작 전 끝나야 하는 작업 ID|
|상태|예정 / 진행 / 완료 / 지연 / 보류|

필요하면 추가: 진행률(%), 산출물, 비고

## 작성 절차

1. **Phase부터 정한다** — 3~5개 큰 묶음 (예: Discovery, Design, Build, Test, Close)
2. **각 Phase 안에 산출물 단위로 쪼갠다** — Level 2
3. **산출물별로 실제 작업으로 쪼갠다** — Level 3 (1~5일 단위)
4. **담당자 배정** — RACI의 R에 해당하는 사람
5. **공수 추정** — 낙관·비관·현실 중 현실 기준
6. **선후 관계 매핑** — A 끝나야 B 시작 가능한 경우
7. **시작·종료일 산출** — 공수와 선후관계로 자동 계산
8. **마일스톤 확인** — 큰 분기점을 별도로 표시
9. **버퍼 추가** — 전체 일정의 10~20%

## 작성 팁

- **노션 DB로 만들 때**: 작업명, 담당자(Person), 시작일·종료일(Date), 상태(Select), 선행(Relation), 공수(Number) 컬럼으로 만든 뒤 Timeline 뷰로 보면 간트처럼 됨
- **작업 단위 기준**: "이 작업이 끝났다고 말할 수 있는가" — 명확한 종료 조건이 있어야 함
- **공수 추정**: 익숙하지 않은 일은 1.5~2배로 잡기. 사람은 항상 낙관적으로 추정함
- **버퍼**: 전체 일정의 10~20%를 예비로 빼둠. Phase 사이에 며칠씩 두면 됨
- **갱신 주기**: 주 1회 (보통 주간 회의 때)

## 자주 하는 실수

- **너무 잘게 쪼갬** — 30분짜리 작업까지 다 적으면 관리 비용이 작업 시간을 넘음. 1~5일 단위가 적당
- **선후 관계 무시** — A 끝나야 B인데 동시에 잡으면 일정 깨짐
- **공수와 일정의 혼동** — 5MD 작업이 5일 안에 끝난다는 뜻 아님. 다른 일과 병행되면 더 오래 걸림
- **버퍼 없음** — 일정대로 100% 진행될 거라 가정 → 항상 지연
- **만들고 안 봄** — 주간 갱신 안 하면 죽은 문서
- **마일스톤 누락** — 큰 분기점 표시 안 하면 진행 점검이 어려움

## 작성 후 체크

- [ ] Phase가 3~5개로 정리되어 있는가
- [ ] 모든 작업에 담당자가 있는가
- [ ] 선후 관계가 명확한가
- [ ] 마일스톤이 3~5개 표시되어 있는가
- [ ] 전체 일정에 10~20% 버퍼가 포함되어 있는가
- [ ] 노션·시트 등 실제 툴에 옮겼는가 (텍스트 표만으로는 관리 불편)
