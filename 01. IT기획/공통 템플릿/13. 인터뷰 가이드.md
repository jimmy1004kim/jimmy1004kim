## 이 문서는

사용자·실무자·이해관계자를 **인터뷰하기 전에 준비하고, 진행 후 정리하는** 표준 양식.

인터뷰는 기획자가 가장 많이 쓰는 정보 수집 도구다. 그런데 가이드 없이 진행하면 매번 비슷한 실수가 반복된다 — 질문 빠뜨림, 유도질문, 시간 부족, 정리 누락.

회의록과 헷갈리기 쉬운데 둘은 다르다.

| 구분  | 회의록          | 인터뷰 가이드          |
| --- | ------------ | ---------------- |
| 대상  | 회의 (다대다)     | 인터뷰 (1대1 또는 소수)  |
| 목적  | 합의·결정 기록     | 정보·인사이트 수집       |
| 질문  | 즉흥           | 사전 설계 필수         |
| 결과물 | 회의록 + 액션 아이템 | 인터뷰 노트 + 인사이트 도출 |

**핵심**: 인터뷰는 회의가 아니다. **질문은 사전에 설계되어 있어야** 한다.

### 어디서 쓰나 (전 유형 공통)

|유형|인터뷰 대상|목적|
|---|---|---|
|유형 1 (신규 서비스)|잠재 사용자, 페르소나 후보|문제·니즈 검증|
|유형 2 (외주/구축)|고객사 담당자|요구사항 명확화|
|유형 3 (서비스 개선)|실 사용자, 이탈자|페인 포인트 발견|
|유형 4 (내부 시스템)|실무자, 관리자|업무 흐름 파악|
|유형 5 (제안/수주)|고객사 의사결정자|진짜 니즈·평가 기준|
|유형 6 (컨설팅/진단)|다양한 계층·부서|균형 잡힌 진단|

## 인터뷰 종류

### 목적 기준

|종류|무엇|언제|
|---|---|---|
|**탐색적 인터뷰**|문제·니즈를 발견|프로젝트 초기|
|**검증적 인터뷰**|가설·솔루션 검증|컨셉 정의 후|
|**사용성 테스트**|실제 사용 시 어려움 관찰|프로토타입 단계|
|**사후 인터뷰**|도입 후 만족도·개선점|출시·도입 후|

### 깊이 기준

|종류|시간|인원|특징|
|---|---|---|---|
|**심층 인터뷰 (1:1)**|45~60분|1명|가장 풍부한 정보, 시간 비용 큼|
|**포커스 그룹**|60~90분|5~8명|상호작용에서 인사이트, 진행 어려움|
|**빠른 인터뷰**|15~20분|1명|다수 표본 확보, 정보 얕음|
|**콘텍스츄얼 인쿼리**|60~120분|1명|실 업무 현장에서 관찰 + 질문|

**팁**: 기획자가 가장 자주 쓰는 건 **심층 인터뷰 1:1**. 이 가이드는 그걸 기준으로 작성.

## 어떤 툴로

|툴|용도|
|---|---|
|**노션**|인터뷰 가이드 작성, 노트 정리, 인사이트 누적|
|**Otter / Clova Note**|음성 → 텍스트 변환 (녹취 필수, 사전 동의)|
|**Zoom / Google Meet + 녹화**|원격 인터뷰|
|**Miro / FigJam**|다수 인터뷰 결과 비교·시각화 (Affinity Mapping)|

## 인터뷰의 5단계

```
1. 설계 (Plan)     → 목적·대상·질문 설계
2. 섭외 (Recruit)  → 적절한 사람 찾고 일정 조율
3. 준비 (Prep)     → 환경·도구·역할 확인
4. 진행 (Conduct)  → 실제 인터뷰
5. 정리 (Analyze)  → 노트 정리·인사이트 도출
```

각 단계마다 빠뜨리면 안 되는 항목이 있어서 양식으로 관리한다.

## 작성 절차

1. **인터뷰 목적 정의** — 무엇을 알고 싶은가
2. **대상 정의** — 누구에게 물어야 답이 나오는가
3. **질문 설계** — 도입·본론·마무리 구조로
4. **사전 검토** — 동료에게 가이드 보여주고 피드백
5. **섭외·일정 조율** — 사전 안내 메일 발송
6. **진행 준비** — 녹음 동의·도구 점검·환경 확인
7. **인터뷰 진행** — 가이드 따르되 유연하게
8. **24시간 내 1차 정리** — 기억이 생생할 때
9. **인사이트 도출** — 단순 받아쓰기가 아닌 패턴·시사점
10. **공유·자산화**

## 1. 핵심 인용

- "엑셀 다운받고, 음수재고 만큼 더해서 입고 템플릿에 붙여넣고, 다시 업로드해요. 한 번에 10분 정도. 근데 진짜 짜증나는 건 그게 아니라 **하루에 6번 해야 한다는 거예요**."
- "**실수는 매일 하나씩 나와요.** 셀 잘못 누르거나, 음수재고 행을 빼먹거나. 큰일 안 나는데 그게 누적되면 분기 말에 재고 안 맞아서 다시 찾아야 해요."
- "자동화되면 좋겠다는 건 알겠는데, 진짜 잘 돌아갈까가 의문이에요. 망가지면 누가 봐주는지가 더 중요해요."
- "내가 직접 판단해야 하는 건 없어요. 다 정해진 규칙대로예요. 그래서 자동화 가능할 거예요."

## 2. 발견

### 업무·행동

- 1회 작업: 약 10분 (실측 11분 25초)
- 빈도: 하루 평균 6회 (예상 "여러 번"보다 많음)
- 인원: 3명이 시간대별로 나눠 진행
- 작업 흐름: ① 샵플링 접속 → ② 음수재고 엑셀 다운로드 → ③ 입고 템플릿에 음수재고 만큼 더해서 덮어쓰기 → ④ 샵플링 입고 업로드
- 판단 영역: 없음 (규칙 기반)

### 불편·페인 포인트

- **반복 횟수** (빈도가 가장 큰 페인) > 1회 시간
- 셀 클릭 실수, 행 누락
- 분기 말 재고 불일치로 인한 역추적

### 현재 해결책 (Workaround)

- 3명이 시간대로 나눠 부담 분산
- 분기 말 별도 점검 작업으로 보정

### 욕구·기대

- 자동화로 시간 확보 시 "재고 분석·예측 같은 더 의미있는 일" 하고 싶음
- 단, 신뢰성·장애 대응이 더 중요

## 3. 인사이트

- **시간 절감(10분 × 6회)도 크지만, "반복으로 인한 정신적 피로"가 더 큰 페인** → ROI 산정 시 시간만 보면 안 됨. 정성적 효과 강조 필요
- **실수가 일별 1건 발생, 분기 말에 역추적** → 휴먼 에러 비용이 실측 가능. ROI 분석서에 정량 포함
- **자동화 자체에 대한 거부감보다 "안정성·장애 대응"이 핵심 우려** → 변화 관리 계획에 "장애 대응 플레이북" 명시 필요
- **판단 영역 없음** → 100% 자동화 가능. 캡차·UI 변경 외엔 인적 개입 불필요
- **운영팀이 "더 의미있는 일" 욕구가 있음** → 도입 후 역할 재정의에 긍정적 동기 존재. 변화 관리 메시지로 활용 가능

## 4. 인용 가능한 표현

- "1회 10분 × 하루 6회" — ROI 분석서 표지 인용
- "실수는 매일 하나씩 나와요" — 휴먼 에러 비용 정량화 근거
- "망가지면 누가 봐주는지가 더 중요해요" — 변화 관리·운영 인계의 중요성 강조 인용

## 5. 의문·검증 필요 사항

- 분기 말 재고 불일치 역추적에 정확히 몇 시간이 드는가? → 박OO 인터뷰에서 확인 필요
- 다른 2명도 동일한 빈도·실수 패턴인가? → 박OO·이OO 인터뷰로 검증
- 자동화 후 "장애 대응 책임자"는 누가? → 본부장과 별도 논의 필요

## 작성 팁

- **사전 가이드 작성이 핵심** — 가이드 없이 들어가면 매번 빠뜨림. **준비 시간이 인터뷰 효과의 80% 결정**
- **녹음은 거의 필수** — 받아쓰면서 들으면 깊이 못 들음. 사전 동의 + Otter/Clova Note 같은 자동 전사 도구 활용
- **노트 테이커를 따로** — 인터뷰어 혼자면 흐름·관찰·기록을 동시에 못 함. 둘이 들어가면 깊이가 다름
- **24시간 내 정리** — 기억이 가장 생생할 때. 일주일 지나면 50% 휘발
- **사실(Findings)과 해석(Insights)을 분리** — 핵심 인용은 그대로 남기고, 해석은 별도 섹션. 섞이면 신뢰성 떨어짐
- **의문·검증 필요 사항을 명시** — 한 번에 다 못 듣는 게 정상. 다음 인터뷰에서 확인할 것을 명시적으로
- **3명 이상 인터뷰해야 패턴 보임** — 1명 의견을 전체로 일반화하지 말 것. 특히 사용자 인터뷰
- **인터뷰이는 자기가 하는 일을 다 못 설명한다** — "보여주세요"가 "말씀해 주세요"보다 강력. 시연·관찰 권장 (콘텍스츄얼 인쿼리)
- **유도질문 가장 흔한 실수** — "이 기능이 불편하시죠?" → "이 기능 쓰실 때 어떠세요?" 로
- **재인터뷰 가능성 열어두기** — "다음에 한 번 더 여쭤도 될까요?" 사전에 합의해두면 후속 인터뷰가 쉬워짐

## 자주 하는 실수

- **사전 가이드 없이 진행** — 즉흥적 회의처럼 진행 → 핵심 질문 누락
- **유도질문** — "X 좋지 않으셨어요?" 형태. 인터뷰이가 동의하는 답만 줌
- **이중 질문** — "지금 작업 어떠세요, 그리고 자동화되면 어떨 것 같으세요?" → 둘 중 하나만 답함
- **본인 가설 검증하려고 듣기** — 다른 신호를 무시함. 인터뷰는 본인 가설 부정도 가능해야 가치
- **너무 많은 질문** — 30분에 15개 질문 → 깊이 0. 5~8개 + 후속 질문이 더 나음
- **녹음 없이 받아쓰기** — 흐름 못 따라가고 핵심 인용 놓침
- **24시간 안 지나 정리 안 함** — 기억이 사라지고 노트 절반 의미 잃음
- **인용을 의역해서 적음** — 인터뷰이의 정확한 표현이 사라지면 인사이트도 약해짐
- **소수 의견을 무시** — N=1이라도 강한 신호일 수 있음. "이거 아무도 안 하잖아"가 위험
- **인터뷰 결과를 안 공유** — 본인 머리에만 남고 팀에 전달 안 됨. 노션 인터뷰 DB에 누적 필수
