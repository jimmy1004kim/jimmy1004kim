## 이 문서는

프로젝트별로 **만들어야 할 산출물 목록과 현재 진행 상태를 한 페이지에서 관리**하는 표.

WBS·이슈 관리 대장과 헷갈리기 쉬운데 셋의 역할이 다르다.

| 구분    | WBS / 일정 계획 | 이슈 관리 대장   | 산출물 인덱스             |
| ----- | ----------- | ---------- | ------------------- |
| 대상    | 작업(Task)    | 문제(Issue)  | 문서·결과물(Deliverable) |
| 관리 단위 | 시간·일정       | 발생·해결      | 완성도·버전·위치           |
| 질문    | 언제까지?       | 무엇이 막혀 있나? | 무엇이 있고 어디까지 됐나?     |
| 종료    | 작업 완료       | 이슈 해결      | 산출물 확정·자산화          |

**핵심**: 산출물 인덱스는 **"이 프로젝트가 끝나면 무엇이 손에 남는가"** 의 마스터 리스트. 시작 시점에 짜두고 종료까지 계속 갱신한다.

## 왜 필요한가

- **누락 방지** — 산출물 목록을 명시적으로 두지 않으면 끝날 때 "이건 안 만들었네"가 반드시 나온다
- **진행 상태 한눈에** — 30개 산출물 중 어디까지 했는지 즉시 파악
- **유형별 표준 적용** — 유형 4면 이 13개가 필수, 그 중 우리 프로젝트는 몇 개 했는지
- **종료 판단 근거** — 100% 체크되어야 종료 가능
- **자산화 연결** — 어느 산출물이 재사용 가치 있는지 표시
- **포트폴리오 자료** — 본인이 만든 산출물을 한눈에

## 언제 만드나

- 프로젝트 착수 시점 (Charter 합의 직후)
- 유형 정의 페이지의 필수 산출물(✅) 목록을 토대로 시작
- 진행 중 산출물 추가·삭제 시 갱신
- Phase 종료 시 점검
- 종료 시점에 100% 체크 후 종료 판단

## 어떤 툴로

| 툴                    | 추천도     | 이유                         |
| -------------------- | ------- | -------------------------- |
| **노션 DB**            | ⭐ 강력 추천 | 필터·정렬·뷰 자유, 산출물 페이지 자체와 연결 |
| 노션 테이블 (단순 표)        | 추천      | 작은 프로젝트, 빠른 시작             |
| 구글 시트                | 보조      | 외부 공유 시                    |
| Jira (Epic·Sub-task) | 비추      | 작업 관리에 적합, 산출물 관리엔 부적합     |

**가장 강력한 형태**: 노션 DB로 만들고, 각 산출물 행을 노션 페이지(실제 산출물 본문)로 연결. 그러면 인덱스 = 진입점, 페이지 = 본문이 됨.

## 산출물 상태 정의

|상태|의미|
|---|---|
|⬜ **계획**|만들기로 했지만 아직 착수 안 함|
|🟡 **작성 중**|초안 작성 중 (v0.x)|
|🟠 **검토 중**|초안 완료, 이해관계자 검토 받는 중|
|🟢 **확정**|v1.0 이상, 사용 가능 상태|
|🔵 **갱신 중**|확정된 문서를 추가 수정 중 (v1.1, v2.0 등)|
|🔴 **폐기**|더 이상 안 씀 (사유 명시)|
|⚫ **N/A**|이 프로젝트에는 해당 없음 (생략 결정)|

## 들어가야 할 것

- 프로젝트 메타 (프로젝트명·유형·기간·전체 진행률)
- 산출물 목록 (이름·카테고리·필수 여부·상태·버전·담당·기한·위치 링크)
- 카테고리 그룹화 (정의·전략 / 설계 / 실행·관리 / 검증·납품 등)
- 진행률 요약 (필수 산출물 기준 / 전체 기준)
- 자산화 표시 (재사용 가치 있는 항목)

## 작성 절차

1. **프로젝트 유형 확정** — 기획 유형 분류 페이지에서 유형 식별
2. **해당 유형의 필수 산출물 목록 복사** — 유형 정의 페이지의 ✅ 항목들
3. **프로젝트 특화 산출물 추가** — 표준에 없지만 이 프로젝트에 필요한 것
4. **불필요 산출물 제거** — ⚫ N/A 처리 + 사유 메모
5. **카테고리별로 그룹화** — 정의·전략 / 설계 / 실행·관리 / 검증·납품 등
6. **각 산출물의 담당·예상 기한 기입**
7. **진행 중 매주·매 Phase마다 상태 갱신**
8. **종료 시점 100% 체크 확인 → 종료 워크플로우 진입**
9. **자산화 표시된 항목을 자산화 워크플로우로 이관**

## 작성 팁

- **시작 시점에 짜둔다** — 종료 직전 만들면 누락 발견. Charter 합의 직후 바로 인덱스 작성
- **유형 정의 페이지 활용** — 유형 4의 필수 산출물 13개 그대로 가져와서 시작. 0에서 짜지 말 것
- **N/A 처리는 사유 명시** — 그냥 빼지 말고 "이 프로젝트엔 결재 흐름이 없어서 상태 흐름도 생략"처럼 메모. 6개월 후 본인이 확인 가능
- **버전 표기 일관성** — v0.x(초안) → v1.0(확정) → v1.1(부분 수정) → v2.0(주요 개정). 명명 규칙 페이지 참조
- **자산화 ⭐ 표시는 진행 중에 식별** — 종료 시점에 갑자기 떠올리는 게 아니라, 진행 중 "이건 다음에도 쓸 것 같다" 싶을 때마다 ⭐
- **노션 DB로 운영하면 뷰가 강력** — "필수만 보기", "이번 주 마감", "내 담당", "자산화 후보만" 등 필터 뷰 활용
- **위치 링크는 산출물 페이지 직접 연결** — 인덱스 행이 곧 산출물 페이지 진입점이 되게
- **주간 회의에서 갱신** — 매주 한 번씩만 갱신해도 충분. 너무 자주 갱신하려면 부담
- **종료 100% 도달 전엔 종료 못 한다** — 인덱스가 종료 게이트 역할. 80%에서 끝내려 하면 인덱스가 막아줌

## 자주 하는 실수

- **인덱스 없이 진행** — "다 머리에 있다"고 시작 → 종료 때 누락 발견
- **시작 시점이 아니라 중간에 만듦** — 이미 만든 것 + 안 만든 것 정리부터 해야 해서 두 배 일
- **N/A 사유 미기재** — 6개월 후 본인이 "이건 왜 안 만들었지?" 헷갈림
- **자산화 표시 누락** — 진행 중에 식별 못 하면 종료 시점에 처음부터 회상. 누락 발생
- **위치 링크 없음** — 인덱스만 있고 실제 문서 페이지로 못 감 → 인덱스 의미 절반 사라짐
- **너무 자주 갱신하다 부담** — 매일 갱신하려다 1주일 후 포기. 주간 1회면 충분
- **종료 진입을 인덱스로 안 막음** — 인덱스가 80%인데 종료해버림 → 누락 산출물 발견 → 종료 후 재호출
- **카테고리화 안 함** — 산출물 30개가 순서 없이 나열되면 검색·점검 어려움

- [ ] 프로젝트 특화 산출물이 추가되었는가
