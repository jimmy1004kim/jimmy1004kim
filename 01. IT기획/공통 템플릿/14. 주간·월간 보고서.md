## 이 문서는

프로젝트 진행 상황을 **정기적으로 이해관계자에게 알리는** 표준 양식.

회의록·산출물 인덱스와 헷갈리기 쉬운데 셋의 역할이 다르다.

| 구분  | 회의록    | 산출물 인덱스   | 보고서             |
| --- | ------ | --------- | --------------- |
| 대상  | 회의 참여자 | PM·팀 내부   | 의사결정자·외부 이해관계자  |
| 내용  | 합의·결정  | 산출물 진행 상태 | 진행·이슈·다음 계획     |
| 빈도  | 회의 1회당 | 수시 갱신     | 주간 / 월간 정기      |
| 톤   | 사실 기록  | 추적 도구     | **요약·설득·결정 요청** |
|     |        |           |                 |

**핵심**: 보고서는 **읽는 사람이 5분 안에 의사결정에 필요한 정보를 얻게 하는** 문서. 받아쓰기 아님.

### 왜 정기 보고가 중요한가

- **나쁜 소식이 일찍 위로 올라간다** — 늦으면 회복 불가
- **의사결정자가 늦은 개입을 막는다** — 매주 보면 매주 조정 가능
- **다음 프로젝트의 신뢰 자산** — 보고가 꾸준한 PM은 다음에도 일을 받는다
- **본인의 사고 정리 도구** — 매주 강제로 정리하면 흐름이 보임

## 보고서 종류

|종류|주기|길이|청중|목적|
|---|---|---|---|---|
|**데일리 스탠드업**|매일|5분 발화|팀 내부|진행·블로커 공유|
|**주간 보고**|매주|1페이지|팀 + Sponsor|진행·이슈·다음 주|
|**월간 보고**|매월|2~3페이지|Sponsor + 경영진|마일스톤·성과·리스크|
|**Phase 종료 보고**|Phase 종료 시|3~5페이지|의사결정자 전체|결과·교훈·다음 Phase 승인|
|**종료 보고**|프로젝트 종료|5~10페이지|이해관계자 전체|최종 성과·자산화|

이 가이드는 **주간 보고 + 월간 보고** 를 다룬다. Phase 종료/종료 보고는 별도 (회고·종료 워크플로우 참조).

## 좋은 보고서의 6가지 원칙

1. **결론부터 (TL;DR)** — 5초 안에 핵심 파악 가능해야
2. **3색 신호등 (🟢🟡🔴)** — 한눈에 상태 인식
3. **숫자로 말하기** — "잘 되고 있음" ❌, "마일스톤 진행률 68%" ⭕
4. **이슈는 숨기지 말기** — 작은 이슈도 일찍 공유하면 도움받기 쉬움
5. **다음 액션 명시** — 보고만 하고 끝 X. 요청·결정 사항 명시
6. **짧게** — 주간은 1페이지, 월간은 2~3페이지가 한계

## 상태 신호 (Status Signal)

|신호|의미|기준|
|---|---|---|
|🟢 **정상 (On Track)**|계획대로 진행 중|일정·범위·예산·품질 모두 합의된 범위 내|
|🟡 **주의 (At Risk)**|위험 신호 감지, 대응 중|1주 이상 지연 가능성, 예산 초과 가능성, 품질 우려|
|🔴 **경고 (Off Track)**|합의된 범위 이탈, 의사결정 필요|1주 이상 지연 확정, 범위·예산 변경 필요, 블로커 미해결|

**중요**: 🟡·🔴 는 부끄러운 게 아니라 **PM의 책임 있는 신호**. 다 🟢만 적는 보고서는 신뢰가 떨어진다.

## 작성 절차

1. **고정 양식 사용** — 매번 같은 구조로 작성 → 독자가 빠르게 파싱
2. **데이터 먼저 모으기** — 진행률·이슈·결정 사항 등
3. **결론부터 작성** — TL;DR을 먼저 쓰고 본문 작성
4. **숫자로 검증** — 모호한 표현 다 빼고 수치화
5. **이슈·요청 사항 명시** — 의사결정자가 결정해야 할 것
6. **검토 후 발송**
7. **노션 DB에 누적**

## 작성 팁

- **고정 양식 사용** — 매주 양식 바뀌면 독자가 다시 학습. 같은 구조 유지가 독해 속도 결정
- **TL;DR이 핵심** — 본문 안 읽어도 의사결정 가능한 수준으로 압축. 결론·이슈·요청을 3줄에
- **🟢🟡🔴 일관성** — 기준 모호하면 신호 의미 사라짐. "1주 이상 지연 가능 = 🟡" 같은 기준 명시
- **🔴를 두려워하지 말기** — 🟢만 나오는 보고서는 신뢰 안 됨. 🔴 띄울수록 책임감 있는 PM
- **숫자로 말하기** — "잘 되고 있음" ❌, "마일스톤 68%" ⭕. 정성도 가능하면 정량 동반
- **의사결정 요청을 명시** — 그냥 보고하고 끝 X. "본부장 6/24까지 결정 필요" 같이 명시
- **이슈 1주 이상 끌면 위로** — 본인이 못 풀 이슈는 보고서로 위에 알리는 게 PM의 책임
- **이메일·Slack 발송 시 요약만, 본문은 노션 링크** — 푸시는 가볍게, 본문은 한 곳에
- **누적이 자산** — 노션 보고서 DB로 1년 누적되면 다음 프로젝트의 강력한 레퍼런스
- **사전 양해 없이 빠뜨리지 않기** — 매주 같은 시점에 발송. 한 번 빠지면 신뢰 손상
- **포트폴리오 자산** — 정기 보고를 6개월 누적한 PM은 그 자체가 강력한 케이스 스터디

## 자주 하는 실수

- **양식이 매번 바뀜** — 독자가 매번 다시 학습. 양식 고정이 가장 중요
- **TL;DR 누락** — 본문 다 읽어야 핵심 파악 → 안 읽힘
- **🟢만 나오는 보고서** — "다 잘되고 있어요"는 가장 의심받는 보고. 🟡·🔴 두려워하지 말 것
- **숫자 없음** — "잘 진행 중" 같은 표현. 다음 주에도 같은 말 → 진행 안 보임
- **이슈 숨김** — 작은 이슈를 안 적어둠 → 한 달 후 큰 문제로 폭발
- **의사결정 요청 없음** — "그냥 알려드립니다" 톤. 의사결정자는 뭘 해야 할지 모름
- **너무 길게** — 주간 보고가 3페이지 → 안 읽음. 1페이지 한계
- **너무 짧게** — "잘 되고 있습니다" 한 줄 → 신뢰 안 됨
- **발송 누락** — 매주 발송하다 한 번 빠짐 → 신뢰 손상. 정기성이 핵심
- **이전 보고서 갱신 없이 새로 작성** — 이슈 추적이 안 되고 사라짐. 누적 DB 필수
- **결과 보고만 하고 다음 계획 누락** — "다음 주에 뭘 할지" 없는 보고서는 의미 절반
- **외부 발송 시 내부 표현 그대로** — 사내용 약어·은어를 외부 이해관계자에게 발송 → 부담
