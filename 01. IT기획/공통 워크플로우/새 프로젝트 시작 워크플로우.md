## 이 문서는

새 프로젝트가 들어왔을 때 **"무엇을, 어떤 순서로, 어디까지 하는가"** 의 표준 절차.

매번 "뭐부터 해야 하지?"로 헤매지 않기 위한 체크리스트. 시작 단계에서 빠뜨리기 쉬운 일들을 잡아준다.

## 언제 쓰나

새 프로젝트 시작 직후. 첫 1주일 안에 이 워크플로우를 따라 모든 단계를 끝낸다.

## 사용법

1. 이 페이지를 통째로 복사
2. 해당 프로젝트 페이지 안에 붙여넣기 (`00_메타` 폴더 권장)
3. 각 단계의 체크박스를 하나씩 채워가며 진행
4. 모든 체크가 끝나면 본 작업 진입

## 어떤 툴로

|툴|추천도|이유|
|---|---|---|
|**노션**|⭐ 추천|체크박스·하위 페이지·링크 자유로움. 다른 산출물과 연결 자연스러움|
|구글 독스|보조|외부 공유 많을 때|

## 전체 흐름 한눈에

```
유형 식별  →  폴더 생성  →  산출물 체크리스트 가져오기
    ↓
프로젝트 개요서 작성  →  이해관계자 분석(RACI)  →  WBS / 일정 계획
    ↓
킥오프  →  본격 진행
```

총 7단계. 1주일 이내 완료가 목표.

# 🔲 양식 (그대로 복사해서 사용)

> 새 프로젝트 시작 시 이 박스 전체를 복사해서 해당 프로젝트 페이지 안에 붙여넣고 진행

**프로젝트명**: [프로젝트명 입력] **시작일**: [YYYY-MM-DD] **담당**: [작성자명]

---

## Step 1. 유형 식별 (Day 1, 약 30분)

- [ ] **공통 > 기획 유형 분류** 페이지 열기
- [ ] 식별 가이드(Q1, Q2)에 따라 유형 결정
- [ ] 복합 유형이면 주(Main) + 보조(Sub) 유형 모두 표기
- [ ] 프로젝트 페이지 상단에 식별 결과 한 줄로 명시

**산출물**: 유형 식별 결과 한 줄 (예: "유형 4 단독")

---

## Step 2. 프로젝트 폴더 생성 (Day 1, 약 15분)

- [ ] 해당 유형 폴더 아래에 새 프로젝트 페이지 생성
- [ ] 페이지명: `[YYYY]-[프로젝트명 축약]`
- [ ] 다음 하위 페이지 골격 생성:
    - [ ] `00_메타` (유형 식별, 이해관계자, 의사결정 기록)
    - [ ] `10_Discovery` (Charter, AS-IS 등)
    - [ ] `20_Design` (요구사항·설계 문서)
    - [ ] `30_Build` (개발 진행 기록)
    - [ ] `40_Test` (테스트·검증)
    - [ ] `90_회고` (프로젝트 종료 후)

**산출물**: 비어있지만 골격이 잡힌 프로젝트 페이지 구조

---

## Step 3. 산출물 체크리스트 가져오기 (Day 1, 약 15분)

- [ ] 해당 유형 페이지의 "주요 산출물" 섹션 복사
- [ ] 프로젝트 페이지(`00_메타` 안)에 붙여넣고 체크박스 형태로 변환
- [ ] 필수(✅) 표시된 것은 반드시 만든다는 것 인지
- [ ] 복합 유형이면 두 유형의 산출물을 합쳐서 가져옴

**산출물**: 프로젝트에서 만들 산출물 체크리스트

---

## Step 4. 프로젝트 개요서 작성 (Day 1~3)

- [ ] **공통 > 공통 템플릿 > 프로젝트 개요서** 양식 복사
- [ ] `10_Discovery` 안에 붙여넣고 작성 시작
- [ ] 모든 섹션 채우기 (미정은 [미정] 명시)
- [ ] 이해관계자에게 공유하고 피드백 수집
- [ ] v1.0으로 합의·승인

**산출물**: 프로젝트 개요서 (Charter) v1.0

---

## Step 5. 이해관계자 분석 (Day 2~3)

- [ ] 이해관계자가 5명 이상이거나 부서가 둘 이상이면 진행
- [ ] **공통 > 공통 템플릿 > 이해관계자 분석(RACI)** 양식 복사
- [ ] `00_메타` 안에 붙여넣고 작성
- [ ] 주요 활동·산출물 행 채우기
- [ ] R / A / C / I 표기 (A가 누락된 행이 없는지 확인)
- [ ] 이해관계자에게 공유·합의

**산출물**: RACI 매트릭스

> 1인 사이드 프로젝트면 생략 가능

---

## Step 6. WBS / 일정 계획 (Day 3~5)

- [ ] **공통 > 공통 템플릿 > WBS / 일정 계획** 양식 복사
- [ ] `00_메타` 안에 붙여넣고 작성
- [ ] Phase 3~5개로 큰 묶음 잡기
- [ ] 산출물 단위 → 세부 작업 단위로 쪼개기
- [ ] 담당자 배정, 공수 추정
- [ ] 선후 관계 매핑, 시작·종료일 산출
- [ ] 마일스톤 3~5개 설정
- [ ] 전체 일정에 10~20% 버퍼 포함
- [ ] (가능하면) 노션 DB의 Timeline 뷰로 시각화

**산출물**: WBS 표 + 마일스톤 표

---

## Step 7. 킥오프 (Day 5~7)

- [ ] 킥오프 자료 준비 (Charter 요약 + RACI + WBS 마일스톤)
- [ ] 킥오프 회의 일정 잡고 이해관계자 초청
- [ ] 회의 진행
    - 프로젝트 배경·목적 공유
    - 범위와 산출물 합의
    - 일정·마일스톤 합의
    - 정기 회의 주기 합의 (보통 주 1회)
    - Q&A
- [ ] 회의록 작성 (`00_메타` 안에)
- [ ] 회의록 이해관계자 전원에게 공유

**산출물**: 킥오프 회의록, 합의된 정기 회의 일정

---

## Step 8. 본격 진행

- [ ] 해당 유형의 업무 흐름에 따라 진행 (각 유형 페이지 참조)
- [ ] 회의록·이슈·리스크·변경 사항은 그때그때 기록
- [ ] 주 1회 진행 상황 점검 (WBS 갱신)
- [ ] 마일스톤 도달 시 자가 점검 후 다음 단계 진입

---

## 시작 단계 완료 체크

모든 Step이 끝나면 다음 항목을 자가 점검:

- [ ] 프로젝트 유형이 명확하게 식별되어 있는가
- [ ] 프로젝트 페이지에 들어갈 산출물 목록이 정해져 있는가
- [ ] Charter가 v1.0으로 합의되어 있는가
- [ ] (필요시) RACI가 이해관계자 합의를 받았는가
- [ ] WBS와 마일스톤이 작성되어 있는가
- [ ] 킥오프가 끝났고 회의록이 공유되었는가

이 6개가 모두 ✅ 되면 시작 단계 완료. 본격 진행 가능.

## 자주 하는 실수

- **유형 식별 건너뜀** — "감으로" 시작하면 산출물이 들쭉날쭉해짐
- **폴더 구조 없이 시작** — 자료가 흩어져서 나중에 못 찾음
- **Charter 없이 바로 작업 진입** — 중간에 "이게 아니었는데" 발생
- **킥오프 생략** — 이해관계자 합의 없이 진행 → 후반에 큰 충돌
- **시작 단계가 너무 길어짐** — 1주 넘어가면 본 작업이 늦어짐. 7일 이내 종료가 원칙
- **체크리스트만 만들고 안 봄** — 진행 중 자주 펴봐야 효력 있음
